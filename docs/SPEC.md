# ReportDiff 仕様書

## 1. 目的と範囲

業務システムの帳票出力を新旧 2 つ受け取り、画像として比較して、相違箇所を「まとまり」（クラスタ）単位で報告する。

対象の帳票は 2 種類ある。

- 表が主体の帳票（罫線、文字、数値、セルの塗り）
- 図が主体の帳票（工程表の進捗線、オートシェイプ、塗りつぶしなど）

入力は PDF または画像。Excel 帳票は、ツールの外で PDF か画像に変換してから渡す（1.2）。

### 1.1 やること

- レンダリング由来の細かな差（アンチエイリアス、1〜2px の位置ずれ）を無視する
- 1 文字の変更を、数十個の画素差ではなく 1 個の相違として報告する
- 相違箇所の位置（mm と px）、新旧の切り出し画像、ページ全体の重ね描きを出力する
- 帳票ごとに除外領域（出力日時など）を設定できる
- CI から使えるよう、終了コードと JSON を出力する

### 1.2 やらないこと

- Excel などから PDF への変換（同じマシン・同じプリンタ設定で新旧両方を変換する運用を前提とする）
- OCR
- 行の挿入で下がずれたページの自動整列（Phase 3 の検討項目）
- GUI（当面は HTML レポートが UI）

## 2. 用語

| 用語 | 意味 |
|---|---|
| A / B | 基準（旧）／比較対象（新） |
| 候補 | 一段目の比較で「違う」と判定された画素 |
| 生の差分（raw） | 二段目まで通過した画素。報告の元になる |
| グループ | 二段目で位置ずれを判定する単位。つながったインクごと |
| クラスタ | 近接する生の差分をまとめた報告単位 |
| 吸収 | 位置ずれで説明できたため差分としなかったこと |

## 3. 全体構成

```
入力 A, B
  └─ 4. 正規化 …………… 同じ DPI・同じ大きさの BGR 画像の組（ページごと）
       └─ 5.2 一段目 ……… 候補の抽出（0.5px 以下のずれはここで消える）
            └─ 5.3 二段目 … 位置ずれで説明できるグループを吸収
                 └─ 5.4 除外領域の適用
                      └─ 5.5 クラスタ化
                           └─ 8. 出力（result.json、画像、HTML）
```

`ReportDiff.Core` は 5 章だけを担当し、入力は `Mat`（BGR 8bit、同サイズ）2 枚とパラメータ、出力はマスクとクラスタの一覧とする。ファイル、PDF、コンソールには触れない。

## 4. 入力の正規化

### 4.1 対応形式

- PDF（複数ページ）
- PNG、JPEG、BMP、TIFF（TIFF は先頭ページのみ）

形式は拡張子ではなく先頭バイトで判定する。A と B の形式が違ってもよいが、警告 `MIXED_INPUT_TYPES` を出す。

PDF と画像を混在させる場合は `dpi` と `image_dpi` を同じ値にする。異なる場合は、mm 換算の基準が一意に定まらないため、設定をそろえるよう案内して終了コード 2 とする。A/B の順序によって扱いは変えない。

### 4.2 PDF

- PDFium（PDFtoImage）で `dpi`（既定 300）でラスタライズする。アンチエイリアス有効、注釈とフォームも描画、背景は白
- PDFtoImage の戻り値（`SKBitmap`）から画素を取り出し、BGR 8bit 3 チャンネルの `Mat` にする
- 1 辺が 16000px を超えるページはエラー（`dpi` を下げるよう案内する）
- ファイルは .NET 側で開き、ストリームで渡す

### 4.3 画像

- .NET 側でバイト列を読み、`Cv2.ImDecode` でデコードする
- アルファ付きは白背景に合成する。グレースケールは BGR に変換する
- mm 換算に使う DPI は `image_dpi`（既定は `dpi` と同じ）

### 4.4 大きさの違い

A と B でページの大きさが違う場合、拡大縮小はしない。左上を合わせ、小さい方の右と下を白で埋めて同じ大きさにする。警告 `SIZE_MISMATCH` を出し、ページ結果の `size_mismatch` を true にする。

### 4.5 ページの対応

Phase 1 ではページ順で対応させる。ページ数が違う場合、共通部分を比較し、余ったページは `only_in_a` / `only_in_b` として報告する。警告 `PAGE_COUNT_MISMATCH`。

## 5. 比較アルゴリズム

`reference/prototype.py` の `tolerant_diff` と `compare_page` が実行可能な定義。以下はその説明で、食い違いがあれば参照実装を正とする。

### 5.1 前処理

1. 高速パス：`absdiff(A, B)` がすべて 0 なら、そのページは `same`。以降は実行しない
2. 色空間：BGR 8bit を float32（1/255 倍）にしてから `BGR2Lab` で Lab にする。L は 0〜100、a と b は約 −127〜127。8bit のまま Lab にしない（L が 255 に引き伸ばされ、しきい値の意味が変わる）

### 5.2 一段目：候補の抽出

`edge_tolerance`（k）が 0 より大きいとき：

```
blurA = blur3x3(LabA)            blurB = blur3x3(LabB)
conA  = dilate5x5(LabA) − erode5x5(LabA)     conB も同様（チャンネル別の局所コントラスト）
候補  = いずれかのチャンネル c で
        |blurA − blurB|_c  >  color_threshold + k × max(conA, conB)_c
```

k が 0 のとき（厳密比較）：`|LabA − LabB|_c > color_threshold`。ぼかしもコントラスト項も使わない。

設計の意図：

- 0.5px 以下のずれ（斜めを含む）は、3×3 の平均ではほとんど差にならない。残る差は周囲のコントラストに比例するので、しきい値をコントラストに比例して広げて消す
- 平坦な部分ではコントラストが 0 なので、しきい値は `color_threshold` だけになる。白から #F2F2F2 への塗り変更（L の差 約 4.5）が検出できる
- 判定をチャンネル別にするのは、色相だけが変わった細線（青→赤）を明度のコントラストの大きさで見逃さないため

OpenCV の既定の境界処理（`blur` は `BORDER_REFLECT_101`、`erode` / `dilate` は画像外を無視）をそのまま使う。

### 5.3 二段目：位置ずれで説明できる候補の吸収

`s = round(max_shift_mm を px に換算)`。s が 0、または候補が 0 個なら、一段目の候補がそのまま生の差分になる。

1. グループを作る
   - 候補マスクを 5×5 で膨張したもの
   - 加えて、候補に触れている「インクの連結成分」の全体。インクは、半径 `max(1, round(mm_px(ink.background_radius_mm)))` px の最大 L を局所背景とし、`局所背景 − L > ink.contrast_threshold` の画素（A と B の和）。既定は半径 1.5mm・差 25。等号は含まない。広い塗りつぶしの内部はインクに含まれにくい
   - 上の和を (2s+1)×(2s+1) で膨張し、8 連結の連結成分をグループとする
2. B を (dx, dy)（−s〜s の整数、全組み合わせ）だけ平行移動して一段目をやり直し、グループごとに候補の画素数を数える。平行移動は最近傍、端は複製
3. グループごとに、候補数が最小になるずれを選ぶ。同数なら |dx|+|dy| が小さい方
   - 最小が 0 → そのグループは「吸収」。`absorbed_groups` に数え、使ったずれの最大値を `max_shift_px` に記録する
   - 最小が 1 以上 → そのずれでの候補（グループ内）を生の差分とする

設計の意図：

- 画素ごとに近傍を許容する方式（画素ごとに都合のよいずれ方向を選べる）では、「両端が伸びた線」「太くなった線」「未と末」のように、部分ごとに逆向きのずれで説明できてしまう変更を見逃す。グループ全体でずれを 1 つに限ると、これらは説明できずに残る
- 実際のノイズは「オブジェクトごとの小さな平行移動」なので、このモデルで十分に吸収できる
- 一段目と合わせて、`s + 0.5` px までの一様なずれを吸収する

実装上の注意（C#）：

- `blurB` と `conB` は一度だけ計算し、ずれごとにそれらを平行移動して使う（平行移動と `blur` / `dilate` / `erode` は交換できる）
- 全ページで 25 通りを計算すると遅い。候補のあるグループの外接矩形（余白 s+3 px）に切り出して評価する。参照実装は最適化していない（A4・300dpi で差分のあるページに約 12 秒）。C# での目標は、差分が局所的なページで 2 秒以内、最悪でも 10 秒以内
- ラベル画像（CV_32S）と候補マスクはマネージド配列に写し、1 回の走査でグループごとの画素数を数える。画素単位のインデクサ呼び出しは使わない

### 5.4 除外領域

設定の `exclude`（mm、左上原点）を px に変換し、該当範囲の生の差分を消す。px 化は、左上は切り捨て、右下は切り上げ。除外領域は重ね描き画像に黄色の半透明で描く。

### 5.5 クラスタ化

1. 生の差分が 0 個なら `same`
2. 生の差分がページ全体の `max_diff_ratio`（既定 0.30）を超えたら `too_different`。クラスタは作らず、警告 `TOO_DIFFERENT` を出す（別の帳票を比べている、向きが違う、など）
3. 結合：生の差分を横 `2*hx+1`、縦 `2*hy+1` の矩形で膨張する。`hx = ceil(merge_x_mm の px / 2)`、`hy` も同様。間隔が `merge_x_mm` 以下の差分がつながる
4. 8 連結の連結成分ごとに、そこに含まれる生の差分の画素数を数える。`min_pixels` 未満は捨て、捨てた数を `noise_dropped` に記録する
5. クラスタの矩形は、膨張後の領域ではなく、生の差分にぴったり合わせる
6. `fill_ratio = 画素数 / 矩形の面積`。低いものは線や枠の形をしている
7. 読み順に並べて 1 から採番する（矩形の上端を `max(1, round(mm_px(cluster.reading_band_mm)))` px の帯で分けて上から、帯の中は左から。既定は 5mm）
8. 1 ページのクラスタが `max_clusters_per_page`（既定 500）を超えたら、画素数の多い順に残し、警告 `CLUSTER_LIMIT`

矩形ではなく連結成分でまとめるので、表の外枠が変わっても、枠の内側にある数値の変更は別のクラスタとして残る（ケース D11）。

重ね描きの輪郭は `findContours` の `RETR_LIST` で取る。`RETR_EXTERNAL` では、枠の内側にあるクラスタの輪郭が描かれない。

### 5.6 既知の限界（仕様）

| 内容 | 理由 | 対処 |
|---|---|---|
| 200dpi 以下では、9pt 前後の「未／末」「ば／ぱ」「ー／一」を安定して検出できない | 字形の差が 1〜2px で、0.5px ずれのノイズと同じ大きさになる | 既定を 300dpi にした。小さい文字が多い帳票は 400dpi |
| 1px 幅の線の、同系色での濃淡変化（L の差 約 20 まで）は検出できない（L01） | 0.5px ずれた線と見分けがつかない | 厳密プロファイルを使う |
| `max_shift_mm` + 0.5px を超えるずれは差分になる（L02） | 仕様 | `max_shift_mm` を上げる。全体のずれは Phase 2 で補正して報告する |
| 線の 1px 以内の延長・短縮は吸収される | 1px の位置ずれと区別できない | 厳密プロファイルを使う |
| 文字が罫線に触れていて、文字と罫線のずれ量が違うと、その文字が差分になる | 触れているインクは同じグループになる | 実害が出たらグループの分割を検討（Phase 2） |
| 行の挿入で下がずれると、それ以降がすべて差分になる | 画像比較の原理的な弱点 | Phase 2 の移動判定、Phase 3 の帯の整列 |

## 6. CLI

```
reportdiff compare <A> <B> --out <dir>
    [--config <file.yaml>] [--profile normal|strict|loose]
    [--dpi <n>] [--pages <1-3,5>] [--save-all-pages] [--no-html] [--force] [--quiet]
reportdiff --version
```

- `--out`：出力先。なければ作る。空でなければエラー。`--force` で上書き
  - `--force` は指定した出力ディレクトリ全体を置き換え、以前の画像・HTML 等を残さない。結果の生成中は旧出力を保持する
  - 入力・設定ファイル、現在の作業ディレクトリ、実行ファイルの保存先を含む出力先は拒否する。出力先そのもののシンボリックリンク・ジャンクションも拒否する
- `--config`：設定ファイル（7 章）。省略時は既定値
- `--profile`：7.2 のプロファイル。設定ファイルより後に適用する
- `--dpi`：設定ファイルと `--profile` より優先
- `--pages`：比較するページ（1 始まり）。省略時は全ページ
- `--save-all-pages`：差分のないページの画像も保存する（既定は差分のあるページだけ）
- 標準出力：1 行の要約（例 `相違あり: 20 ページ中 3 ページ、7 箇所 → out/report.html`）。`--quiet` で抑止
- `--no-html`：HTML を作らず、要約には `result.json` の保存先を表示する
- エラーは標準エラー出力に日本語で出す

終了コード：

| コード | 意味 |
|---|---|
| 0 | 相違なし |
| 1 | 相違あり（`too_different`、ページ数の不一致を含む） |
| 2 | エラー（引数の誤り、読めないファイル、設定の誤りなど） |

## 7. 設定ファイル

利用者が編集する外部定義は UTF-8 の **YAML** とする。`#` によるコメントを記載でき、既存の `--config` と `examples/settings.yaml` を継続する。固定値だった 14 項目も **T2-4a** で設定化した。[設定リファレンス](CONFIGURATION.md)に全キーの既定値・範囲・影響と、固定する構造を記載する。以下のスキーマと合わせて正とする。`result.json` は機械処理用の結果出力として維持する。

### 7.1 スキーマと既定値

```yaml
dpi: 300                  # PDF のラスタライズ解像度
image_dpi: 300            # 画像入力の想定 DPI（mm 換算用）。省略時は dpi と同じ
diff:
  max_shift_mm: 0.15      # 位置ずれとして吸収する最大量。0 で二段目を無効化
  color_threshold: 3.0    # 平坦部のしきい値（Lab の各チャンネルの差）
  edge_tolerance: 0.3     # コントラスト比例の許容。0 で厳密比較
ink:
  background_radius_mm: 1.5 # 局所背景の半径。吸収・分類・移動で共通
  contrast_threshold: 25.0  # 背景との差がこの値を超える画素をインクとする
cluster:
  merge_x_mm: 3.0
  merge_y_mm: 1.0
  min_pixels: 4
  max_clusters_per_page: 500
  max_diff_ratio: 0.30
  reading_band_mm: 5.0    # クラスタの読み順を決める帯の高さ
move:
  search_mm: 5.0          # 移動注釈の各軸の探索距離。0 は無効化（11.2 節）
  min_score: 0.98         # 一致度の下限
  min_score_gap: 0.02     # 最良候補と次点との差の下限
  template_margin_mm: 1.0 # 移動テンプレートの周囲の余白
align:
  enabled: false         # 比較前に B 全体を A に合わせる。明示的に有効にする（11.4 節）
  max_shift_mm: 5.0       # 上下左右それぞれの上限。0 は探索しない
  min_score: 0.98         # 補正後の一致度の下限
  min_score_gap: 0.02     # 次点候補との差の下限
  min_improvement: 0.05   # 補正なしからの一致度の改善量の下限
  coarse_max_side_samples: 800 # 粗い計算格子の長辺の目安上限
  refine_radius_samples: 2     # 復元段階の各軸の探索半径（計算要素数）
  min_support_cells: 3         # 固定3×3格子で必要な支持区画数
  min_support_rows: 2          # 支持区画がまたがる行数
  min_support_columns: 2       # 支持区画がまたがる列数
  min_ink_area_mm2: 1.0         # 各区画・A/B各側に必要な黒換算面積
text:
  max_letters_per_page: 100000 # ページ・片側の文字要素数上限
  max_words_per_page: 20000    # ページ・片側の単語数上限
  max_runes_per_cluster: 2000  # クラスタ・片側の本文上限（省略記号を含む）
  min_line_overlap: 0.5        # 同じ行とする縦の重なり率
exclude:                  # mm、左上原点。page は数値か all
  - { page: all, x: 150, y: 8, w: 50, h: 6, note: 出力日時 }
report:
  crop_margin_mm: 2.0     # 切り出し画像の余白
```

- 未知のキーはエラーにする（綴りの誤りに気づけるように）
- 値の範囲を検証する（dpi は 72〜1200、mm は 0 以上、`edge_tolerance` は 0 以上 1 未満、など）。`move.search_mm` は 0〜20、`move.min_score` と `move.min_score_gap` は 0 より大きく 1 以下
- 既定値 → YAML → 明示 `--profile` → CLI の順に適用する。`--profile` は diff.max_shift_mm / diff.edge_tolerance だけ、`--dpi` は dpi と未指定の image_dpi を上書きする。image_dpi の明示値は維持する
- 未知・重複キー、型、非有限値、範囲、最終 DPI での探索候補数・結合カーネルの整数限界、除外矩形の座標と寸法の加算オーバーフローをキー名付きで拒否する。無効な機能の値やプロファイルで上書きする値も型・範囲を検証する
- 実際に使った全値（既定値と上書きを反映したもの）を `result.json` の `config` と HTML に記録する。入力 YAML は書き戻さないためコメントを保持する
- `align.enabled` は `true` / `false`。`align.max_shift_mm` は 0〜20、三つのしきい値は有限かつ 0 より大きく 1 以下。無効時も設定の型と範囲は検証する。明示プロファイルは `diff.max_shift_mm` と `diff.edge_tolerance` だけを上書きし、`move`・`align` は変更しない

追加項目の範囲：ink.background_radius_mm は (0,20]mm、contrast_threshold は [0,100]。cluster.reading_band_mm は (0,1000]mm、move.template_margin_mm は [0,20]mm。text の文字要素数は整数 1〜1,000,000、単語数は 1〜200,000、本文長は 1〜100,000 Unicode スカラー値、行の重なり率は (0,1]。align の粗い格子は整数 64〜4096、復元半径は 1〜8、支持区画数は 1〜9、支持行数・列数はそれぞれ 1〜3、黒換算面積は (0,10000]mm²。数値はすべて有限値。

支持区画数・行数・列数はすべて満たす。弱い区画数条件と強い行列数条件の組み合わせは矛盾とせず許可する。新項目の省略・旧設定では従来の既定値を補う。schema_version=1 の追加項目とし、旧 JSON にない値も既定値で読む。

### 7.2 プロファイル

| 名前 | max_shift_mm | edge_tolerance | 用途 |
|---|---|---|---|
| normal（既定） | 0.15 | 0.3 | 通常 |
| strict | 0 | 0 | 同じエンジン・同じ環境での回帰テスト。1px の差も検出する |
| loose | 0.30 | 0.3 | 現新比較など、位置の揺れが大きいとき |

JPEG やスキャン画像を入力にするときは、`color_threshold` を 8〜12 に上げる。

### 7.3 単位の換算

`px = mm / 25.4 * dpi`。換算は `Units` クラスの 1 か所で行い、丸め方は用途ごとに 5 章の記述に従う。面積は `px² = mm² × (dpi / 25.4)²` を `Units.SquareMmToPixels` で換算する。`align.*_samples` は物理的な長さではなく縮小計算の格子要素数であり、DPI で換算しない。

### 11.1 追加・削除・変更の分類（T2-1）

分類は A→B の画像上の推定であり、業務上の意味や文字の内容を判断しない。5 章の検出・位置ずれ吸収・除外・ノイズ除去・上限処理を終えた**採用クラスタだけ**に注釈を付ける。生差分マスク、状態、数・矩形・画素数、吸収・ノイズ・警告を変更しない。

インクは 5.3 節と同じ定義を使う。正規化済みの元画像を float32 BGR→Lab に変換し、L の周囲 `max(1, round(mm_px(ink.background_radius_mm)))` px の最大値を局所背景とする。`局所背景 − L > ink.contrast_threshold` の画素をインクとする。既定は 1.5mm・25。等号は含まない。ink は局所吸収・分類・移動の共通設定なので、変更は検出自体にも影響する。

- `edge_tolerance > 0`：分類用のインクマスクだけを 3×3 矩形で 1px 膨張する。検出時の 3×3 平均が作る差分の縁を対応させるための固定カーネル。
- `edge_tolerance == 0`：膨張しない。
- インクは比較に渡した A/B（全体補正を採用した場合は補正後）の座標で求める。グループごとのずれ吸収量を分類用に適用し直さない。曖昧な場合は `changed` に残す。
- インク計算を ROI に限定する場合も、局所背景半径と膨張 1px の余白を含め、ページ全体と同じインク判定にする。

各クラスタに属する**生差分画素**を A だけ（removed）、B だけ（added）、両方（both）、どちらもインクでない（other）に分ける。外接矩形内の別クラスタを混ぜない。分類の画素数は JSON に追加しない。

| kind | 条件 | HTML 表示 |
|---|---|---|
| `added` | added が 1 以上で、他は 0 | 追加（推定） |
| `removed` | removed が 1 以上で、他は 0 | 削除（推定） |
| `color_changed` | both が 1 以上で、他は 0。さらに膨張前のインク形状が A/B で一致 | 色変更（推定） |
| `changed` | 上記以外。混在・形状変更・背景や塗り・不明確なもの | 変更 |

形状一致は、クラスタを作った**膨張後の連結成分全体**に属し、除外領域外にある画素で、膨張前のインクマスクを比較する。矩形内の別成分を含めず、膨張で穴や違いが消えただけの形状を色変更としない。ノイズ・上限で落としたクラスタは分類せず、削除の緑マスクにも含めない。

広い塗りの内部や薄い色はインク定義を満たさないことがあり、追加・削除でも `changed` になる。見た目が色変更でも、アンチエイリアスや濃淡によってインクしきい値をまたぐと `changed` になる。多数決や新たな割合しきい値は導入しない。

切り出しは B を下地とし、採用した A だけの差分を緑、その他の生差分を赤で描く。クラスタの種類が `changed` でも A だけの部分は緑になる。ページ全体の重ね描きは従来どおり差分・輪郭・番号が赤、除外が黄色。HTML に分類の説明と緑／赤の凡例を表示する。

### 11.2 移動の注釈（T2-2）

T2-1 の分類後、同じ内容が近くへ整数 px で平行移動したと推定できる場合だけ `kind: moved` とする。検出マスク・削除マスク・状態・クラスタの数／ID／矩形／画素数・吸収／ノイズ／警告は維持する。移動でも相違の終了コード 1 のまま。サブピクセル、回転、拡縮、複合クラスタの一部だけの移動は扱わない。

`move.search_mm` は各軸の最大距離で、`floor(Units.MmToPixels(search_mm, dpi))` px とする。300dpi・5mm は上下左右それぞれ ±59px。斜めの距離は各軸で判定する。0 は注釈の無効化。プロファイルによる上書きは行わず、実効設定を JSON / HTML に記録する。

判定は次のすべてを満たす場合に限る。

1. `removed` または `changed` の採用クラスタを起点とし、生差分の矩形に `ceil(mm_px(move.template_margin_mm))` px（最小 1px、既定 1mm）の余白を付けた A 側をテンプレートにする。表示の切り出し余白とは独立する。平坦、局所インクなし、インクがテンプレート端に接して内容の欠落を否定できない場合は推定しない。
2. 元画像 BGR 8bit の B 側周辺を `matchTemplate` の `CCoeffNormed` で探索する。有限の最大スコアが `min_score` 以上で、最良候補の中心と隣接 1px（3×3）を除いた次点との差が `min_score_gap` 以上であること。最良が元位置の場合は移動としない。
3. A のテンプレートと B の移動先を比較し、既存の一段目（5.2 節）による差分が 0 であること。`max_shift_mm` はこの再検証では 0 とし、追加のずれ吸収で色・形の差を消さない。元画像の色は相関とは別に確認する。
4. B の移動先から A を同じ条件で探索し、逆ベクトルで同じ移動元に一意に戻ること。
5. 元領域と移動先領域にかかる採用クラスタを、生差分と連結成分の所属から集める。各クラスタの生差分全体がこの二つの領域に収まり、一部だけを拾っていないこと。外接矩形の内側の別成分を混ぜない。
6. 関連する各クラスタについて、余白付き領域の `A → B の移動先` と `移動量を戻した A → 元位置の B` の両方の比較で一段目の差分が 0 であること。移動先だけが一致していても、元の位置に別の差分が残る場合は推定しない。
7. 使用する各検証領域がページ内に完全に収まり、除外領域と交差せず、ノイズ・上限で落とした生差分を含まないこと。背景の余白を確保できない画像端も保留する。別の移動候補と関連クラスタが競合する場合は、先着順で選ばず競合する候補をすべて保留する。

採用時は関連する全クラスタに同じ A→B の `shift_px` を付け、`related_cluster_ids` に他の関連 ID を記録する。クラスタを新たに結合・分割しない。単独クラスタ内で移動が完結する場合は関連 ID が空でも moved になる。A/B を反転したとき、同じ移動が認識されればベクトルの符号は反転する。

推定されない場合は T2-1 の分類を残し、shift_px は null、関連 ID は空とする。薄い塗り、長い単純な線、反復、色や形が変わる移動、画像端、近くの別要素がテンプレートに混じるケースは推定されないことがある。移動を見送っても相違は残る。画像上で同じ結果になる「移動」と「削除して同じ内容を追加」は区別しない。

緑／赤の切り出しとページ全体の重ね描きは T2-1 のまま。HTML は「移動（推定）」、右／左・下／上の px 数、関連クラスタへのリンクを表示し、方向が A→B であることを説明する。

### 11.3 PDF テキスト層の注釈（T2-3）

PDF 入力の採用クラスタだけに、元ファイルのテキスト層から単語を補足する。OCR や文字列による比較は行わず、画像の検出マスク・状態・クラスタ数／矩形／画素数・分類・移動量・関連 ID・切り出し・終了コードを維持する。画像入力の側は注釈しない。同一・too_different・片側だけのページはクラスタがないのでテキストを抽出しない。

PdfPig 0.1.16 の NearestNeighbourWordExtractor で単語化する。単語の矩形とクラスタ矩形（切り出し余白なし）が正の面積で重なった場合、単語全文を `text_a` / `text_b` に採用する。境界に接するだけでは含めない。除外領域と正の面積で重なる単語は全体を省く。大きな外枠クラスタでは未変更の文字も含み、複数クラスタと重なる単語はそれぞれに記載する。

座標は A/B ごとの元の描画サイズを使う。PdfPig 0.1.16 は MediaBox と交差した CropBox の左下原点へ補正済みなので、原点を二重に引かない。有限で正のページ寸法と `Units.PointsToPixels(pt, dpi)` が実描画サイズと各軸 ±1px 以内で一致することを確認し、x は `実描画幅 / page.Width`、y は `実描画高 / page.Height` で換算して上下を反転する。単語矩形は元の描画領域にクリップする。正規化の白埋めへ文字を拡大せず、クラスタの局所移動量も適用し直さない。11.4 節の全体補正を採用した B では、その補正量だけを単語矩形に加えてページ範囲に再度クリップし、補正後のクラスタ・除外領域に対応付ける。

単語は上→下、同じ行では左→右に並べる。同じ行とは、上から処理した行の先頭単語との縦方向の重なりが、小さい方の高さに `text.min_line_overlap`（既定 0.5）を掛けた値以上あるもの。同値は位置・文字列の ordinal 順で安定化する。同一文字列・同一変換矩形の重複だけを除く。単語中の空白類は空白一つにそろえ、残る制御文字を除去する。全角半角や Unicode の正規化はしない。単語間は空白、行間は改行にする。縦書き・複雑な段組み・意味に基づく読み順は保証しない。

| 条件 | 出力と警告 |
|---|---|
| PDF 抽出成功、該当単語あり | 文字列。警告なし |
| PDF 抽出成功、該当単語なし | 空文字列。警告なし |
| 画像入力 | null。テキスト注釈の警告なし |
| ページの回転が 0 度以外（継承を含む）、標準と異なる UserUnit、寸法・単語座標の対応が不明 | その側を null、`TEXT_ANNOTATION_SKIPPED` |
| ページの文字要素が text.max_letters_per_page（既定 100,000）件または空白以外の単語が text.max_words_per_page（既定 20,000）件を超える | その側を null、`TEXT_ANNOTATION_SKIPPED` |
| PDF オープン・ページの文字抽出に失敗 | その側を null、`TEXT_EXTRACTION_FAILED`。画像比較は継続 |
| 1 クラスタ・片側の本文が text.max_runes_per_cluster（既定 2,000）Unicode スカラー値を超える | 最初の上限−1 文字と「…」（上限1では「…」だけ）、`TEXT_ANNOTATION_TRUNCATED` |

警告は A/B・ページを含み、省略時は理由、本文打ち切り時はクラスタ番号も記録する。生の例外や抽出本文を警告へ流さない。メモリ枯渇は回復可能な抽出失敗として握りつぶさない。件数上限は解析後の単語化・整形・対応付けの量を抑えるもので、PDF パーサー自体の実行時間・メモリの強制上限ではない。

HTML には画像確認の補助であることを説明する。不可視の文字、不正確な文字情報、変更していない文字も含まれ得る。文字の相違を `kind` や検出数へ反映しない。件数・本文上限と行の重なり率は text 設定で調整する。CLI オプションは追加しない。抽出と整形は Pdf に置き、Core は PDF に依存しない。

### 11.4 全体のずれの推定・補正（T2-4）

`align.enabled` の既定は false。明示的に有効な場合のみ、描画・サイズ正規化後、5 章の比較処理より前に B 全体の整数 px の平行移動を推定する。元サイズが異なるページと片側だけのページは補正しない。回転・拡大縮小・サブピクセルの補正はしない。未採用なら元の B を使い、採用時は補正後の A/B を既存の検出・分類・移動注釈へ渡す。既定の比較式・パラメータ・ゴールデン期待値は変更しない。

探索上限は各軸 `R = floor(Units.MmToPixels(align.max_shift_mm, dpi))`。0 は探索を省略する。300dpi・5mm は上下左右それぞれ ±59px。

1. BGR 8bit →グレースケールの暗さ `255 - gray` を使用する。長辺が `align.coarse_max_side_samples`（既定 800）以下になる最小の 2 の累乗を縮小倍率 S とする。右・下に倍率の端数だけ黒（元画像では白）を計算用に加え、整数の倍率で面積平均縮小する。比較画像の寸法は変えない。
2. 粗い段階では各軸 ±ceil(R/S) セルを総当たりする。以後は倍率を半分ずつ戻し、直前の最良座標を 2 倍した位置の ±align.refine_radius_samples（既定 2）セルを評価する。各段階は ±ceil(R/S) に制限し、最終段階は ±R の整数 px だけを評価する。同点は原点へのマンハッタン距離、Y、X の順に安定化するが、採用には候補差を要求する。
3. 同じ段階の全候補で同じ評価マスクを使う。ページ端からその段階の最大探索距離を除き、除外領域（左上切り捨て・右下切り上げ）も同じ距離で拡張して除く。幅か高さが 0 の除外領域は無視する。粗い段階の切り上げ分も含み、縮小セル内がすべて有効な場合だけ評価する。評価領域が空、または片側の暗さの合計が 0 なら補正しない。
4. 各候補の一致度は `1 - sum(abs(A_dark - shifted_B_dark)) / sum(A_dark + shifted_B_dark)`。白紙による一致の水増しを避ける。分母が 0 の候補は 0。これは画素の一致度であり、信頼確率ではない。
5. 元解像度の一致度が `min_score`（既定 0.98）以上、補正なしからの改善が `min_improvement`（0.05）以上、最終探索窓内の次点との差が `min_score_gap`（0.02）以上であること。縮小探索でも最良点から各軸 1 セル以内を除く別ピークとの差を同じ下限以上とする。別ピークが存在しない場合の値は null として、この検査だけ省略する。元解像度で全範囲を総当たりする方式ではなく、縮小で候補を絞れない場合は補正を見送りやすい。
6. 元のページを固定 3×3 に分け、align.min_support_rows 行・align.min_support_columns 列以上にまたがる align.min_support_cells 区画以上で同じ補正を支持すること（既定は 2 行・2 列・3 区画）。各区画は有効領域内に A/B それぞれ黒換算 align.min_ink_area_mm2 mm²（既定 1mm²）以上の暗さがあり、同じ一致度・改善量の条件を満たすこと。分散や面積の条件を下げると、局所移動も全体補正と扱い得る。
7. B をページ外へ押し出す帯に、白（全 BGR チャンネル 255）以外の画素が一つでもあれば補正を見送る。除外領域内でも内容を捨てない。採用時は再補間せず整数移動でコピーし、空いた端だけを白で埋める。

推定専用に外した領域を差分から消すことはない。比較は補正後のページ全体を対象とし、除外領域は A／補正後 B の座標に固定して既存どおり適用する。PDF テキストも同じ座標へ対応付ける（11.3 節）。

`pages[].global_shift_px` は B に実際に加えた **B→A の補正量** `{dx,dy}`。右・下が正で、B が右へ 10px ずれている場合は dx=-10。未適用時は null。従来の `max_shift_px` は局所ずれの吸収量のまま、クラスタの `shift_px` は補正後に残る **A→B の移動量**のままとする。

`pages[].alignment` は `status`（disabled / not_applied / applied）、`reason`、`estimated_shift_px`、`score_before`、`score_after`、`score_gap`、`coarse_score_gap`、`support_cells` を持つ。未計算の値は null。補正なし・低スコアの候補も取得できた数値は残す。理由は disabled / zero_range / size_mismatch / unpaired_page / insufficient_area / insufficient_information / no_shift / low_score / low_improvement / ambiguous / insufficient_support / edge_content / applied。HTML は日本語で理由・量・スコアを表示する。

補正を採用した場合は `GLOBAL_SHIFT_APPLIED` にページと補正方向・量を記録し、相違なしでも A・補正後 B・補正前 B・重ね描きを保存する。`images.b_original` は補正前 B の相対 PNG パス、未適用時は null。HTML には「全体補正あり」と画像切り替えを表示し、座標と局所移動との方向の違いを説明する。config.align を含めこれらは追加項目として schema_version=1 を維持する。旧出力に項目がない場合は補正なしとして扱う。

補正によって差分数・結果・終了コードは変わり得る。警告だけで終了コードを変えず、補正後の比較結果を最終結果とする。画像だけで出力装置のずれと意図した全体移動を区別できないため、有効化は全体移動を許容する指定となる。背景が端まであるページ、少ない情報、広い除外、周期的な配置では見送りが増える。

### 11.5 フォント非埋め込みの警告（T2-5）

選択した各 PDF ページについて、A/B ごとに使用フォントの埋め込みを検査する。相違なし、クラスタなし、too_different、片側だけのページも対象とし、画像入力・未選択ページは対象外。テキスト注釈の省略条件・件数上限・除外領域・全体補正によって検査対象を切り捨てない。描画・比較結果・分類・クラスタ・終了コードは変更しない。

既存の PdfPig でページ本文と実行された Form XObject から得た文字要素（空白・不可視文字を含む）のフォントを調べる。リソース登録だけのフォントは非埋め込み警告の対象にしない。元辞書のオブジェクト番号・世代番号を識別に使い、同名の異なる辞書は分ける。同じ辞書の別名や繰り返し使用はページ内でまとめる。フォント名は元辞書の BaseFont、Type3 は Name を優先し、代替フォントの名前から元辞書を推測しない。

| 種類・状態 | 判定 |
|---|---|
| Type1 / MMType1 / TrueType | FontDescriptor 内の対応する FontFile / FontFile2 / FontFile3 を参照し、解決・デコードできる空でないストリームの所在を確認する |
| Type0 | DescendantFonts の単一 CIDFontType0 / CIDFontType2 について同じ確認をする |
| Type3 | CharProcs の空でない字形ストリームを確認する。FontFile がないだけで非埋め込みにしない |
| 標準14フォント | 特別扱いせず、埋め込みがなければ警告する |
| サブセット | 名前の接頭辞では判定せず、プログラムの所在を確認する |
| FontDescriptor またはプログラム指定がない | Type1 / MMType1 / TrueType / CIDFont は NON_EMBEDDED_FONT |
| 直接辞書・代替フォントで元辞書が不明、未対応形式、参照切れ・循環・型不正・空ストリーム・デコード失敗 | FONT_INSPECTION_INCOMPLETE |

FontFile は Type1 / MMType1、FontFile2 は TrueType / CIDFontType2 に対応する。FontFile3 は Subtype が Type1C（Type1 / MMType1）、CIDFontType0C（CIDFontType0）、または OpenType であることを確認し、不一致・不明は検査未完了とする。フォントプログラムの全字形・構造の正しさや利用許諾を検証する機能ではない。

ページの解析に失敗した場合も FONT_INSPECTION_INCOMPLETE を出し、描画できる画像の比較と他ページの検査は継続する。PDF 注釈・入力フォームの外観は通常の文字抽出に含まれないため、空でない Annots があるページには外観が検査対象外である旨を明示する。リソースにパターン、使用 Type3 の字形リソースに別フォント等がある場合も、その内部を追跡できない旨を明示する。これらは存在の検出による検査範囲の警告であり、未使用のリソースや図形だけの外観にも出る場合がある。PDFium による注釈・フォームの描画は維持する。

既存の warnings[].code / message に、日本語で入力 A/B・1 始まりの元ページ番号・取得できた元フォント名とオブジェクト参照・理由を記録する。非埋め込みは入力・ページ・辞書ごとに 1 件とし、複数ページと A/B を混ぜない。元辞書が不明なフォントは取得したフォントの同一性でまとめ、名前不明と記す。解析失敗や検査範囲の制限はページ・理由ごとにまとめる。HTML は同じ警告を文字列としてエスケープ表示する。schema_version は 1 を維持する。

新しい依存・設定・しきい値は追加しない。PDF テキスト注釈と現在の 1 ページの解析を共有し、全ページの文字要素を保持しない。警告がない場合も OS 間の描画一致を保証しない。PDFium と PdfPig の解釈差・破損時の復旧や上記の検査範囲は限界として残る。A/B は従来どおり同じマシンの同じ実行で描画する。

### 11.6 フォルダ一括比較（T2-6）

```text
reportdiff compare-dir <dirA> <dirB> --out <result>
  [--config common.yaml] [--rules rules.yaml]
  [--profile normal|strict|loose] [--dpi n] [--pages 1-3,5]
  [--save-all-pages] [--no-html] [--force] [--quiet]
```

既存の `compare` と個別 schema_version、比較式・既定値・注釈の定義を共用する。ファイルも PDF 描画も逐次処理する。`--rules` は `compare-dir` 専用。

**列挙と対応付け**

サブフォルダと隠し項目を省略せず再帰探索する。拡張子 `.pdf .png .jpg .jpeg .bmp .tif .tiff` を大小文字を区別せず候補にし、ほかのファイルは A/B 別に `ignored` へ記録する。拡張子は候補選択だけに使い、対応した入力の実形式は従来どおり内容で判定する。空ディレクトリは比較行を作らない。

相対パスの OS 区切りを `/` にそろえ、Unicode NFC と OrdinalIgnoreCase で対応付ける。A/B 元の表記も保持する。同じ側でファイル・フォルダが正規化後に衝突した場合、または両側の同じキーがファイルとフォルダの場合は開始前エラーとする。対象外ファイルも衝突検査に含める。改名・拡張子変更の推測はしない。

片側だけの候補は `only_in_a` / `only_in_b` とし、存在の差分として終了コード 1 の対象にする。内容を開かず、規則を適用せず、個別レポートを作らない。安定したキー順で `f000001` から ID を付ける。代表パスは両側の NFC 表記の Ordinal 順で先のもの。入力ファイル名を出力ディレクトリ名に使わない。

**パスと処理中の前提**

入力 A/B が同一フォルダであることは許可する。一方がもう一方を含む場合は拒否する。入力ルート自身と配下のシンボリックリンク・ジャンクション・再解析ポイントは、対象外拡張子や切れたリンクも含めて拒否する。親ディレクトリのリンク別名は実パスへ解決して扱う。

出力はどちらの入力とも同一・祖先・子孫になれない。字句上とリンク解決後の両方で検査する。出力自体のリンクは禁止し、共通設定・選択定義・全参照設定・作業ディレクトリ・実行ファイルの保存先を含む出力先も拒否する。

比較前に両入力の列挙を完了する。列挙失敗を空フォルダとみなさない。実行中は入力が変わらない前提で、スナップショットは作らない。列挙後に対応入力が削除される等の読み込み失敗は個別エラーになる。

**帳票別設定**

コメント付き UTF-8 YAML の選択定義は `schema_version: 1`、配列 `rules`、各要素の非空 `pattern` / `config` を持つ。空配列は許可し、未知・重複キー、型・版・正規表現の不正を拒否する。config の相対パスは選択定義のフォルダが基準、絶対パスも許可する。

正規表現は NFC・`/` 区切り・拡張子付きの相対パスに適用し、NonBacktracking・CultureInvariant・IgnoreCase を使う。部分一致を許可する。全体一致は `\A` / `\z` で指定でき、先読み・後読み・後方参照等は非対応エラーとする。A/B のどちらかに一致した規則を候補にし、同一規則の両側一致は 1 件と数える。

候補が 0 件なら共通設定、1 件なら該当 YAML、複数ならその対を `CONFIG_RULE_AMBIGUOUS` エラーとする。同じ config への複数一致もエラーにし、一致した 1 始まりの番号・パターン・設定パスを記録する。

優先順位は **既定値 → 共通 YAML → 該当 YAML → 明示 profile → CLI**。ネストしたキーを部分上書きし、空マッピングは元を保つ。exclude は指定時に配列全体を置換し、空配列で解除、省略で継承する。image_dpi は両レイヤーで未指定なら最終 dpi に追従し、明示値は保持する。PDF/画像混在の DPI 不一致は個別エラー。

後から上書きする値を含む各設定、未使用の参照設定、合成した設定を開始前に検証する。同じパスの内容を一度読み込み、途中で読み直さず、元 YAML を変更しない。設定のパス・読み込んだバイト列の SHA-256 と CLI 値を一覧に記録する。[設定リファレンス](CONFIGURATION.md#フォルダ比較の帳票別設定)に例と説明を示す。

**出力**

`index.json` と `index.html` を作り、成功した対だけ `files/f000001/result.json` / `report.html` / pages / crops を保存する。失敗した個別出力は削除するため ID は欠番になり得る。`--no-html` で一覧・個別両方の HTML を省略する。

一覧は個別結果と別スキーマで、`schema_version: 1` / `report_type: directory_comparison` とする。

| フィールド | 内容 |
|---|---|
| tool / generated_at / inputs | ツール名・版、生成日時、A/B 入力フォルダの絶対パス |
| configuration | common / rules / referenced の出典 path と sha256、cli の profile / dpi / pages / save_all_pages / no_html / force / quiet |
| summary | status、total、compared、same、different、only_in_a、only_in_b、error、ignored（対象外は A/B の延べ数） |
| files[] | id、relative_path、元の relative_path_a / b（片側欠落は null）、status、selected_rule、comparison、warning_count、json / html 相対リンク、error |
| files[].selected_rule | 選択された index / pattern / config。選択なし・片側のみ・複数一致は null |
| files[].comparison | 成功時の個別 ReportSummary。未比較・失敗は null、warning_count も null |
| files[].error | code / message / matched_rules（複数一致した規則）。成功・片側のみは null |
| ignored[] | side / relative_path / reason。内容未検査と示す |
| warnings[] | NO_TARGET_FILES 等の全体警告。個別の警告本文は個別結果へ記録 |

HTML はオフライン・日本語・エスケープ済みの文字列と固定 ID の相対リンクを使う。全体集計、各対の状態・比較ページ数・相違ページ数・クラスタ数・警告数・選択設定・エラー理由・対象外一覧を表示する。片側のみ・失敗は「未比較」と示し、検査済み 0 件として表示しない。

**エラーと終了コード**

| 状況 | 保存と終了コード |
|---|---|
| すべて same、片側のみ・エラーなし | 一覧を保存、0。個別警告だけでは変更しない |
| different または片側のみがあり、エラーなし | 一覧を保存、1 |
| 個別入力・ページ範囲・比較処理の失敗、複数規則一致 | 他の対を続行。error 行を含む一覧を保存、2 |
| 対象 0 件 | NO_TARGET_FILES、summary.status=error の一覧を保存、2 |
| 列挙・衝突・リンク・包含・設定の開始前エラー | 全体中止、2。旧出力を保持 |
| 画像・個別結果・一覧等の出力障害 | 全体中止、2。旧出力を保持 |

status の優先順位は error → different → same。個別比較失敗の code は COMPARISON_FAILED とし、日本語の理由を併記する。`--quiet` は通常の完了表示を抑止し、エラーの標準エラー出力は維持する。通常表示は一括の集計と一覧の保存先を 1 回だけ出す。

一括全体を一時ディレクトリに作成し、保存可能な一覧が揃った時点で確定する。**個別エラーを含む完了は保存対象であり、--force で旧結果を新しいエラー一覧へ置き換える**。開始前・出力障害では置き換えない。強制終了・電源断からの自動復旧は対象外。

## 12. 設計判断の記録

| 判断 | 理由 |
|---|---|
| C# / .NET | Windows に自己完結の単一 exe で配布でき、macOS 上でビルドできる。Python は PyInstaller がクロスビルドできず、exe が大きく誤検知されやすい |
| FFmpeg を含まない OpenCvSharp ランタイム | Windows は公式 slim、macOS は core / imgproc / imgcodecs だけのローカルビルドを使う。標準ランタイムに含まれる FFmpeg を避けるため、2026-09-20 にこの方針を承認。比較アルゴリズムは変更しない |
| Intel Mac を対象外とする | 確認環境を用意できないため、2026-09-20 にユーザーが対象外と指定。macOS の受け入れ対象は Apple Silicon とする |
| PDF と画像の混在時は同一 DPI を必須とする | 異なる画素密度では除外領域・クラスタ位置の mm 換算基準が曖昧になる。拡大縮小や A/B 順序による基準の変更は行わず、設定をそろえるようエラーで案内する。2026-09-21 にユーザーが選択。比較アルゴリズムと既定値は変更しない |
| 局所背景のインクによる保守的な分類 | T2-1 の推奨案を 2026-09-21 に採用。検出は維持し、曖昧な塗り・形状差は changed に残す。追加の設定・依存は導入しない |
| 双方向で確認する保守的な移動注釈 | 2026-09-21 に T2-2 推奨案を承認。各軸 5mm、一致度 0.98、次点との差 0.02 を既定にし、移動元の残存物や曖昧な対応を moved にしない。検出を維持し、関連 ID の追加で元・先のクラスタを追えるようにする |
| PDF テキストは単語全文の補足とし、抽出失敗で画像比較を止めない | 2026-09-21 に T2-3 推奨案を承認。重なり・順序・除外・上限・null と空文字列の違いを明示し、本文の情報を画像の判定と混同しない |
| 全体補正は既定無効、候補の一意性・複数箇所・端の内容を確認する | 2026-09-21 に T2-4 仕様案を承認。比較結果を変える前処理として、補正量と元 B の証拠を残し、画像・テキスト・除外を同じ座標にそろえる |
| 承認済み調整パラメータの外部定義はコメント付き YAML に統一する | 2026-09-21 の追加依頼。既存の YamlDotNet と --config を利用し、残る固定値の台帳・設定化・説明付き設定例を T2-4a で整備する。結果 JSON は維持する |
| 14 項目の固定値を YAML の任意設定にする | 2026-09-21 に T2-4a のキー・範囲・固定構造との境界を承認。既定値を維持し、インク定義と読み順を Python・ゴールデン params と同期する。計算格子の要素数は物理長と区別する。設定変更時の検出保証は既定値と同じとは限らない |
| 使用フォントの非埋め込みと検査未完了を分ける | 2026-09-21 に T2-5 の推奨案を提示し、続行指示を受け採用。標準フォントを特別扱いせず、未使用リソースから非埋め込みと断定しない。元辞書不明・注釈外観等の検査範囲外は別の警告として残し、比較結果と終了コードを維持する |
| PDFium（PDFtoImage） | MIT。Windows・macOS・Linux のネイティブを同梱。PyMuPDF / MuPDF は AGPL なので使わない |
| looks-same から採ったもの | 知覚的な色空間（Lab）で比べること、完全一致を先に判定する高速化 |
| looks-same から採らなかったもの | アンチエイリアス検出（直線には効かず、一段目の方式で代替できる）。矩形ベースのクラスタリング（表の外枠が変わると矩形が表全体を覆い、中の差分が埋もれる） |
| OpenCV から採ったもの | `erode` / `dilate`、`blur`、`connectedComponents`、`findContours`、Lab 変換、`warpAffine`。Phase 2 で `matchTemplate` |
| 画素ごとの近傍許容をやめ、グループ単位のずれ探索にした | 近傍許容では 未／末、ば／ぱ、線幅の変更を見逃した（試作で確認）。ずれをグループで 1 つに限ると検出できた |
| 一段目を「3×3 平均の比較」にした | 画素そのものの比較では、斜め 0.5px のずれを消すのに許容係数を 0.75 以上にする必要があり、検出力が落ちた |
| 既定 300dpi | 200dpi では上の方式でも 未／末 と ば／ぱ を取りこぼした。レンダリングのノイズは解像度によらず約 1px だが、字形の差は解像度に比例して大きくなる |
| しきい値をチャンネル別にした | ΔE の大きさ 1 つで判定すると、色相だけ変わった 1px の線を見逃した |
| 設定の長さは mm | DPI を変えても設定を書き直さずに済む |
| 吸収・除外したものを必ず報告 | 許容が不具合を隠す事故を防ぐ |
