# T3-1c 末尾の片側ページと独立した送り原因の事前検証

2026-09-26。A4のローカル自動検証に続く独立診断。その後、末尾1ページ・独立単一原因の追加8方向に限定した下記接続案について、ユーザーの「OKです。進めてください。」により製品接続を承認済み。接続後の実装とローカル自動検証は[製品接続の記録](../verification/t3-1c-unpaired-integration.md)を参照。以下の事前診断は接続前の経緯として残す。

## 対象と境界

単一原因のR11（2→3ページ、6構造→1原因）は既存機能。次に、互いに交わらない送り連鎖の最後だけが新しい末尾ページへ達する場合を調べる。既存製品では、同一ページ対応済みの境界証明と複数成分の集約が全ページ対応を要求する。まずどの段階が未成立かを分け、製品の式・条件・出力は変更しない。

診断対象は、各側のページが1から連続し、片側ページが末尾の1枚だけ、補正・数値対応・除外・領域・選択なし、300dpi／normal。全本文の一意性・共通順序を確認し、両端の全行が同じ物理ページの相手へ対応する `text_mismatch` の候補だけを非送りの検証候補とする。実際に跨ぐ行・画像不一致・曖昧な変位は救済しない。元帯の全画素一致・置換比較・C/D写像・既存の支持と改善率をそのまま要求する。

片側ページは、送り帯と複数ページで証明された固定部分以外の全非白画素を検査する。色の閾値で薄い内容を捨てず、残余が一画素でもあれば文書集約を見送る。`only_in_a/b`、未比較、両方の網羅性falseを保持し、補助帯に架空の構造IDやクラスタ数を付けない。

ページ群は実際に対応する本文の跨ぎから独立に監査する。各群に単一の連続原因と全実構造の所属、ページ別収支を要求する。一群でも不成立なら全グループを取り消す。別群で挿入と削除が併存しても、それぞれの符号と収支を検証する。同一群の複数原因、末尾以外の片側ページ、途中のページ追加による後続ページ番号の移動は今回の一般化候補から外す。

## 固定する検証

- 単一R11、3→4ページの単一連鎖、1→2ページの固定部分不足。
- 独立二原因と末尾ページ、別群での挿入／削除、途中の中立ページ、内容の濃淡差。
- 新ページの帯外の濃淡・ごく薄い非白画素、固定部の変化、送り帯自体の数値変更。
- 同じ連鎖の二原因、余分な未接続ページ、別群にまたがる反復本文。
- A/B両方向。生成時の行列は正解側でのみ使い、推定へ渡さない。

実PDFの文字／元画素を読み、現製品CLIの有効／無効結果も保存する。C/Dと元帯・片側ページの残余をPythonで別に再構成し、既存参照比較器のマスクと照合する。構造IDの重複・欠落、残余確認の取消、行／ページ／リンクの破損、選択省略で集約が成立しないことも監査する。診断が成立しても現CLIの未成立を合格へ変更しない。

成果は固定入力と実測結果、成立範囲、製品接続の具体案まで。予算予約・証拠結合・JSON／HTML／compare-dir・保存・既存互換・全回帰・Windowsは製品接続時に改めて必要。A4用紙の未成立9条件、薄色1px線2方向、数値行自体の跨ぎ、実帳票と手動表示の保留は引き継ぐ。

## 診断結果と推奨する接続範囲

[検証結果](../verification/t3-1c-unpaired-components.md)の32方向で当初の期待が一致した。新しい成立候補は4ケース8方向。独立二原因、別群での逆符号、途中の中立ページは11→2、内容の濃淡差2,462px・1クラスタを残す場合は12→3。現CLIは同じ入力を19→19のまま見送る。単一R11は従来どおり6→1、3→4ページの連鎖は9→1。BGR(254,254,254)の帯外30画素は残余となり集約しない。

推奨は**検証済みの末尾1ページと独立した単一原因群に限定した製品接続**。同一成分の複数原因を片側ページへ広げる案は、今回も写像が未成立のため採らない。次の変更だけを候補とする。

1. **非送りの証明を末尾1ページの文書へ限定拡張する。** 従来の全ページ対応経路を優先する。両側のページ列が1から連続し、対応ページが2枚以上あり、片側ページが文書末尾の1枚だけの場合に限る。非送りを証明する両端と各行の相手は全て対応済み物理ページ内にあり、全本文の一意性・共通順序・境界を誰も跨がないこと・元座標への完全な帰属を要求する。画像不一致、曖昧な変位、本文の数値変更をこの証明へ昇格させない。元候補のIDを保持する。
2. **集約を全成分成功時だけ許可する。** 既存の単一R11が成功した結果は維持する。新しい経路では、送りのないページは対応済みで同一行配置かつ構造0、各送り成分は既存の単一原因検査を通ることを要求する。片側ページを含む成分にも、全非白残余0・実構造の一意な所属・送り元／先の行数と高さ・各ページの収支を要求する。別成分の挿入と削除は個別の符号で検査し、一成分でも不成立なら全グループを取り消す。片側ページへ構造IDを発行しない。
3. **初回の追加採用を診断の条件へ限定する。** ページ選択なし、300dpi／normal相当の実効比較値、全体補正・数値対応・除外・領域なし。各ページの既存支持・改善率・最大区間数等はそのまま評価し、設定を強めて見送りになる場合を検証する。同一成分の共有原因、新しい片側ページが2枚以上、途中のページ番号移動は対象外とする。
4. **製品用の証拠と資源予約を先に確定する。** 診断は反射で計画を組み立て直し、候補を取り除いた別ゲートを試すだけである。この手法を製品へ移さない。製品では文書・元候補・元矩形へ結合した既存の非送り証拠を拡張し、記述64MiBの残りへ索引・行対応・成分と所属参照を確保前に計上する。現在の非送り証拠の固定費256B＋対応行512B、文書上限、全破棄の規則を維持する。成分作業領域の計上式と上限ちょうど／1B不足、解放・取消は実装前に接続仕様へ確定する。
5. **既存出力の意味を維持する。** `only_in_a/b`、未比較、`difference_count_complete=false` と `aggregated_difference_count_complete=false` を保持。既存 `nonflow`、`groups`、`auxiliary_bands` と実構造参照を使い、新しいクラスタを作らない。CLI／HTML／compare-dirは未集約と集約後を併記し、raw overlayは元画像から生成する。

接続時は今回32方向を固定し、新しい8方向の期待差だけを許可する。残る24方向、既存の全ページ対応・単一R11・補正・数値対応・共有原因・A1〜A4の成功／見送りを保持する。設定・選択・予算・入力変更・保存失敗、参照先の存在、静的HTMLとcompare-dirを確認し、全テストとPythonゴールデン、実CLIの資源を検証する。Windows・実帳票・保留された手動操作を合格へ変更しない。

より一般的な片側ページや同一成分の複数原因を先に設計する選択肢もあるが、未成立の写像契約が残るため、上記の限定接続を先に行う方針が承認された。

## 製品接続の証拠・資源契約

既存の範囲確定と単一原因集約が成功した結果は先に返す。新経路は文書記述と推定結果の同一インスタンス、凍結済みの元レイアウト／候補配列、実効設定に結合した内部の対象範囲証拠を必要とする。通常の公開集約APIへ片側ページ付きの入力を渡しただけでは新経路を使えない。CLIから全体補正の有効設定も渡し、補正量0であっても新経路では対象外とする。従来R11の挙動は変えない。

非送りの追加検証は、作業領域 `1,024 + 本文行数×2,048 + ページ記述数×256 + 候補数×512` Bを、索引／配列を作る前に予約する。この固定費に対象範囲証拠を含める。成立した証拠ごとに既存の `256 + 対応行数×512` Bを追加し、どこかで超過すれば全追加証拠を破棄して `flow_descriptor_limit`。成功時は一時作業領域も含めた保守的な値をNonflowの記述量へ保持し、後段で同じ予算を二重使用しない。本文文字列・元画像・行ハッシュは複製しない。

末尾ページを含む複数成分の集約は、作業／結果の上限 `1,024 + 本文行数×2,048 + ページ数×512 + 送りリンク数×1,024 + 実構造数×2,048` Bを、全索引・局所入力・成分リストの作成前に予約する。これは旧新配列の同時保持、成分ごとの元ページ番号への変換、実構造／原因／補助帯／収支の結果参照を含む保守的な上限。最大ページ・行・候補件数を先に検査し、checked演算を用いる。文書・非送り・数値・曖昧候補の記述量を除いた64MiBの残りだけを使う。ちょうどなら許可、1B不足なら全グループを破棄し `terminal_descriptor_limit` として既存C/D・未集約件数を維持する。

予約は当該計画／結果に属する管理データの計上であり、共有の可変カウンターやMatを保持しない。失敗時の結果に予約量や部分グループを残さず、再試行で残量が累積減少しない。実RSSや内部比較器のメモリ上限とは区別し、CLIの時間・最大RSSは別に測定する。古い全ページ対応経路の記述量・採否・出力は変更しない。
