# 元ページを連続して保持する複数ページ由来の内容比較面

2026-09-26。[跨ページ支持の検証](../verification/t3-1c-cross-page-support.md)で残った `unanchored_join` を受けた独立実験。製品の `RowComparisonSurface`、支持条件、比較式、集約器は変更しない。

## 試す構成

元の `same-page-two` に対し、挿入前の側をページ全体にわたって保持する。反対側の共通行は、全文の一意な対応から元の物理ページ・全幅帯を参照する。送り行を両側のCから削除する代わりに、送り先の実画素を送り元の行に対応付ける。逆方向では保持する側がBになる。

第1面では、A1の全1,250行を保ち、B1の共通行・固定部とB2の送り行を対応付ける。第2面でもA2の全行を保ち、B2の残り本文を対応付ける。A2の本文末尾からB2の本文末尾までの200行は、全チャンネル255を確認して実在する純白余白として残す。反対側がない箇所には既存のWhiteSpaceと同様の白を対応付ける。非白なら面の生成を拒否する。白帯を消したり、その前後を接続したりしない。

各Cの全高に一つの元物理ページが連続して存在するため、画像端を含むどの近傍もそのページに属する。反対側の異なる物理ページの帯を「元から連続していた」と扱わない。画像の特徴量・二段目のグループ・クラスタはC全体で通常どおり計算する。

## この工程の受け入れ境界

- 固定PDFと前工程の記録・元PNGをハッシュで結び付ける。前工程の文字証拠・送り帯一致・独立した次ページ支持が成立した元ケース2方向と内容色変更2方向について、内容面の構成と比較を試す。既存30方向の採否は変更しない。
- A/Bの各元走査行は、全Cを合わせて一度だけ参照するか、独立に特定済みの挿入／削除原因帯に属する。送り帯はCに残す。全画素の欠落・重複、元ページ取り違え、非白余白、原因範囲の欠落を検査する。
- 片側の元ページをそのまま保持する条件は、現行の片側連続近傍より厳しい条件として実験内で要求する。既存の `unanchored_join` を解除しない。
- 境界の色・形状・薄い印・罫線、二段目の周期帯をメモリ上の別入力で検証する。通常座標の独立参照と比較し、境界でマスクやグループを切らない。送り帯に差を作る対照は、内容面を作れても元帯一致で拒否する必要がある。
- Cの生差分を物理ページごとの元座標へ写し戻し、保持側の画素数を保存する。両側への投影数を足して差分件数にしない。実Dへの投影・構造ID・文書集約・HTMLへはまだ接続しない。

これは2画像・1物理ページを前提とする現行のC表現の拡張案である。連続近傍の安全条件が成立しても、製品の採用成立や10→2件の達成を意味しない。ページ所属を持つ内容クラスタと設定座標の契約、全ページ採用、文書・候補IDへの証拠結合、確保前の予算、再読込、出力との接続は別途必要。とくに削除方向では保持側Bと設定基準Aが一致しないため、領域・除外をそのまま転用しない。

元ケースの正例期待、既存負例、A4・Windows・実帳票・ブラウザー保留は維持する。

## 検証結果

[独立検証](../verification/t3-1c-anchored-content.md)で元ケース2方向の内容面を構成でき、色変更2方向も3,807px・1クラスタを保持した。58条件中22条件・44ページで比較を実行し、Python参照と一致した。薄色1px線2方向の検出期待は通常座標でも未成立のため残す。現行のCを強制成立させた結果ではなく、診断専用の複数ページ由来の表現である。次は元ページ所属・D投影・設定座標・証拠結合と全ページ採否の契約を具体化し、その後に製品接続を判断する。
