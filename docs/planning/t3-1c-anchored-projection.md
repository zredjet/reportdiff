# 複数ページ由来の内容面の表示・設定・採否契約

後続状況（2026-09-26）：診断を受けた[製品接続仕様](t3-1c-anchored-integration.md)をSPEC 11.8へ反映し、[A1のCore基盤](../verification/t3-1c-anchored-foundation.md)と[A2の比較・投影・採用検査](../verification/t3-1c-anchored-comparison.md)を実装した。CLI接続と製品の受け入れは未完了。以下は独立検証時の計画と結果を保持した記録。

2026-09-26。[内容面の独立検証](../verification/t3-1c-anchored-content.md)の次工程。製品ソースを変更せず、表示・設定座標と既存の採用検査を診断ツールで組み合わせる。

## 表示と件数

Cの各帯はA/Bそれぞれの物理ページと元座標を持つ。Cの画素所属IDを比較コアから保持し、C→O→各物理ページのDへ転写する。Dは前工程で作った全元行を一度ずつ覆う写像を使う。生成したCを現行の `RowComparisonSurface` と偽って渡さない。

同じC画素がA/Bから同じD座標へ戻る場合は一つにまとめる。別の物理ページへ戻る場合は、同じ内容IDの別の表示断片にする。クラスタIDは `(内容面ID, CでのクラスタID)`。件数の所属ページは内容面が保持する物理ページに固定し、別ページの断片は参照として表示する。断片の面積で再クラスタ化・ノイズ除去せず、表示画素の総和をCの生差分数へ上書きしない。

構造IDはDの読み順で決め、挿入／削除原因、送り端点、同一ページ移動を区別する。送り端点はD上の構造でもCに残るため、「Dの構造帯＝Cから省略した帯」としない。C省略の監査は二つの原因だけ、送りは内容比較済みとする。内容件数を減らさず、文書集約の既存入力・式がこの構造を扱えるかは別段階で調べる。

移動注釈のテンプレート・検証窓が複数ページや異なる変位へ分かれる場合、移動を表示座標へ推測変換しない。内容IDと生差分を保持し、`changed` と理由を表示する。今回は投影の診断を行い、製品JSON／HTMLへ新しい項目を実装しない。

## 設定座標

領域・除外は元Aの物理ページと矩形へ結び付ける。Cの保持側がBでもAの出自から所有領域を写し、同じyの別ページへ流用しない。CにAが存在しない純白区間や、Cから除いた原因帯を隣の設定で埋めない。設定マスクの往復を独立に検証する。

最初の接続候補は、全2ページ対応・ページ選択なし・全体補正なし・数値対応なし・領域と除外なし・両ページの実効比較設定が同一の場合に限定する。未対応条件は文書全体を既存比較へ戻す。設定マスクを写せることだけを、領域比較・除外下の採用証明とはしない。将来の一般化で実効比較条件が混在する場合は、ページ所属付き所有領域と最大近傍を別途検証する。

## 採用の条件

入口は末尾原因について前工程の文字・順序・全送り範囲の証拠が成立した文書だけ。全画素一致の送りを支持数へ加えない。同じ物理ページで対応する元の語を使い、Dの同じ変位の連続区間について既存の `RowGroupValidator` と `RowSupport` を変更せず呼ぶ。前方、原因間、送り先本文に加え固定部の支持も要求する。

各物理ページの通常比較と、同じページ番号を保持するCの比較を計測し、既存の改善率を各ページで要求する。ページごとの失敗を合計で隠さない。候補、設定、画像、D、C、採否を同じ入力指紋へ結び付ける。いずれかのページ・支持・範囲・設定・証拠が失敗したら全ページの仮結果を破棄し、部分採用しない。

診断では既存記録の12証拠候補を再評価し、元ケース／色変更4方向の成立、送り変更2方向・薄色／一行インク／平坦支持6方向の拒否を期待する。その他の既存記録は新しい入口へ進めない。さらに継ぎ目の変更で、送り帯が同じまま周辺演算の差分が送り帯端へ届く入力を用意し、複数ページ表示でも1内容ID・1件を保つことを検証する。小さい断片・設定の別ページ混同・全ページ取り消し・証拠改変は別の契約検査とする。

比較式・既定値、元ケースの製品上の未成立、薄色1px線2方向の未成立、既存負例を変更しない。資源の確保前予約、変更ファイルの再読込、保存の原子性、JSON/HTML/compare-dir、実プラットフォーム受け入れは製品接続の後続要件として残す。
