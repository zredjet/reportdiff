## T2-1：追加・削除・変更の分類と切り出し表示

### 採用した仕様

分類は A→B の方向で付ける、画像上の推定ラベルとする。業務上の「追加／削除」や文字の意味を判定する機能ではない。既存の差分検出を通過し、除外・ノイズ・上限処理後に採用されたクラスタだけを分類する。

インクの基準は、既存の SPEC 5.3 と同じ「周囲約 1.5mm の最大 L より 25 を超えて暗い画素」を使う。しきい値を別途増やさず、白以外の用紙・セル背景にも局所的な基準を使える。ただし、この定義は広い塗りつぶしの内部をインクと見なさないため、背景や塗りの差は一般的な `changed` に残す。

分類用のインクマスクは、`edge_tolerance > 0` の通常比較では 3×3 の矩形で 1px 膨張する。既存の 3×3 平均で生じる差分の縁をインクと対応させるためで、mm の許容量を追加するものではない。`edge_tolerance == 0` の厳密比較では平均処理がないため膨張しない。元画像と生差分マスクは変更しない。

生差分の画素を、クラスタ所属を保ったまま次の 4 種に分ける。

| 画素の状態 | 集計名 | 切り出しでの表示 |
|---|---|---|
| A にだけインクがある | removed | 緑（BGR 0,255,0） |
| B にだけインクがある | added | 赤（BGR 0,0,255） |
| 両方にインクがある | both | 赤 |
| 両方ともインク基準を満たさない | other | 赤。背景等の差として保持 |

分類を無理に断定しないため、多数決の割合しきい値を導入せず、次の保守的な規則を使う。

| `kind` | 条件 |
|---|---|
| `added` | added が 1 以上で、removed・both・other がすべて 0 |
| `removed` | removed が 1 以上で、added・both・other がすべて 0 |
| `color_changed` | both が 1 以上で、added・removed・other がすべて 0。さらに対象領域の A/B のインク形状が一致 |
| `changed` | 上記以外。追加・削除の混在、形状変更、背景・塗りの差、判定が明確でない場合 |

`color_changed` の形状確認には膨張前のインクマスクを使う。膨張で近い形が同じに見えただけの場合に、色変更と断定しないため。分類は元の正規化済み A/B 画像から行い、既存のグループごとの吸収処理のずれを新しく適用しない。ずれや描画差で条件を満たさない場合は changed に残す。

### 仕様案の事前確認

製品コードを変えない試行プログラムを `out/phase2-classification-probe/` に作り、既存の `PageComparer.Compare` が返す生差分と、局所背景のインク定義を組み合わせて確認した。次は単一クラスタの 7 ケース・既定の通常設定での集計。分類自体の製品実装や全テストの受け入れを済ませた結果ではない。

| ケース | 膨張なしの other 画素 | 1px 膨張後の other 画素 | 1px 膨張後の内訳 |
|---|---:|---:|---|
| D01 小数点の削除 | 0 | 0 | removed 22 |
| D02 マイナスの削除 | 17 | 0 | removed 55 |
| D03 数字変更 | 44 | 0 | removed 101、added 100、both 114 |
| D07 線の青→赤 | 474 | 0 | both 1,418 |
| D09 淡いセル塗り | 24,219 | 24,219 | other 24,219 |
| D10 マーカーの追加 | 27 | 0 | added 320 |
| D14 線の濃淡変更 | 0 | 0 | both 1,418 |

この結果を踏まえ、1px の膨張と、塗りの差を changed に残す規則を採用した。形状条件まで含めた本実装では、D14 は元のインク形状に 4px の差があるため changed になる。色変更の形状条件、厳密設定、A/B 反転、入れ子、除外、位置ずれ、複数 DPI の検証結果は検証記録を参照。

切り出しは B の画像を下地にして緑／赤を描く。ページ全体の重ね描きは従来の赤い差分・番号・黄色の除外領域を維持する。HTML には「追加（推定）」「削除（推定）」「変更」「色変更（推定）」と切り出しの凡例を出し、色だけに依存しない説明を付ける。

`schema_version` は予約済みの `kind` を使用するため 1 を維持する。分類の画素数を新しい JSON 項目として公開するかは、この段階では追加せず内部検証に使う。`shift_px`・`text_a`・`text_b` は null のままとする。

### 比較した代案

| 案 | 利点 | 注意点 |
|---|---|---|
| 既存の局所背景によるインク定義、曖昧なものは changed（推奨） | 差分検出と整合し、分類の断定を抑えられる | 薄い色・広い塗りの追加は一般的な変更になる |
| 白との差で画素を前景とみなす | 塗りつぶしの追加も added にしやすい | 色付き用紙や全面背景を前景と誤認しやすい |
| 90% 等の多数決で分類する | 微小な混在に強く、added/removed を付けやすい | 小さい別種の変更も同じクラスタ内で断定される。割合の根拠が必要 |

### 受け入れ条件

1. 既存 37 ゴールデンと最適化前後の一致テストを維持し、マスク・検出数・矩形・吸収・ノイズ・状態が変わらない。
2. 合成の追加、削除、色変更、形状変更、混在、淡いセル塗りについて分類を検証する。A/B 反転では added/removed が反転し、色変更と一般変更は対称になる。
3. 除外部分、捨てたノイズ、上限で落としたクラスタを分類に混ぜない。外枠内の変更を別クラスタとして集計する。
4. 画像端、通常／厳密設定、300/400dpi、非連続 Mat を含めて検証する。既存の位置ずれ吸収後の座標と分類元画像の関係を明記する。
5. JSON の kind、差分切り出しの画素色、HTML の日本語ラベルと凡例を確認する。外部参照なし、狭い幅とキーボード操作を維持する。
6. 実プロセスの PDF 結合テストを維持し、追加／削除を含む合成 PDF でも JSON・PNG・HTML まで確認する。
7. A4・300dpi の既存計測を再実行し、分類による時間・メモリへの影響を記録する。

## T2-2：移動の判定

SPEC の `matchTemplate` に沿い、T2-1 の結果への追加注釈として実装する。検索範囲は mm。相関が高くても無地や繰り返しの罫線などで候補が複数ある場合は移動と断定しない。

着手前に確定する事項：検索距離、スコア方式としきい値、複数候補の差、色変化もある移動の扱い、移動元・先が別クラスタになる場合の関連付け、`shift_px` の符号と座標系。推奨はクラスタ数を維持し、移動元・先の関連を明記する方式。

受け入れ条件：既知距離の上下左右・斜め移動、検索限界、移動なし、反復図形、形状変更、A/B 反転を検証。注釈の有無で既存の相違判定を消さない。

## T2-3：PDF テキスト層の注釈

PdfPig を使い、クラスタに重なる単語を `text_a` / `text_b` に入れる。OCR は行わない。CropBox の原点と pt→px、A/B ごとの元ページ寸法を反映する。回転ページは SPEC の方針に従って注釈を省略し警告する。

着手前に確定する事項：単語の重なり条件、読み順・改行、重複、出力量の制限、抽出失敗時の警告、回転の扱いをページ単位でどう記録するか。推奨はテキスト抽出失敗でも画像比較を完了し、理由を警告として残す方式。

受け入れ条件：文字を埋め込んだ合成 PDF、CropBox ずれ、回転、文字のない PDF、重なり境界、特殊文字と HTML エスケープ。文字抽出失敗で相違を見逃さない。新しい依存を含む Windows publish・ライセンス・ZIP 検証も実施する。

## T2-4：全体のずれの補正

推奨は `align.enabled: false` を既定にし、明示的に有効にした比較だけ B を補正する方式。補正を許容する範囲・最小の改善量・確度を設定し、低情報量や曖昧な候補では補正しない。推定量、実際の補正量、実効設定と `GLOBAL_SHIFT_APPLIED` を JSON・HTML に残す。

着手前に確定する事項：縮小率、探索・再評価方式、補正の採用条件、端の新しい余白の扱い、サイズ不一致、除外領域と補正の順番、画像・テキスト・矩形の座標系。ページ全体のずれで差分が消えるため、T2-1〜T2-3 と異なり比較結果を変える機能として扱う。

受け入れ条件：補正無効では Phase 1 と一致。全体移動、移動＋内容変更、白紙、罫線の繰り返し、ページ端の内容、範囲外、サイズ差で誤った補正をしない。補正後も実際の内容変更を残し、量と向きを出力する。

## T2-5：フォント非埋め込みの警告

PDF の使用フォントを調べ、埋め込みがない場合は `NON_EMBEDDED_FONT` を表示する。テキスト注釈の有無とは独立して警告を収集する。

着手前に確定する事項：Type0/Type1/TrueType/Type3・サブセット・標準フォント、未使用リソース、ページ番号とフォント名の記録、判定できない場合の扱い。推奨は使用を確認できたフォントを対象にし、不明を「埋め込み済み」と扱わない方式。

受け入れ条件：埋め込み有無、サブセット、混在、同名フォントの重複を含む合成 PDF。警告と理由を JSON・HTML に表示し、描画処理・判定結果を維持する。

## T2-6：フォルダ一括比較

`compare-dir <dirA> <dirB>` で相対パスを対応させ、比較結果へのリンクを持つ一覧 HTML・JSON を出力する。既存の 1 ファイル比較を再利用し、PDF は逐次処理する。

着手前に確定する事項：再帰対象、対象外拡張子・実形式の扱い、大小文字・パス衝突、片側だけのファイル、リンク・ジャンクション、ファイル名の正規表現と設定の優先順位、複数一致、個別の失敗を継続するか、集約終了コード・JSON スキーマ。推奨は曖昧な対応・設定選択をエラーにし、各ファイルのエラーを一覧に残して他の比較を継続する方式。

受け入れ条件：ネスト、日本語・空白、片側ファイル、読めないファイル、複数の設定、衝突、リンク、force での入力保護。各レポートと一覧の相対リンクがオフラインで機能し、個別エラーがある実行は終了コード 2、相違のみは 1、全一致は 0。

## T2-7：実帳票での評価

現時点で `samples/private/` に評価用の帳票はない。実帳票を用意し、人が無視すべき差と検出すべき差を確認してから評価する。元データ・抽出テキスト・切り出し画像は Git に入れない。

受け入れ条件：帳票の種類・DPI・フォント条件、期待値、誤検出／見逃し、時間・メモリを記録する。期待値を調整して不具合を通さない。再現用には機密を含まない合成ケースを追加する。パラメータや比較式を変える場合は既存の検出必須／無視必須を両立させ、SPEC・参照実装・期待値を同時に更新する。
