# 元ページを保持する内容面の製品接続仕様

2026-09-26。T3-1cの追加接続仕様。ユーザー承認済みの[限定した接続案](../verification/t3-1c-anchored-projection.md#製品接続へ進むための案)を具体化する。**A1のCore基盤・A2の比較・投影・採用検査・A3のCLI／出力／保存接続を実装済み、A4の製品受け入れは未完了**。[A1](../verification/t3-1c-anchored-foundation.md)・[A2](../verification/t3-1c-anchored-comparison.md)・[A3](../verification/t3-1c-anchored-output.md)の検証記録を参照。[SPEC 11.8](../SPEC.md#118-隣接ページへの送りと文書集約t3-1c開発中)の既存経路・比較式・既定値を変更しない。この文書は新経路だけに適用する。

## 1. 入口と採用範囲

既存送りの範囲確定・採用評価が文書全体で成功した場合は、その結果をそのまま使う。既存経路の失敗後、次の全条件が成立した場合だけ `anchored_content` を評価する。新経路が失敗したら、従来のページ単位の比較へ文書全体を戻す。既存経路の成功を新しい制限で拒否しない。

- `rows.enabled` と `rows.carry_enabled` がtrue、両側とも文字層を取得できるPDF、物理ページ集合はA1・A2・B1・B2だけ。全ページ対応で、明示的なページ選択もない。
- 同じ描画寸法、本文開始・行間隔・本文容量が一致する。本文の元文字列が文書内で一意で、共通行の順序が一致し、固定部の既存検証が成立する。
- 第1ページに同符号の一行原因が二つあり、第2原因は変更側の最後の本文行。最初の原因の前と原因間に各2行以上の共通行がある。次ページに送り帯とは独立した2行以上の支持行がある。実効 `rows.min_support_bands` が大きければ、その条件も満たす。
- 共通する送り行の全体が元ページ末尾と次ページ先頭を隙間なく埋め、送り高さが二原因の高さの合計と一致する。元帯の全BGR一致と既存の両端・両順序・比較条件による置換検証を通す。文字一致・行ハッシュだけでは採用しない。
- 全体補正は設定自体が無効。数値対応証拠、除外、領域は空で、両ページの実効 `ComparisonParameters` が等しい。
- 初期接続は **300dpi、normal相当の実効Diff／Ink／Cluster／Move値** に限定する。プロファイルの名前ではなく解決済みの値を比較し、同じ値の明示設定も受け付ける。strict／loose・他DPI・比較値の上書きは新経路を見送る。置換検証内でstrict／looseを使うこととは別の制限であり、それらの内容比較の受け入れを意味しない。

行整列の設定は実効値を既存検査へ渡す。最大移動、区間数、画素再探索、一意性、支持帯／インク、ページごとの改善率を緩めない。送り帯の一致を支持へ加算しない。Dの同変位の連続区間から、同じ物理ページの元の語で支持を作る。固定部も検査し、再探索が予定したdyを変えた場合は見送る。C1と元A1/B1、C2と元A2/B2をそれぞれ既存の改善率で評価し、合計の改善で片方の失敗を埋めない。

この制限は、診断で実際に使った条件を最初の接続範囲にするためのもの。他DPI・比較条件、三ページ以上、片側ページ、数値行自体の跨ぎ、領域・除外の一般化は別の受け入れを要する。新しいユーザー設定や自動的なしきい値変更は追加しない。

## 2. 型、座標、証拠の結合

Coreに次の意味を持つ型を追加する。以下の型名は実装名の基準とし、コンストラクターで不変条件を検査する。文字列 `A1` の分解や診断ツールのreflectionを製品APIへ移植しない。

| 型 | 保持する内容と責任 |
|---|---|
| `AnchoredContentPlan` | 実行内の文書記述への参照、候補ID、二原因、支持／送り証拠、実効設定の不変スナップショット、C/D、資源予約。Mat・PDF・可変Listを公開しない |
| `OriginalRowSpan` | `PageFlowPageKey`（A/B、1始まり物理ページ）、Oのtop・height。既存のG/O共用帯と区別する |
| `ContentSurfaceId` | 所属物理ページ。初期接続ではC1・C2のIDは1・2。保持側がAかBかは別項目 |
| `AnchoredContentPiece` | Cのtop・height、A/Bそれぞれの `OriginalRowSpan?`。xは全幅で不変。少なくとも一側が実画像 |
| `AnchoredContentSurface` | ID、寸法、保持する元ページ、上から並ぶpieces。片側の元物理ページを全高・恒等写像で保持する |
| `AnchoredDisplayPlan` | 表示先物理ページとDの写像。同ページのA/B全行を各1回保持し、欠ける側だけ白を足す |
| `ContentClusterKey` | `(ContentSurfaceId, Cで確定したClusterId)`。列挙順、Dの読み順、保存順で変更しない |
| `ContentDisplayPart` | 内容キー、表示ページ、C矩形、D矩形、A/B別の元ページ付き矩形、所属画素数。画素の所属はCのIDから作る |
| `AnchoredContentResult` / `AnchoredDisplayResult` | 前者はCの比較値・内容ID、後者はDのマスク・断片・実構造。別の型として所有権を持ち、DのマスクとCの件数を通常の `PageComparison` に偽装しない |

Oは `original_top_left`、Cは `content_top_left`、Dは `row_display_top_left`。px矩形は左上を含み右下を含まない。設定とmm表示の換算は `Units` と既存の換算処理に従う。片側nullは白で、別ページの同じ座標を暗黙に参照しない。保持側は未挿入側（逆方向では未削除側）とし、A固定にしない。

検証を二層に分け、両方を必須にする。

1. **証拠からの再構成**：現在の文書記述・全行配置・候補集合・二原因・全共通行対応・次ページ支持・実効設定からC/Dと省略帯を再構成する。受け取った帯集合が同じでも対応先が交換されていれば不成立。候補の選別前後で元候補IDを変更しない。
2. **幾何と画素**：各Cの保持側が元ページ全体を連続して覆い、四元画像の全走査行がCの出自または二原因のどちらかにちょうど1回属する。Cの両側同時欠落は禁止。反対側がnullの帯は保持側の全BGR値が255であることを確認する。254の1画素も白としない。Dは各物理ページの全元行を各1回保持する。

実行内では同じ文書記述・計画への参照同一性を検査する。さらに四元画像の寸法とBGR SHA-256、入力PDFのファイルSHA-256、DPI、実効比較／行／文字設定、全行配置、候補・支持行のIDと対応、C/Dの全帯を、順序と形式を固定した指紋へ結び付ける。Coreはファイルを扱わず、PDFの同一性はCLIが結び付ける。ハッシュだけで帯一致や意味上の対応を証明しない。

## 3. 予約予算と画像の寿命

既存の128ページ／32,768行／2,097,152文字／512Mi画素／64MiB／128候補の制限を維持する。新経路の記述・証拠・投影用の追加配列は、**既存の文書・非送り・数値・曖昧候補証拠を計上した64MiBの残り**へ確保前に予約する。予算を新しい候補ごとにリセットしない。加算・積はcheckedの64bit演算で行い、桁あふれも予算超過として見送る。

以下は製品実装用の保守的な計上単位であり、実RSSの上限ではない。診断ツールで既に実装した予算ではない。

| 対象 | 予約量（B） | 解放時点 |
|---|---:|---|
| 計画・設定・指紋・検証の固定領域 | 4,096 | 計画破棄 |
| 元ページ参照 | 256 × P | 計画破棄 |
| 本文／固定行の索引 | 64 × L | 計画破棄 |
| 評価対象の元候補 | 512 × H | 計画破棄 |
| C帯・D区間・原因省略帯 | 256 × (Mc + Md + E) | 計画破棄 |
| 支持・跨ぎの元行参照（両側を別に数える） | 256 × R | 計画破棄 |
| 保持する内容クラスタ | 512 × K | 出力モデルの解放 |
| D断片、元矩形／監査の追加レコード | 256 × F | 出力モデルの解放 |
| Cの疎なマスク区間 | 48 × Q | 全Dへの転写終了 |
| 移動のテンプレート／検証窓の対 | 192 × V | 投影の確定 |
| C画素所属IDの配列 | 4 × C画素数 | 当該Cの疎区間変換終了 |
| 投影用のラベル→ID補助配列 | 4 × ラベル数 | 所属ID構築終了 |
| 行転写の一時バッファ | 8 × 最大幅 | 当該走査終了 |
| 複製する文字列 | 2 × UTF-16文字数 | その複製の解放 |

Pは元ページ数4、Lは記述内の全行数、Hはこの評価へ渡す元候補数。Rは出力を含む保持する行参照の総数で、同じ行を複数の配列へ持つ場合は各参照を計上する。本文文字列自体は共有する。基本予約は `4096 + 256P + 64L + 512H + 256(Mc+Md+E+R)`。K/F/Q/Vは**使用件数ではなく割当容量**を数える。索引や並べ替えの参照配列は追加で8B/要素、辞書は64B/項目、配列／辞書ごとの固定費64Bを予約する。スナップショット化で新旧配列が共存する間は両方を計上し、返却後にだけ旧予約を解放する。上表にない追加保持は実装時に予約項目を明示し、暗黙の無制限キャッシュを作らない。

A1では行索引・二辞書・作業配列に `64×16 + 8×(6L+24) + 64L` を追加予約し、C/D・支持参照・被覆検査配列も確保前に計上する。A1の一時予約は計画破棄まで保守的に保持する。A2で `AnchoredContentBudget` の容量予約APIを比較器・疎区間・結果所有型へ接続した。比較中の所属IDと移動証拠は疎区間・注釈への変換後に解放し、保持内容と表示マスクは別々にDisposeする。単語再取得後の行整理にも単語数×256Bの参照／レコードと、一時文字複製容量を確保前に予約する。入力PDFと文字設定のSHAはCoreでは呼出側から受け取る識別子であり、実ファイルと収集時設定への結合はA3で行う。

Qは `(Cのy, x開始, 長さ, cluster_id, mask_flags)` の区間列。クラスタIDが0の生差分・除去マスクも保持する。区間の追加／容量拡張の**前**に予約し、密なノイズで圧縮できない場合も間引かず全候補を取り消す。比較器へ投影を依頼する追加APIにも予約を渡し、ラベル数が判明した時点で補助配列を確保前に計上する。通常比較にはその予約を要求しない。JSONに画素区間の全配列は出さない。集約は計画と保持中の結果を差し引いた残りを既存式で予約する。集約だけの上限超過は既存どおり `shared_descriptor_limit` とし、採用済みC/Dと未集約件数を維持する。

既存記述の画素量に、作成予定のC両側とD両側の画素量を加えた `document.Usage.Pixels + 2Σarea(C) + 2Σarea(D)` を、最初のC確保前に512Mi画素以内と確認する。同寸法画像でも予定した出力面ごとに数え、再読込の回数は重ねて数えない。999×1250の四元画像、C二面、999×1450のD二面では15,784,200画素。これは処理対象面の上限であり、同時保持量やコア内部バッファの上限とは区別する。

画像の処理段階を重ねない。

1. 記述収集・帯証明・支持と通常比較を逐次実施し、ページ画像を都度解放する。PDFiumの呼出しは逐次。PDFハンドルは既存の入力A/B用だけで、ページごとのハンドルを計画へ残さない。
2. 一つのCのA/Bを確保し、必要なOを一枚ずつ再読込して同一性を検査、帯をコピーして即解放する。同時に四元画像をキャッシュしない。Cを比較して生差分／所属ID／除去マスクを疎区間へ変換し、C画像と比較器の結果を次のCへ進む前に解放する。
3. 最終出力時はC画像を一面ずつ保存して解放する。Dは物理ページごとに作成し、全C由来の疎区間を合流させて保存する。別ページのDマスクは同時に持たない。raw evidenceはOから独立した段階で生成する。

新経路の転写処理が所有する全ページカラーMatは「CまたはDのA/B二枚＋読込元一枚」まで。帯の置換検証は既存どおり元二枚と置換作業画像を使う。比較コア内部の特徴量・マスク、PDFレンダラー、PNGエンコーダーの一時領域はこの三枚に含めたと偽らず、別途ピークRSSを測る。新経路の画像保存はまず逐次とし、比較中の保存を行わない。ROIは所有元より先にDisposeし、例外・キャンセル・見送り時も全予約とMatを回収する。

## 4. 投影、所属、構造監査

Cで一度だけ比較・クラスタ化・ノイズ処理・上限処理を行い、その画素IDをC→O→Dへ写す。同じC画素がA/Bから同じD位置へ戻る場合は一画素に統合する。別のDへ戻る場合は同じ内容キーの参照断片。表示断片が `cluster.min_pixels` 未満でも捨てず、Dで再クラスタ化しない。ID0の生差分もDマスクへ写すが、内容クラスタを新設しない。異なる内容キーの表示画素が同じD位置を共有しても片方の所属を失わず、Dの生差分マスクは和集合、各クラスタの断片は別々に保持する。

所属ページはCの保持する物理ページに固定する。保持側の全ページ恒等写像により、所属ページには各内容画素が必ず表示される。所有クラスタの `id` はCのIDとし、Dの読み順で振り直さない。関連IDは同じC内で解決し、HTMLの並べ替えは表示順だけを変える。構造IDは従来どおり各Dの読み順で独立に採番する。

Cの `raw_pixels`、`noise_dropped`、`absorbed_groups`、クラスタの `pixels`・内容fill比・比較上限の分母はCの値を保持する。Dの画素和で上書きしない。Dごとの `display_raw_pixels` は投影後マスクの和集合であり、ノイズも含む表示監査値。文書全体の検出画素数として合算しない。

新経路では構造ごとに `role: cause | carry | movement` と `compared_in_content` を記録する。causeはCから省略した二つの原因、carryとmovementは内容比較済み。`omission_audit` は**Cから除いた元帯**だけを数え、送り元・先を追加の省略にしない。全行のC被覆検査とD被覆検査は別に記録する。因果集約には全Dの実構造を各1回渡し、所有クラスタ数だけを内容件数へ加える。全構造の説明が成立しなければ集約のみを見送る。

移動注釈は、Cの元・先クラスタに加えてテンプレートと全検証窓を写す。同一Dページ上で全窓が欠落なく一つの変位へ写り、元の検証関係を保持できる場合だけ、そのD上のshiftと関連IDを表示する。複数ページ・非一様写像では内容と件数を保持して `changed`、shiftと移動の関連IDを空にし、既存理由 `nonuniform_display_mapping` を記録する。証拠自体がなければ `movement_proof_unavailable`。診断で実際のmovedは未検証のため、後述の受け入れで成立／不成立の両方を作るまで注釈変換を完了扱いにしない。

## 5. JSON、HTML、一覧の契約

`schema_version: 1` の追加項目とする。無効・既存成功・新経路へ進まない入力では新しい項目を省略し、既存項目／画像／終了コードの互換を保つ。新経路を評価した場合だけ `page_flow.anchored_content` を付ける。これは実行状態・証拠の監査であって、読込可能な計画キャッシュではない。

| 追加先 | 必須の内容 |
|---|---|
| `page_flow.anchored_content` | `status`（applied/skipped）、`reason`、`proof_version: 1`、`fingerprint`、`pages`、予約の `budget`（limit/peak、単位Bと画素を区別）。理由だけで実証拠を代用しない |
| 同上の `evidence` | 元候補ID、二原因のO帯、送り元／先のO帯、前方／原因間／次ページの支持行と対応先、跨ぐ全行と対応先。各行はA/B・ページ・O矩形・元本文を持つ。`pixel_equality_proven` は帯画像検証だけ、行支持への転用はfalse |
| 同上の `surfaces[]` | `id`、`owner_page`、`anchor`（side/page）、`coordinate_system`、`size_px`、`pieces`（content_start/length、A/B別side/page/topまたはnull）。適用時だけ出力 |
| `pages[].row_alignment` | 新経路ではreasonを `anchored_content` とし、既存の採否・D segments・構造・監査を維持。旧 `content_canvas` はnull、新しい `content_surface_id` で上記Cを参照。既存の同一ページ用piecesへ別ページを偽装しない |
| `pages[].clusters[]` | 所属ページにだけ置く。追加 `content_ref: {surface_id, cluster_id}` と `source_parts`（A/B・元物理ページ・O矩形）。既存bbox／display_parts／row_parts／cropsは所属ページのDだけ、content_bboxとcontent_fill_ratioはC |
| `pages[].content_references[]` | 別C由来の参照を内容キーごとに一つ。`content_ref`、`owner_page`、`owner_cluster_id`、当該Dのbboxとparts、`display_pixels`、当該Dのcrops。クラスタ配列へ複製しない |
| `pages[].content_display` | `coordinate_system: row_display_top_left`、`raw_pixels`（表示監査値）、`reference_count`（異なる内容キーの数）。通常の `pages[].raw_pixels` と区別 |
| 新経路の構造 | 既存構造に `role` と `compared_in_content` を追加。C省略の元帯一覧を `anchored_content.omitted_original_bands` に保存する |

`source_parts` と参照のpartsには `content_bbox_px`、`display_bbox_px`、`source_a`／`source_b`（side/page/coordinate_system/bounds_px）、`display_sides`、`pixels` を持たせる。source_a/bは該当C断片の両側の出自、display_sidesはそのD位置へ実際に投影された側の集合。所有者のsource_partsは所属Dの断片だけを持ち、別Dの断片はcontent_referencesへ置く。複数ページを外接矩形にまとめない。旧 `source_a/b` はクラスタの該当側の全出自が所属物理ページ内で表せる場合だけ設定し、それ以外はnull、新項目を参照する。旧 `row_parts` も当該断片に対応する出自が所属物理ページ外ならその側をnullにする。新読者は新経路の出自を常にページ付き `source_parts` から読む。新項目を無視する旧読者は別ページの参照表示を再現できないが、内容件数を二重に受け取ることはない。

所有クラスタのbbox／fill_ratioは所属Dの断片の外接矩形とCのpixelsを使う既存の関係を維持し、厳密な内容密度はcontent_fill_ratioを見る。`images.a/b/overlay` はD、`images.content_a/b` はそのページが所有するC、`raw_evidence` はO。全パスは出力フォルダ内の相対パス。参照用切り出しは `crops/p002_ref_p001_c001_*` のように表示ページと所有者を名前へ含め、通常の切り出しと衝突させない。

ページの `difference_count = clusters.Count + structural_change_count` を維持する。参照件数は加えない。Cがsameでも内容参照または構造があれば表示ページのstatusはdifferentとし、`summary.pages_different` に含める。文書のclustersは所有クラスタの総数、未集約Uは内容と全実構造の総数、集約後は既存式 `U - Σ(n-k)`。compare-dirは個別結果のSummaryをそのまま使い、参照表示から件数・ファイル数を再計算しない。参照の存在だけで不完全な比較をcompleteへ変えない。

HTMLは「内容差分 P1-C1（1ページで計上）」と「P1-C1の参照表示」を区別し、所有者と各D断片へ相互リンクする。表示の画素数には「表示上の画素数」と明記する。画像・切り出しの見出しにC/D/Oと物理ページを表示し、元本文はエスケープする。JavaScript無効でも全参照と画像へ辿れる静的リンクを用意する。外部通信・CDNを使わない。

PDF注釈はC断片ごとの元A/Bページの語を取得して対応させ、同じyの所属ページから文字を拾わない。取得上限・回転・座標不明は既存どおり省略理由を記録する。除外YAMLは各断片を**元Aの該当物理ページ**へ戻してから既存marginを適用する。A出自がない参照断片では作らず、所有者の該当断片へ案内する。送り先にあるB画像を根拠にAの同座標へ除外を作らない。参照ページから文書全体の複数ページ除外を一括生成しない。

raw overlayの色・共通色設定、左上合わせ、元カラー画像、保存条件は現行のまま。C/D・採否・比較マスクから生成せず、同じOと出力設定ならPNGが全画素一致することを要求する。

### 件数と出力の具体例

診断 `cross-page-context-ab` の実測値を使った[出力項目の抜粋](t3-1c-anchored-output-example.json)を併設する。これは製品生成物でも完全なresult.jsonでもなく、以下の対応を確認するための仕様例である。

| 項目 | ページ1 | ページ2 | 文書 |
|---|---:|---:|---:|
| Cの生差分 | 956 | 0 | 956 |
| 所有内容クラスタ | 1 | 0 | 1 |
| 別ページの内容参照 | 0 | 1 | 件数へ加えない |
| Dの生差分表示 | 956 | 238 | 1,194は検出画素数ではない |
| 実構造 | 4 | 2 | 6 |
| 未集約difference_count | 5 | 2 | 7 |
| 集約後 | — | — | 3（内容1＋原因2） |

C1の `(581,700)` の画素はA1由来としてD1の `(581,800)`、B2由来としてD2の `(581,300)` に出る。キーは両方 `{surface_id:1, cluster_id:1}`。元ケースなら内容0・6→2、色変更ならCの3,807px・1クラスタを保持して7→3。逆方向は保持側とDの区間順序が変わるため、正方向のD矩形を流用しない。

## 6. 採否と保存の状態遷移

`未評価 → 証拠・写像確定 → 全ページ事前採用検査 → 仮保存 → 出力検査 → 公開` とする。事前検査ではC結果と画像を保持せず、設定／画像／計画の指紋、ページ別採否と比較値だけを残す。仮保存では全Cを逐次再比較して採否・比較値・マスクのダイジェストを照合する。投影用の疎区間を保持してから全Dを逐次保存し、最後に所有者／参照／構造／集約と全画像リンクを検査する。

| 条件 | 処置 |
|---|---|
| 対象外、証拠不足、帯不一致、非白余白、支持／改善率不成立 | 文書全体の新経路を見送り、従来比較を実行。理由を保存し部分採用しない |
| 新経路の確保前予算不足、候補上限、Cのtoo_different／CLUSTER_LIMIT | 文書全体を従来比較へ戻す。Cの上限をDで再計算しない。後者は `anchored_content_incomplete` として記録し、従来比較の網羅性を保持 |
| 仮保存中に投影／結果保持の予算不足 | 仮の候補画像・参照を全て破棄し、別の空の試行用ディレクトリで従来比較を再実行。最終出力へ候補の孤立PNGを混ぜない |
| 因果集約だけが不成立／予算不足 | C/Dと未集約Uを維持。部分的な原因集約をしない |
| 入力PDF／元画素／計画指紋の変更、確定後の比較値不一致 | 処理エラー。変更した入力を従来比較へ黙って切り替えない |
| PNG／JSON／HTML／再読込のI/O失敗、キャンセル | 処理エラーとして仮出力を破棄。成功扱いの欠落参照を作らない |

予算不足は確保前の判定で処理する。実際のメモリ確保例外を安全な通常見送りとみなして実行継続しない。計画の事前検証へ不正な証拠が渡された場合は見送り、確定済み計画の破損や内部の参照不整合は処理エラーとする。

設定ファイルは既存どおり読込時の実効スナップショットを使い続け、途中で読み直さない。実行中に設定ファイルが編集されても現在の実効値へ混ぜない。設定オブジェクト／計画の差し替えは拒否する。PDFのファイルSHA-256は開始時・最終比較前・全出力完了後の公開直前に照合し、画像は各再読込時に照合する。公開後にユーザーが入力を変更することまでは検証対象にしない。

全ての保存は既存 `OutputWorkspace` のstaging内で行う。新経路用の試行ディレクトリには所有範囲を設け、fallback時はその範囲だけを消す。公開は全ページとJSON/HTMLが揃ってから1回。比較の全ページ採否とファイル公開は別々に検査する。診断の `published_pages=[]` は実ファイルの原子的公開を検証した結果ではない。

現行OutputWorkspaceは既存出力をbackupへ移してからstagingを移す。したがって**プロセスクラッシュ・電源断を含む完全な原子性は保証しない**。通常の保存失敗では旧出力を維持、置換失敗では復元を試み、復元失敗なら旧出力のbackup位置を報告する。公開成功後のbackup削除失敗では、新結果を保持し「保存済み・旧出力の削除失敗」を報告する。この境界を変更せず、公開前失敗・置換失敗・復元失敗・公開後清掃失敗を別の受け入れにする。compare-dirは既存の各ファイル対のエラー記録／全体の公開契約に従い、他の対まで架空の成功へ変更しない。
