# T3-1c：元ページの周辺を保持する帯の検証案

2026-09-22。[前回の境界問題](../verification/t3-1c-page-flow-probe.md)を受け、ユーザーの続行指示に基づいて設計・独立検証する補足案。製品には未接続。[主仕様](t3-1c-page-flow.md)の件数・既定無効・送りを相違として残す判断は維持する。

検証結果：37入力・750比較でC#／Pythonが一致し、既存の共通面174条件も再確認した。下記の四比較0**だけ**による採用は、境界をまたぐ薄い塗りを分割して見逃すため不採用。初期案を「帯の全画素一致を必須とする」に限定し、下記の四比較は元の周辺を保持できることの確認に使う。[詳細な結果](../verification/t3-1c-context-verification.md)を参照。

## 検証を受けた初期案

指定したRa／RbのBGR全画素が一対一に一致することを追加の必要条件とする。これは送りの認定範囲を狭める条件であり、5章の通常比較の式や設定値は変更しない。白・薄色・罫線も含め、しきい値以下の画素差も完全一致には含めない。

一致する帯では四つの全ページ比較が既存の完全一致経路で0になる。非一致の帯は、四比較が0でも`nonidentical_band_not_proven`として送りを確定せず、帯をCから外さない。既存の比較へ戻す。この理由名は試行用で、製品の出力契約には未追加。

この限定には代償がある。単独のオブジェクトが2px動いた場合、通常比較がnormal／looseで吸収しても送りは確定しない。サブピクセル描画・アンチエイリアス差にも同じ制限がある。今回のR10／R11・連鎖の入力は全画素一致なので条件を満たすが、任意のPDFやSkia入力でも成立するとは未確認。許容付きの認定は境界をまたぐ変更を分割しない別の証明ができるまで拡張しない。

画像が一致しても、自動推定した帯の範囲・構造としての根拠・一意な文字対応・既存Cの安全条件・全元画素の帰属が必要という主仕様は維持する。特に反復行・帯外の変更・片側ページ全体は全画素一致だけでは確定しない。

## 元ページを使う双方向の置換検証（必要条件の確認）

元ページAの帯Raと元ページBの帯Rbを候補とする。幅・高さが等しく、元画素を整数座標で一対一に対応させられることを前提とする。表示面の詰め物や補間画像は使わない。

1. Aの複製を作り、Raの全画素だけをBのRbの全画素で置き換えたA'を作る。Raの外側はAそのまま。
2. 同様に、Bの複製のRbだけをAのRaで置き換えたB'を作る。Rbの外側はBそのまま。
3. A対A'、A'対A、B対B'、B'対Bを既存5章の比較器で**元ページ全体**について比較する。四つとも生差分0を必要条件とする。
4. 除外・領域による差分の消去・ノイズ除去後の件数は一致の根拠にしない。帯の外に出た生差分も数える。境界を白くする、帯端をマスクする、通るまで帯を狭める処理はしない。

この試行ではnormal／strict／looseをそれぞれ同じ設定で四比較する。製品へ接続する前には、両端の実効diffが異なる場合、帯が複数の領域にまたがる場合、全体補正を含む元座標の扱いを別途確定する必要がある。片側の緩い設定だけで採用することは認めない。

比較式・しきい値・groupの作り方を変えない。ページ全体を使うため、有限の余白で連結成分やgroupを切らない。A/B順の非対称性が採否に入らないよう、各ページで比較順も交換する。

## 得られる保証と得られない保証

帯が全画素で一致していれば、A'=AかつB'=Bになる。元ページの周辺が異なっていても、既存の完全一致経路で四比較とも0になる。前回のR10／R11で周辺の別の行や罫線終端を直接比べたことによる4〜8pxの差分を導入しない。

帯が異なる場合は、変更が各元ページの実際の周辺でどのように判定されるかを調べる。帯の外の連続罫線までgroupに含め、境界をまたぐ相反する移動を帯内部だけの都合で吸収しない。章5がもともと許容する変更・既知の限界はそのまま残る。一般にあらゆる変更を検出する保証ではない。

これは**指定した帯の画像検証**である。行の対応・本文と固定部分の区別・帯の範囲・原因の一意性は別の前提であり、画像が一致したことだけから正しい送りとは確定しない。

帯外の変更は置換検証の対象ではない。後続の内容比較面C、原因の構造帯、未比較部分に必ず残す。Cから省略する範囲と、実際に検証した帯は同一にし、半開区間で全元画素の帰属を保つ。新しい片側ページの帯外は固定部分の検証と全非白内容の網羅性を別途必要とする。帯の一致からページ全体の一致・網羅性を推論しない。

元A/B、確認用オーバーレイは元のまま。A'/B'は「検証用の置換画像」として独立した種類・元座標・置換範囲を持たせ、raw evidenceとして扱わない。

## 独立検証の期待

- 前回のPDF・帯座標を固定する。R10／R11／連鎖の既知の送り帯は四比較0。文字変更・同文の色変更・帯端変更は0にならない。
- 帯のすぐ外の変更は帯の検証に混ぜず、既存Cに変更が残ることを確認する。新ページの余分な薄色は帯の一致で消さない。
- 長い罫線の帯内だけを横へ動かした入力を用意する。帯だけでは二段目で吸収されても、元ページ全体では罫線との継ぎ目を検出する。帯の前後40pxを越える連結部分を残す。
- 帯の内側・境界をまたぐ部分・外側に、灰色罫線、薄い塗り、色の変更を置く。内側の変更を境界扱いで捨てない。
- 帯から離れた単独オブジェクトの許容内の移動はnormal／looseで吸収し、strictでは残す。両端の設定が違えば、厳しい側に残る差分を無視しない。
- C#と変更していないPython参照実装で、原画像・置換画像の対応と全生差分マスク・統計を照合する。既存の174条件の内容比較面を別に再確認する。

## 資源と後続の境界

この試行はページ全体の比較によりgroupの保存を優先する。将来帯へ狭める最適化は、ページ全体との同値性が示されるまで導入しない。帯の生画素が完全一致する場合は既存の完全一致経路と同値であるが、その高速化を画像以外の前提の省略には使わない。

製品は隣接する候補帯を持ち越し、必要な元ページを逐次再描画して各端点を検証できる。全文書分のMatは保持しない。再描画・比較回数・最大RSS・候補上限の実測は別工程。失敗・上限超過・不明な所有範囲では採用を見送り、既存の相違を保持する。

独立した入力で成立しても、自動候補・構造帯の内容保存・片側ページ・集約の事前検証が終わるまで製品へ接続しない。
