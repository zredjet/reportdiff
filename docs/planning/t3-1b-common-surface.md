# T3-1b 補足仕様案：表示面から独立した内容比較面

2026-09-22。状態：**承認済み・製品実装中**。補足仕様提示後の「ローカルリポジトリが一部変更になっています」「次の作業に進んでください」を受け、実装へ進む。互換性の基準は、追加された進捗表示と共通色設定を含む v0.1.4（`6a899d1`）へ更新する。独立試行の記録は当時の v0.1.3 の証跡として維持する。「次に進んでください」を受けて、[前回の検討課題](../verification/t3-1b-mapped-features.md)を具体化した。[検証結果](../verification/t3-1b-common-surface.md)を根拠とする。

承認済みの [行整列仕様](t3-1b-rows.md)のうち、「表示用の詰め物を含む画像を既存比較へ渡す」という部分を置き換える。行推定・支持・次点との差・構造変化の件数・既定無効・raw evidence の独立性は維持する。比較式と既定値を変えず、何を比較面とし、どの座標でクラスタを作るかを明示する。

## 推奨する処理

三つの画像座標を分ける。

| 面 | 内容 | 用途 |
|---|---|---|
| 元画像 | 正規化した元 A/B。全体補正・行整列前 | raw evidence、元カラー画像、元の PDF 座標 |
| 表示面 D | 現在の行整列案の PageMap。片側帯を白い詰め物で補う | A/B表示、構造変化、判定の描画、既存の bbox |
| 内容比較面 C | 対応帯を順に転写し、片側の内容帯を外す。純白余白は両側に残す | 5.1〜5.5、分類、移動候補の検証 |

D の A/B は元の画素を全て順序どおり一度ずつ保持する。C から省くのは、行推定・支持条件で**挿入または削除と確定した帯だけ**。画素が非白であるという理由だけで構造帯にしない。同じ位置の内容置換を、削除＋挿入として外すことも禁止する。

`white_space` は片側の実体が全 BGR チャンネル255の余白。Cでも同じ高さを確保し、相手側に同じ純白を置く。薄い塗り・罫線・印があれば余白として扱わず、支持された内容帯か、対応帯かを再確認し、決められなければ見送る。余白を残すのは、固定フッター等の近傍と内容同士の間隔を保つため。両側の白い余白は先にできるだけ対応付け、同じ空白を両側の片側帯として二重に残さない。

片側の内容帯を外した隣接点では、少なくとも片側の元画像で前後が連続していることを要求する。隣り合う対応帯の間で、AとBの両方から別々の非白帯を削らない。対応帯のないページ、両側余白の対応を確定できないページも、行整列を見送る。単に同じ文字列を対応付けただけでは、この条件を満たしたことにしない。

## 近傍と二段目の契約

Lab・ぼかし・局所コントラスト・インクは、Cに転写し終えた画像から計算する。前回案の「元画像の特徴量を転写する」経路は使わない。group の生成、ずれ候補の探索、同点の選択順も全て C の既存コアで完結する。

- 対応しない内容帯や、Dの詰め物はCの探索対象に入らない。ずれ候補ごとに評価画素を外したり、評価できない画素を差分0と数えたりしない。
- C内の帯の境界は画像端として扱わない。C全体の端だけに、既存のフィルター境界処理とシフトの端複製を適用する。
- インクの連結成分や二段目のgroupを帯ごとに切らない。一つのgroupには既存どおり一つのずれを選び、周期ケースの複数解も従来どおり許容する。
- ユーザーの除外は従来どおり5.4で適用する。構造帯をCから外すこととは区別し、それぞれの範囲と面積を記録する。

局所近傍への追加の採用条件として、Cの各画素行の上下 `r` 行が、少なくとも片側の実際の元画像で連続した行範囲に対応することを要求する。生成した純白しか存在しない側は、その区間の根拠にならない。

```
s = 実効 diff.max_shift_mm の px 換算値
r = max(2 + s, max(1, ink.background_radius_mm の px 換算値))
```

regionsがある場合は全実効設定の最大rを使う。Cの端に近傍が接する場合は、根拠側も元画像の同じ端に達することを要求する。近接した逆向きの切断などでどちらの元画像にも連続する近傍がなければ、`no_bands`、detail=`unsupported_common_neighborhood` としてページ全体の行整列を見送る。窓を小さくして通したり、そこでgroupを分割したりしない。

この条件は新しい近傍の作り方を制限する保守的な条件であり、任意の帳票で検出を保証する証明ではない。SPEC 5.6 の既知の限界は維持する。試行では既定プロファイルの174条件を維持し、4pxしか離れていない逆向きの切断を両方向で拒否した。設定全域・領域併用の検査は製品実装時の受け入れに含める。

A/B交換では、比較入力・写像・構造変化の対応を保証する。残差は**各方向の既存コアの基準結果**への一致で確認する。今回の固定フッターの6組では、基準自体に1pxのマスク位置差があり、両方向とも4画素／1件を検出する。全画素のA/B完全対称性は既存の5章が保証しておらず、今回その目的で式や探索順を変更しない。元の「残存クラスタが対応する」の受け入れを、この範囲として明示的に確認する。

## クラスタ・件数・座標

**クラスタ化までCで一度だけ行う。Dへ転写してからクラスタを作り直さない。** そうしないと、挿入帯をまたぐ一つの変更が二つのクラスタに分裂したり、分裂した各片がノイズとして捨てられたりする。

- 採用クラスタはCで確定した一つの単位。D上で複数の断片になっても、1件として扱う。`pixels`、ノイズ数、上限で落とした数はCでの結果を維持する。
- `too_different` の分母はCの全面積。Dの詰め物で相違率を薄めない。元／C／Dの寸法・省いた内容帯・保持した余白の面積を出力する。
- `bbox_px` / `bbox_mm` は、承認済み案どおりD上の外接矩形。`display_parts_px` に帯別の断片を追加する。断片はクラスタの生差分を帯ごとに分けた矩形とし、別のクラスタを混ぜない。
- `content_bbox_px` / `content_bbox_mm` / `content_fill_ratio` をCの値として追加する。既存の `fill_ratio` は引き続き `pixels / D上のbbox面積` とし、Cの値をそのまま転記しない。
- 元A/Bの `source_a` / `source_b` はDだけを経由して推測せず、Cの帯と元画像の直接の対応から求める。生成した純白の側には元の対応がないことを断片ごとに残す。
- 表示の採番はDのbboxを既存の読み順で並べて付ける。Cで決めたクラスタの同一性を保ち、マスク・注釈・関連ID・HTMLの番号を一緒に更新する。
- 構造変化数と総件数の式は既承認のまま。Cが差分0でも、除外されていない構造変化があれば相違・終了コード1。余白そのものは構造変化数に含めない。

例：Cで `(x=42,y=78,w=2,h=4)` の8画素が1クラスタなら、高さ60pxの挿入を挟むDでは `y=78,h=2` と `y=140,h=2` の2断片になる。同じ番号で両方を示し、件数は1、Dのbbox高は64、Cのbbox高は4となる。

## 設定・分類・移動・画像

設定の基準は、承認済みの「行整列前のA、全体補正後の共通座標」を維持する。まず従来案のPageMapでDの領域所有・除外を確定し、Cの各帯でその所有マスクを転写する。内包関係の優先順位は元の宣言に従い、圧縮後の矩形同士で決め直さない。C上で領域を切り出して個別比較せず、実効設定ごとの全C比較の結果を合成し、最後に一度クラスタ化する。

分類はCでの画像・領域設定・生差分を使い、分類結果をDの同一クラスタへ戻す。既存の移動注釈は、元／先の検証範囲をDへ戻したときにそれぞれ一定の平行移動で表せる場合だけ、従来の変位へ変換して付ける。複数の変位を一つの値へ丸めず、表せない移動注釈は `changed` のまま、理由を `row_alignment` の注釈省略情報に記録する。生差分・件数は消さない。行送り自体の `block_moved` は別の構造変化として維持する。

除外YAMLはDの各表示断片へ従来の余白と外向き丸めを適用し、設定用Aへ逆写像して複数矩形として出す。詰め物を挟む大きな外接矩形一つから、関係ない中間帯まで除外する候補を作らない。クリップ・重複整理と、実CLIへの貼り戻しを確認する。

`images.a/b` はDを維持し、行整列採用時は実際に比較へ渡したCの `images.content_a/content_b` も保存する。HTMLでは「内容比較に使った画像」として参照できるようにし、Cの寸法と省略した構造帯が分かる説明を添える。生差分・採用クラスタ輪郭・削除色はDへ帯別に転写する。断片同士を線でつなげて塗らない。

raw overlayと元カラー画像は引き続き元の正規化A/Bだけから作る。C/Dの画像参照と混同しない。`--no-html`、保存失敗時の旧結果保持、逐次PDF描画、Matの所有・解放は既存の契約を維持する。

## 採否・互換性・実装順

候補の改善率は、全体補正後の基準生差分数と、Cで5.4まで終えた候補生差分数を比べる。既存案の式、基準0なら不採用、支持・一意性・改善率を全て満たす条件を維持する。Cの生差分は全画素を一対一でDへ戻し、転写前後の個数が変わらないことを検査する。

無効・見送り時は現行経路へ戻し、既存JSON値・画像・終了コードを維持する。今回の提案は `rows.enabled: true` かつ採用時だけの契約変更。schema_version=1の追加項目としてC/Dの対応を `row_alignment.content_canvas` に記録し、既存座標系ラベルを別の意味へ転用しない。

実装の順序：

1. CoreにC/D/元画像の写像、白余白の検査、危険な隣接の拒否を実装する。今回の174条件を固定の安全網へ移し、規定外の写像・薄い塗り・画素上限・設定全域を追加する。
2. 元のT3-1bの行推定・支持・再探索と接続し、R01〜R09を元の期待のまま検証する。近傍条件で見送ったケースを、R系の成功に数えない。
3. Cでのクラスタ・領域・分類・移動、Dへの描画、元座標、除外YAML、C画像、CLI / JSON / HTML / compare-dirを接続する。
4. SPECと設定文書を更新し、無効／有効の既存互換性、too_different、ノイズ閾値、件数上限、境界をまたぐ設定とYAML再実行、raw evidence不変性、ブラウザ、A4時間／RSS／保存量、全テスト、Windows配布物を確認する。

実装状況：工程1〜3のCore・行推定・採否・C/D投影・領域・構造計数・CLI・レポート接続を完了。工程4はSPEC・設定文書、互換性、A4時間／RSS／保存量、領域・除外・L03の実CLI確認、Windows配布物の静的検証まで完了した。ブラウザーはユーザー手動確認で概ね問題なし。一部画面サイズ・JavaScript条件の未確認をユーザー指示で保留し、T3-1cへ進む。個別項目の合格やT3-1b全体の完了にはしていない。[最新の検証と再開位置](../verification/t3-1b-acceptance.md)を参照。

受け入れ後にT3-1bを完了し、1ローカルコミットへまとめる。今回の独立試行をもって完了・リリースとはしない。

## 承認済みの判断

1. 対応する内容の比較にはCを使い、片側の内容帯を外す一方、純白余白を両側に残す。上記の近傍・置換の検査に通らなければ行整列を見送る。
2. クラスタと相違率はCで確定し、Dの断片に分かれても1件を維持する。既存bboxとfill_ratioはD、新しいcontent項目はCとして区別する。
3. 設定の基準座標は維持し、YAMLは表示断片ごとに戻す。Cの比較入力画像を追加し、単一の変位で表せない既存移動注釈は省略理由を残す。
4. A/Bの残差は方向別の既存コア基準を維持する。今回確認した基準由来の1px差を含み、画素マスクの完全対称化はこのタスクに追加しない。

[CLAUDE.md](../../CLAUDE.md)の「仕様にない判断が必要になったら、選択肢と推奨を示して確認を取る」に従い、以上を製品実装前に提示し、後続の作業続行の指示により承認された。代案の「白余白も全て詰める」は検出を失うため推奨しない。表示面でクラスタを作り直す案も、件数・ノイズ条件を変えるため推奨しない。
