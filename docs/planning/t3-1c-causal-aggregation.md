# T3-1c：単一原因の収支と構造IDの集約

2026-09-22。[承認済み方針](t3-1c-page-flow.md)に基づく独立検証。製品の比較経路・出力へは接続しない。[文書単位の範囲確定](t3-1c-document-gate.md)の成功は必要条件であり、原因の同一性の証明とは区別する。

## 今回確かめる範囲

一定間隔・一意な本文の限定入力で、文書全体に一つの連続した挿入または削除があり、そこから隣接ページへ送られる場合を扱う。複数の原因があれば、この試行では文書全体の集約を見送る。独立した原因ごとに分割する一般的な実装は含めない。

集約器は抽出した本文、検証済みリンク、実際の構造ID、ページごとの内容件数を受け取る。生成時の行ID、正解座標、ケース名は入力しない。保存したD/C写像と元ページから既存コアの`RowProjection`を実行し、`RowStructuralChange.Id`と投影クラスタを得る。内部APIを公開するための製品変更はせず、検証ツールのアダプターだけでリフレクションを使う。

ここでいう未集約件数Uは、**候補比較面から既存コアが生成した内訳**の件数である。現在のCLIが出している件数を変更した結果ではない。文書の集約器は画像を受け取らず、比較結果や構造のIDを作り直さない。

## 必要条件

1. 文書単位の範囲確定が成功し、選択範囲の欠落がない。片側ページは検証帯と固定部分以外の非白画素が残らない。片側ページの網羅性falseは保持する。
2. A/Bの本文はそれぞれ一意で、共通する行の文書全体の順序が同じ。片側にだけある行が、一ページ内の連続した一つの範囲になる。
3. その範囲と、対応する非除外の挿入／削除構造が一対一で一致する。除外で成立した構造はこの試行の対象外とする。
4. すべてのページをまたぐ共通行が、画像検証済みリンクに一度ずつ含まれる。リンクは同じ向きで物理的に隣接するページを結び、送り元末尾から送り先先頭を過不足なく覆う。帯の高さ・行数が原因の高さ・行数と一致する。
5. 各ページで `B行数 − A行数 = 原因の増減 + 流入 − 流出` が成立する。削除方向では符号を反転する。
6. ペアのあるページのリンク端点は実構造IDを参照する。片側ページの端点は補助帯参照だけを持ち、構造IDを発行しない。ブロック移動は共通本文を全行覆い、方向・移動量が原因と一致する。
7. 原因・リンク端点・対応するブロック移動以外の構造を同じグループへ含めない。未説明の構造、重複ID、欠けた移動、余分なリンクがあれば集約しない。

条件がそろったときだけ一グループを作る。既存の非除外構造参照n件に対し、集約後は `U − (n − 1)`。内容クラスタは一件も参照の置き換えや統合を行わない。無効時は集約件数・集約後網羅性をnullにする。見送り時は件数をUに保ち、理由を残す。

## 独立した照合

- R10、R11、3ページ連鎖、色／境界変更について件数を固定し、A/B交換でも同じ値を要求する。
- 送り先で第二の挿入を行う実PDFを追加する。候補と写像が成功していることを前提に、因果の段階でまとめないことを確かめる。色変更を伴う版でも内容クラスタを維持する。
- 合計の555→556も追加し、写像の失敗を従来比較へ戻す。これは数値変更と送りの同時集約が成立した正例には数えない。
- Pythonの編集列、構造参照の集合、元の内容マスクからDへの転写、各内容クラスタの所属画素数を照合する。
- 列挙順、行・リンク・実構造の欠落／重複、端点・移動量の変更、除外、網羅性falseを注入する。欠けた構造の検査では未集約件数も調整し、単なる件数不整合だけで拒否していないことを確かめる。

[検証結果](../verification/t3-1c-causal-aggregation.md)では76実行、52表示面、1,770監査条件を確認した。複数原因を分割する一般化、文字が変わった行を含む集約、製品の領域・補正・上限・保存・表示は未成立。今回の成功からそれらの受け入れを推定しない。
