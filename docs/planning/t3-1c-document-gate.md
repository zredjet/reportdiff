# T3-1c：別系統PDFと文書単位の範囲確定

2026-09-22。続行指示を受け、[前回の候補検証](../verification/t3-1c-candidate-inference.md)をSkia生成PDFへ広げ、部分的に構造写像が失敗する場合の扱いを独立ツールで確認する。製品・比較式・検出期待は変更しない。

## 入力

SkiaSharpの`SKDocument`で複数ページを描き、自作TrueTypeを埋め込む。OSフォントや代替フォントに依存せず、Type3の文字ストリームをPDFに後付けしない。字形は試験用の図形で、一般の帳票のタイポグラフィを代表するものではない。埋め込み・Unicode・語の抽出と実際の描画を確認する。

R10／R11／連鎖に加え、文字変更、同文の濃淡、対応本文・境界の変更、片側ページの余分な塗り、同名反復、最終ページだけの写像失敗、本文の先頭2行の反復、端数位置の文字を含む。元のType3入力は固定したまま再利用する。正解の行ID・座標を推定器に渡さず、後続の照合器だけで参照する。

## 文書単位の確定条件

最初の試行では、選択した文書全体で候補・対応ページの写像・送り両端の範囲がそろった場合だけ比較面を選ぶ。連鎖ごとの局所採用には広げない。

- レイアウトが確定し、画像検証済みの候補が1件以上あること。
- 未確認・曖昧・画像不一致の候補を残していないこと。
- 選択されたすべての対応ページで構造写像が作れたこと。
- すべての検証済み候補の両端が、同じ側・ページ・開始・高さの構造帯、または片側ページの検証帯として追跡できること。

一つでも欠ければ、その文書の送りリンクの選択は0件とし、成功したページを含めて**すべての対応ページを元のRowComparer結果へ戻す**。試行中に作った比較面や画像一致の証拠は診断用として残す。候補やページの列挙順で部分採用が変わらないことを確かめる。

片側ページは採否によらず`only_in_a/b`と網羅性falseを保つ。帯外の未確認内容がある場合、帯の証拠は保持してもページ全体を検証済みにしない。本文変更のクラスタが残ることは見送り理由にせず、変更を持った比較面もそのまま保持する。

この確定は帯の範囲と比較面の選択だけであり、原因の同一性・収支・構造ID・文書集約の確定ではない。`gate.ready`を製品の`carried`や「文書全体に内容変更なし」と読み替えない。失敗時の保存先復旧、製品のCLI・レポートは後続。

## 照合

旧Type3の候補・比較面が変わらないことを確認し、部分写像の4リンクを含む入力で文書全体が元の比較へ戻ることを検査する。Skia入力も両順序・選択ページで実行し、元画像・比較面・生差分マスク・固定部分・非白残差を参照実装と照合する。描画端や文字層で失敗した入力を修正して成功だけを集めず、見送り理由と未成立の範囲を残す。

## 検証結果

70実行・878参照比較を照合した。Skiaの絶対座標描画では罫線に794画素の実差があり、見送りを維持する。行内座標を共通にした別のSkia対照入力はR10／R11／連鎖の範囲が成立した。部分写像失敗時の全体見送り、列挙順210条件、根拠欠落160条件を確認済み。[結果](../verification/t3-1c-skia-document-gate.md)を参照。次は成立した入力で因果・収支・複数原因の集約を検証する。製品接続はまだ行わない。
