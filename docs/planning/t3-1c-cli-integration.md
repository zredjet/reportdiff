# T3-1c 設定・CLI・レポートへの接続

2026-09-22。[Coreの計画](t3-1c-core-pipeline.md)を実際の比較処理へ接続する。限定入力で成立した送りと単一原因の集約を明示設定から利用できるようにし、成立しない文書の既存比較とraw evidenceを維持する。[検証記録](../verification/t3-1c-cli-integration.md)を参照。

## 採用条件

`rows.carry_enabled` は既定false、trueには最終実効設定で `rows.enabled: true` が必要。各YAMLの型・数値範囲・未知キーは従来どおり検査し、共通→帳票別のスカラー継承後に依存条件を検査する。`--no-regions` はrowsを変更しない。

全体の範囲成立に加え、各対応ページで `PageFlowAdoption` を評価する。既存の行整列から画素再探索・移動区間数・支持インク・支持帯・スコア差の検査を `RowGroupValidator` へ共通化した。画素探索の式・既定値・除外条件は変えない。`RowSupport` で全内容区間の支持を再検査し、基準生差分に対するCの改善率も要求する。本文は全文一致なので単語一致率は1となる。推定した帯の移動量を再探索で変更する場合、列間の矛盾がある場合は見送る。内容の対応写像に変更がないページは改善不要だが、支持条件は確認する。

対応する全ページの採用条件を先にそろえ、一つでも不成立なら送りを文書全体で見送る。原因を集約できるかは、その後に実際の構造IDを得てから別に判定する。

## 全体補正と元画像

今回、補正前帯と補正後C/Dの座標合成は実装しない。事前描画で1ページでも全体補正が `applied` なら `global_alignment_applied` で送り全体を見送る。最終比較は既存の全体補正→行整列→比較の順を維持する。補正が有効でも移動を採用しなければ送りを評価できる。

元帯の証明には元A/Bのみを使う。ページ別設定を `PrepareForPages` で固定し、帯の検証には送り元／先両ページの実効Diff・比較領域Diffも渡す。除外と領域マスクは証明から外す。元帯が一致していても写像や採用を見送る場合があるため、リンクの `image_status` と最終 `status` を分ける。

## 実行と所有権

1. 無効なら追加収集・再描画・保存をせず従来経路へ進む。
2. 有効ならPDF・ページ数を先に検査し、選択ページを逐次描画して画像を持たない記述を収集する。文字上限・画像サイズ差などは安全側へ見送る。
3. 隣接候補を必要時だけ再描画し元帯を検証する。全対応ページのC/Dを構築し、さらに元ページを再描画して採用条件を確認する。PDFiumは逐次利用する。
4. 最終比較でも元画像のSHA256を確認する。送り採用なら既存のC/D比較・投影、見送りなら既存のRowComparerを使う。ページの画像・注釈・構造を保存後、そのページのMatを解放する。
5. 出力した実構造から原因・収支を集約する。入力ファイル全体のハッシュも再確認してからJSON・HTMLを完成させ、既存のOutputWorkspaceで出力を置換する。処理エラー時は旧結果を保護する。

文書記述・候補の上限は[接続基盤](t3-1c-integration-foundation.md)を維持する。性能は再描画、画像検証、採用比較、保存を含めて測る。記述64MiBの予算をプロセスRSSの保証として扱わない。

## 出力契約

| 出力 | 契約 |
|---|---|
| `config.rows.carry_enabled` | 実効設定をJSON／HTMLへ保存 |
| `summary.difference_count` | 内容クラスタ＋除外されていない構造の従来のページ別内訳U |
| `aggregated_difference_count` | 原因＋連鎖n件を確定したときU−(n−1)。見送り時U、無効時null |
| `aggregated_difference_count_complete` | 片側ページ・比較上限でfalse。ページ選択を指定した場合もfalse。無効時null |
| `page_flow` | 採否・理由・ページごとの採用診断・リンク・元帯・原因・実構造参照・収支。無効時は省略 |
| 元帯PNG | `pages/flow_lNNN_source.png`／`target.png`。元座標の全幅帯。補正や判定の描き込みなし |
| HTML | 集約後とページ別内訳、画像検証・採用・原因集約の状態、元帯画像と相手ページ／実構造へのリンク |
| compare-dir | 各比較の集約後とページ別内訳を一覧に併記。共通・帳票別設定を合成 |
| raw evidence | 従来の補正前A/Bから生成。送り有効／無効で同じPNGを維持 |

片側ページは未比較のまま。補助帯から構造IDや新しい相違件数を作らない。集約しても相違の終了コード1を維持する。通常の `difference_count_complete` の意味を変更せず、文書集約の網羅性は別に示す。

## 残る受け入れ

全体補正との座標合成、複数原因のグループ分割、数値変更を含む因果集約は残す。現在の安全な見送りをそれらの成立として扱わない。固定部分不足、一定行間隔以外、反復行などの対象拡張も行わない。Windows実機・A4実帳票の全工程・保留中の画面サイズ／JavaScript確認は別の証拠が必要。T3-1c全体は未完了・未コミット。


A4・多ページの合成入力は後続の[13条件の計測](../verification/t3-1c-scale-measurement.md)で確認した。疎な2／16ページの採用と、通常の24／48行の未成立を区別する。実帳票・Windowsの受け入れは引き続き残す。

[元描画とC/Dの診断](../verification/t3-1c-raster-diagnosis.md)では、固定入力の命令・フォントが同じでも原画像に差が残ることを確認した。転写と参照判定は一致し、製品の描画・採用条件は変更していない。後続の[座標合成の事前検証](../verification/t3-1c-global-composition.md)では縦補正の限定対照が成立した。[縦補正の接続案](t3-1c-global-composition.md#製品接続へ進むための案)は未実装であり、現CLIの見送り契約は維持する。
