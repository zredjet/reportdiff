# T3-1c 全体補正と送り座標の合成の事前検証

2026-09-23。[A4診断](../verification/t3-1c-raster-diagnosis.md)後の続行指示を受けた独立検証。製品の `global_alignment_applied` による送り見送りは、この工程では変更しない。

## 座標と証拠の区別

各ページに、補正前A/Bの元座標O、全体補正後の共通座標G、送りの内容比較面C、表示面Dを持たせる。元帯の証明はO、本文の対応・C/Dの構築と集約の収支はG、レポートの元画像参照はOとする。型が現在同じであることを理由に、Gの帯をOの帯として扱わない。

Bへ加える全体補正が `(gx, gy)` のとき、GのBの点 `(x,y)` はOの `(x-gx,y-gy)` に戻る。C/Dの帯のB開始を `b` とすれば、帯内の行 `r` の元位置は `b+r-gy`。全体補正は一度だけ適用する。全体補正量と、送りによる相対的な行の移動量は別に記録する。

## 固定する契約

- 元PDFのSHA256、元A/Bの画素・記述のハッシュを固定する。補正後ハッシュを元画像の検査に使わない。
- 元ページの全幅BGR帯の全画素一致と、元ページへ帯を置換する既存検証を維持する。
- 補正で隠れる非白画素、ページ外、詰め物、部分幅の帯を送りの証明に使わない。除外で隠れる場合も同様。
- 全体補正と送りの既定採用条件を維持する。既知の入力移動量を採用済み推定値の代わりに使わない。写像だけの算術対照は明確に区別する。
- 全ページで範囲・元帯・採用条件が成立するまで、送りの部分採用や件数集約を行わない。
- raw evidenceはOの画像。設定の領域・除外はA基準の共通座標からD/Cへ写し、Bの全体補正を設定へ重ねて適用しない。

## 検証する範囲

固定した既存PDFから描画と文字座標を取り、ラスタを独立した整数平行移動で変形する。これはCoreの合成写像の試験入力であり、新しく生成したPDFや実CLIの受け入れではない。元のラスタ、入力移動後、補正後、C/Dを保存して独立に照合する。

正負の縦移動、横移動、両軸移動、ページごとに異なる補正、3ページ連鎖、逆方向、本文・送り帯の変更、除外・領域、クリップを含める。元帯のOへの戻し方、文字・クラスタ・構造ID・集約件数を確認し、元座標と補正座標の取り違えを負例で検出する。

横移動ではGの全幅帯がOで部分幅になるため、現契約での成立を前提にしない。縦移動でも元帯がページ内に全て戻ることと、補正で隠れる非白画素がないことを必要とする。失敗する条件はそのまま残す。

## この工程の完了条件

成立する組合せと見送る理由を実測し、C/D・元座標対応の独立監査を通す。安全な候補があれば、製品接続に必要な型・検証・出力変更を具体化する。製品の補正経路変更、A4未成立9条件の解消、ブラウザー保留・Windows・実帳票・性能の受け入れはこの工程へ含めない。

## 検証結果

[18条件・38ページの結果](../verification/t3-1c-global-composition.md)では、移動なしの対照1条件と縦補正9条件が診断上の採用条件を満たした。25ページのC/D、元帯11組、23ページのPython参照判定を照合した。元R10の全体補正不成立、横補正されたB端点の部分幅、変更された帯、切り落とす端の内容、半画素移動は未採用として残した。

## 製品接続へ進むための案

この案は続行指示で承認され、縦方向に限定して製品CLIへ接続した。[実装と実PDFによる検証結果](../verification/t3-1c-global-cli.md)を参照。前半のラスタ事前検証と、後続の製品接続の証拠は区別する。

### 対象を縦方向に限定する

既存の `align.enabled` と `rows.carry_enabled` の両方を有効にした場合だけ対象にする。採用された全体補正が全ページで `dx=0`、同じ大きさの対応ページがそろい、元帯・写像・行の採用条件をすべて証明できる文書を扱う。正負のdy、ページ別dy、補正量0との混在、逆方向を含める。新しいしきい値や設定は追加しない。

横補正を一つでも採用した文書、全体補正を採用し片側ページを含む文書、元帯を完全に戻せない文書は送りを文書全体で見送る。横補正がどのページにもあれば数学的に不可能という主張ではなく、次工程で受け入れる範囲を限定する。全体補正量が0の既存送り・片側ページの経路は変えない。

### Coreの元画像検査と比較面を分ける

元ページの識別子・寸法・BGR SHA256はOの原画像から作り、Gの行記述とは別の型で保持する。帯検証はこのOの識別情報と元帯だけを受け付ける。O/Gの区別を呼出し側の暗黙の約束にしない。Oの行ハッシュ・本文まで重複保持する事前検証用の実装を、そのまま製品へ移さない。

送りの候補・固定部分・行写像はGから作り、候補の各端点をOへ完全に戻せた場合に既存の全幅・全画素一致検証を実行する。Oでの検証結果とGの端点を同じリンクIDで対応付ける。証明失敗時は全体見送り。帯の近傍を削る、除外を証明に使う、補正後画像を元画像と呼ぶ変更はしない。

`PageFlowComparison` の内容比較・改善率・行移動量・因果集約はGで完結させる。表示用の構造／クラスタの元範囲は既存の `PageMap` を使ってOへ戻すが、その範囲を論理集約へ逆流させない。実構造IDは共通にし、集約が参照したIDと利用者向け構造を照合できるようにする。

### CLIと出力へ接続する

`PageFlowRun` でページ別の採用済み全体補正とOの識別情報を固定する。事前検証と最終比較で別の補正を黙って採用せず、再読込変更は処理エラーとして旧出力を保護する。見送り時の全体補正→従来行比較の経路を維持する。

送り元／先の座標・PNG、構造とクラスタの元範囲はO。全体補正量は既存のalignment情報、行の相対移動量はrow_alignment情報で区別する。文字注釈はO→G→Dを一度ずつ適用し、除外／領域はA基準からD/Cへ写す。raw A/B・raw overlayはOから従来どおり生成する。HTML／compare-dirでも既存のページ別内訳と集約後件数を維持する。

### 接続時に確認すること

- 既定設定のまま全体補正と送りが成立するPDF入力、正負・ページ別dy・逆方向・3ページ連鎖、内容変更、除外・領域、部分失敗を実CLIで確認する。今回の合成ラスタだけでこの条件を合格にしない。
- 無効時、横補正・片側ページ等の見送り時のページ結果、元画像／raw overlayが従来結果と一致することを照合する。
- O/Gの取り違え、二重補正、端点のクリップ、元画像と入力ファイルの変更、保存失敗で部分採用や旧出力の破損を残さない。
- 既存の64MiB記述予算などの上限を緩めず、追加の元画像識別情報も保持量へ計上する。PDFiumの逐次処理とページ単位のMat解放を維持し、全体補正を含む追加時間・RSS・描画回数を実測する。
- 製品変更後は関連回帰と全テストを実行し、設定・SPEC・レポート説明・TASKSを更新する。A4未成立9条件、Windows・実帳票・ブラウザー保留、複数原因・数値変更の残件は別に維持する。

## 接続後の残件

縦方向の接続は実装・検証済み。横補正と補正ありの片側ページ、複数原因・数値変更を含む集約は未対応。A4未成立9条件、Windows・実帳票・大規模性能の受け入れ、利用者が保留したブラウザー確認も残す。次の検討候補は複数原因を混同しない因果集約の設計と独立検証であり、既存の単一原因の期待や元帯の全画素一致を弱めない。T3-1c全体の完了・コミットはまだ行わない。

後続の[複数原因の設計・独立検証](t3-1c-multiple-causes.md)を完了した。ページ群が交わらない原因の分離には、同一ページ対応済みの非送り候補の証明も必要となる。具体的な製品接続案と未検証範囲は同文書を参照。
