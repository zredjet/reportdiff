# 末尾原因の跨ページ支持を独立検証する

2026-09-23。前工程の[支持境界](../verification/t3-1c-same-page-support.md)を受けた設計・実験。製品の条件や既存期待は変更せず、診断だけで新しい証拠契約を試す。

## 仮説と範囲

元の `same-page-two` では第2挿入がBの第1ページの末尾にある。Aの末尾2行はBの第2ページ先頭へ移り、その後ろの元本文はA/Bとも第2ページにあり、200pxの差が4行で支持される。この4行は送り端点の外側である。送り帯の画素一致を支持数へ加算せず、次ページに実在する同一ページ移動の支持を独立に調べる。

診断の対象を全2ページ対応・補正なし・一定行間隔・一意な全文・共通順序一致・同符号の一行挿入2箇所に限定する。逆方向の削除は対称に扱う。二つの原因は第1ページにあり、間に少なくとも2共通行、最初の原因の前にも少なくとも2共通行を要求する。最後の原因は本文の末尾に一行だけ存在し、その後に同一ページの対応行がある場合はこの契約を適用しない。

必要な証拠を次のように分ける。

1. 原因を除いた全文の順序が一致すること。行間・左右位置・ページ所属を含め、部分一致や数値対応IDは使わない。
2. 境界を跨ぐ全行が元ページ末尾と次ページ先頭を隙間なく埋めること。長さは二原因の合計に一致し、既存最大変位内であること。
3. 次ページの送り帯外にある全共通行が、同じ物理ページで同じ長さだけ移動していること。最低支持数を満たし、送り行と重複しないこと。
4. 送り帯を既存の全画素一致・元ページへの置換比較で検証すること。
5. 末尾原因の全幅・全高を実構造として残すこと。先行共通行・跨ぐ行・次ページの支持を同じ編集順序へ結び付ける。片側の非対応帯全体が原因一行と一致しなければ分割しない。
6. この原因帯だけを例外として診断用C/Dを構築し、全ページについて既存の支持帯数・インク・再探索・次点差・改善率を変更せず評価すること。次ページの評価失敗でも全候補を破棄すること。
7. 実構造ID・移動量・送り・ページ収支を既存集約器と独立モデルで確認すること。内容クラスタを減らさないこと。

支持1行の対照に「次ページの行を足して2行にする」処理はない。本文末尾に対応行が残る入力は既存の局所支持契約で評価する。今回の例外は支持数による特例でなく、末尾原因と跨ぐ全行を結ぶ別の証拠契約である。

## 事前の期待と反例

固定30方向を再読込する。元の支持0の2方向だけは診断上の新規集約を見込み、製品CLIの10→10は維持する。既存の成立12方向と負例16方向の採否を変えない。元のPDFを修正・再生成しない。

元の支持0入力から、メモリ上の画像・テキストに限定した反例を両方向に追加する。内容色変更は差分を保持して成立を見込む。送り帯の色変更、次ページ支持全体の薄色化、有効インクが一行だけ、次ページ支持の平坦化による次点差不足は見送りを要求する。ページ選択、移動上限不足、欠落・重複・順序・位置・候補・原因参照の破損も拒否する。これらを実PDFの追加受け入れや実帳票の証拠とは扱わない。

Pythonで共通行の編集列から原因と移動を独立に計算し、C/D転写と生差分マスク、原因と実構造ID、支持画素の量・次点差を照合する。プローブは元の候補と代替候補、末尾原因、外部支持、範囲成立、各ページの採否、集約を別々に保存する。製品ソース104ファイルと元PDFのハッシュを維持し、既存CLIの26方向を再生する。

製品への接続は本工程に含めない。成立した場合でも文書・配置・候補ID・設定への証拠の結び付け、確保前の資源予約、除外／領域／補正、出力形式との接続を別途設計する。既存の検出必須の負例を新規採用するなら契約を採用せず、期待を変更しない。

## 検証結果と次の設計境界

[独立検証](../verification/t3-1c-cross-page-support.md)では、元の2方向について次ページの4行が200pxを支持し、送り帯の全画素一致・置換比較も成立した。しかし、第1ページのC/D作成が `unanchored_join` で失敗した。末尾の送り帯と原因帯をそれぞれA/Bから除くと、隣接する対応帯の間で両側から非白帯を削る構成になるためである。支持不足の解決だけでは集約に到達せず、本案は製品接続可能とはしない。

固定30方向は以前の結果を維持する。メモリ上の14方向を含む計44方向では、成立12、負例拒否28、元ケースと内容色変更の未成立正例4となった。元ケースの正例期待は維持し、内容色変更の追加正例も見送り期待へ書き換えない。薄色・一行だけの有効インク・平坦支持は独立した支持評価で拒否できたが、これらの全文書処理は共通面作成で止まり、採用評価まで到達した証拠にはならない。

次の候補は、二つの非白帯を除いた後も安全な内容比較を行える構成の設計・反例検証である。選択肢は次のとおり。

- 現行Cの連続性契約を守った別構成を探索する。元ページ・送り先・原因帯の所属を保ち、支持数の増量や白余白の追加・削除で継ぎ目を作らない。まずはこちらを検討する。
- 両側切断に外部の送り証明を使う新しい共通面契約を作る。この場合は文字一致や全帯一致だけでは足りず、継ぎ目近くの色・形状差、罫線、薄い印、二段目のグループ結合、周期性、領域条件について元の検出期待を保つ独立証拠が必要となる。条件が揃うまで製品へ接続しない。

`unanchored_join` の単純な解除、比較窓の縮小、帯境界でのグループ分割、元ケースを除いた合格宣言は採用しない。既存の片側削除・連続近傍の検査を使う範囲で成立するかを先に調べ、必要になった仕様変更は具体的な証拠とともに判断する。
