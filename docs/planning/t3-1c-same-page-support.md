# 同一ページ二原因の支持境界を切り分ける

2026-09-23。曖昧候補の製品接続後の続行指示に基づく、製品未変更の配置対照と安全網の検証。

元の `same-page-two` は一ページ6行、挿入位置は元本文の2行後・4行後。第2挿入後の同一ページ支持が0で、200pxの移動支持も0である。元PDFと「二原因として扱いたい」という未成立の期待を保ち、支持を満たす別入力で合格へ置き換えない。

最初の挿入までの支持・二挿入の間の支持・第二挿入後の支持を別々に調べる。行間100pxと二つの一行挿入を固定し、容量6・7・8・9・10行を比較する。第二挿入後の同一ページ支持はそれぞれ0・1・2・3・4行になる。容量だけに依存した結果でないことを確認するため、挿入位置を後ろへ移した対照と、前方／中間の支持が一行しかない負例も加える。

15ケース30方向を事前に固定する。十分な支持を持つ容量8・9・10、後ろへ移した2対照、内容色変更は集約を見込み、容量7・後方支持1・前方支持1・中間支持1・送り帯色変更・反復・順序変更・薄い支持行は見送りを要求する。元の容量6の2方向だけは従来の未成立正例として数える。色変更の内容クラスタは集約後も残す。

既存の候補推定、帯の全画素一致と置換比較、C/D構築、支持・画素再探索・曖昧さ・改善率、共有原因集約をそのまま実行する。文字数とインク支持、範囲成立と採用を区別する。範囲だけ成立して採用に失敗したC/Dの診断結果を、製品出力の合格とは扱わない。

Pythonで本文と同一ページ変位・両側支持を再計算し、元画像からC/Dと生差分マスクを照合する。原因・実構造ID・移動寄与・ページ収支、元A/Bとraw overlay、旧CLI出力の不変性を確認する。製品104ファイルと元固定PDFのSHA256を確認し、しきい値・設定・出力契約は変更しない。

元の支持0ケースの救済は本検証に含めない。隣接ページの行を局所支持として使う場合は、現在の同一ページ条件・端の構造条件を変更する別設計が必要になる。変更案を出す場合は、検出期待を保つための証拠・負例・対象外を明記してから接続を判断する。
