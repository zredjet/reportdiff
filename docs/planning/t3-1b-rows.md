ページ内の行整列を対象とする。ページをまたぐ送り、画像だけからの行推定、固定枠と文字の別々の移動、網掛けの集約はそれぞれ後続タスクに残す。T2-8 の D16 / D17 / J07 / J08 の保留も維持する。

## 確定したい判断と推奨

| 判断 | 推奨する契約 | 別案との違い |
|---|---|---|
| ブロック移動 | 行の挿入・削除と別に、相違として数える | 数えない案では、残存内容の移動を箇所数で確認できない |
| 件数 | `clusters` を維持し、`structural_change_count` と `difference_count` を追加する | クラスタ数の転用はしない。以下の式を単一比較・HTML・ディレクトリ一覧で共用する |
| 有効化 | 独立した `rows`。既定無効。全体補正 → 行整列 → 既存比較 | `align` に含めると全体移動の許容と行構造の報告を別々に指定しにくい |
| CLI | 総箇所数に、構造変化の種類別件数を添える。構造変化 0 件では従来の書式 | 常に長い内訳を出す案より、既存の出力を維持できる |
| 設定の座標 | `exclude` / `regions` は行整列前の A 側を基準とし、PageMap で整列後へ写す | 最終キャンバスに直接固定する案では、行の追加で設定対象がずれる |
| HTML の除外 YAML | 比較キャンバスから設定用の A 側座標へ逆写像して出す | 表示座標をそのまま貼ると再実行時に同じ場所を除外できない |

最後の 2 項目は、既存の T3-4a / T3-4b を行整列後にも使うための具体化。無効・見送り時の座標、全体補正の既存契約は維持する。数値の設定案と、採用・見送りの条件も以下に含めて確認する。

## 設定案

```yaml
rows:
  enabled: false
  max_shift_mm: 20.0
  min_word_match: 0.60
  refine_mm: 0.3
  min_improvement: 0.05
  min_score_gap: 0.02
  min_support_bands: 2
  min_support_ink_mm2: 1.0
  max_segments: 8
```

| キー | 型・範囲 | 意味 |
|---|---|---|
| `enabled` | bool | PDF テキスト層による行整列を有効にする |
| `max_shift_mm` | 有限数、0 より大きく 100 以下 | 全体補正後からの追加の縦ずれの絶対値上限。累積したずれにも適用 |
| `min_word_match` | 有限数、0 より大きく 1 以下 | 行の単語列の一致率下限 |
| `refine_mm` | 有限数、0〜2 | テキストの基準位置の周囲で画像を再探索する半径 |
| `min_improvement` | 有限数、0 より大きく 1 以下 | 基準の生差分に対する減少率の下限 |
| `min_score_gap` | 有限数、0 より大きく 1 以下 | 異なる量の整列仮説との画像一致度の差の下限 |
| `min_support_bands` | 整数、2〜100 | 各内容区間を支持する、独立した対応済み帯の最小数 |
| `min_support_ink_mm2` | 有限数、0 より大きく 1000 以下 | 各区間の支持帯に必要なインク面積。A/B それぞれで満たす |
| `max_segments` | 整数、1〜64 | 内容のある、同じ追加 dy の区間の最大数。詰め物・白い余白は含めない |

値は実装前の提案であり、検出性能の実測値ではない。R 系を通すために検出期待や採用条件を黙って緩めない。

mm / mm² の換算は Units に集約する。`max_shift_mm` と `refine_mm` は既存の整数 px 丸めを使い、後者が 0px なら中心候補だけを調べる。候補の追加 dy は再探索後も上限内とする。型、未知キー、非有限値、範囲、最終 DPI での変換限界をキー名付きで検証する。

共通 YAML → 帳票別 YAML の順に、指定したスカラーだけを上書きする。profile は rows を変更しない。今回、rows 専用の CLI フラグは増やさない。`config.rows` に全実効値を出し、CONFIGURATION と設定例を同期する。`--no-regions` は従来どおり除外・領域設定を無効にするだけで、rows の指定は維持する。

## 行の手がかりと安全な帯

1. 既存の逐次 PDF 描画と全体補正を行う。追加整列前の A と補正後 B が完全一致なら、行の抽出・推定を省く。既存のフォント検査は維持する。
2. Pdf 層で単語本文、元ページの矩形、文字のベースラインを抽出する。現在使用中の PdfPig `Letter.StartBaseLine` / `EndBaseLine` を使い、外接矩形の下端をベースラインの代用にしない。Core には PDF の型を渡さない。
3. テキストの制御文字除去・空白整理は T2-3 と同じ。NFKC、大小文字の同一視、数字の削除、OCR は追加しない。行まとめも `text.min_line_overlap` と先頭語を基準にした規則を共用する。単語は左から並べ、同一位置では既存の決定順を使う。水平でない文字や座標が確定できないページは推定に使わない。
4. 行の基準 y は所属する水平文字のベースラインの中央値とする。B の座標には全体補正を適用してから A と対応付ける。単語一致率は `2 × 単語列 LCS の一致語数 / (A の語数 + B の語数)` とする。空行は支持にしない。
5. 一致率を満たす行の対応を LCS で求め、同じ追加 dy で説明できる並びを区間にする。連番列だけが違う行でも、他の語が十分一致すれば候補になる。数値の差分は後段の画像比較に残る。
6. 帯の境界は、文字・図形・横罫線を切らない画素行に限る。縦罫線だけが横切る場合は許可するが、文字の縦画を罫線として除去しない。PDF の文字矩形と画素の両方で確認する。文字内容と直下の横罫線を同じ帯に含め、安全な境界がなければ隣と結合する。

文字・単語の取得上限は既存の `text` 設定を使う。整列の組合せ数にも上限を置く案とする：片側 2,000 行、行の DP 400 万セル、単語一致計算の DP はページ合計 800 万セル、同値をまとめた具体的な仮説は 64 個まで。超過時に候補を恣意的に間引いて「一意」と判定せず、`resource_limit` で従来比較へ戻す。計数は割当・計算前に確認する。この上限は PDF パーサーを含むプロセス全体の時間・RSS の保証ではない。

## 仮説の制約・検証

対応する帯は元画像の順序を保つ。画像の伸縮、重複転写、内容のある画素の切り捨てを禁止する。A/B の片側にしかない帯は、相手側に同じ高さの白い詰め物を置く。挿入位置の前後の支持区間と帯の過不足で、追加 dy の変化を説明できる必要がある。

**不一致の行を、そのまま削除＋挿入として比較対象から外さない。** 同じ区間で位置・帯数が対応する未一致行は、内容変更のある対応帯として通常の画像比較へ渡す。構造変化は支持されたずれの変化と整合する、帯の過不足に限定する。対応の根拠が足りなければページ全体の行整列を見送る。R02 の合計変更、同じ位置で全語が変わる行、同じ高さの行の置換を安全網にする。

画像の再探索は整数 dy だけ。横は全体補正の dx を共用する。各区間で複数の帯と A/B それぞれの十分なインクが支持し、別の列に矛盾する支持がないことを要求する。固定区間も内容があれば支持を確認し、余白だけの区間は支持数に含めない。文字がない横位置の図形・罫線も最後の全ページ比較から外さない。

再探索と次点との比較は、T2-4 と同じ暗さの一致度 `1 - sum(abs(A_dark - B_dark)) / sum(A_dark + B_dark)` を用いる案とする。評価する元の支持帯と有効画素は候補間で共通に固定し、除外の周囲は探索半径ぶん避ける。白背景、詰め物、挿入・削除候補の帯は支持点にしない。分母 0 は支持不足。候補ごとに都合のよい一部だけを評価することは認めない。

異なる挿入量・区間の dy を持つ競合仮説との画像一致度の差に `min_score_gap` を使う。R06 の同一行の連続では、詰め物の位置を動かしただけでも保存画像の画素位置は変わるため、そのままの画像ハッシュだけでは同値性を判定しない。

繰り返し帯の高さと全画素（罫線・塗りを含む）が同一で、構造変化の種類と量も同じ場合に限り、その連続範囲の先頭を代表の挿入／削除位置にする。代表位置へそろえた写像で、整列後の A/B 画像・画素比較対象も同一なら同値とする。文字列だけの一致ではまとめない。代表位置と同値な元位置の範囲を記録し、行の追加量・ブロックの移動量を一意性の対象にする。列ごとの異なるずれは同値にしない。

仮説の探索順だけで A/B の対称性が壊れない決定規則を使う。順位を確定できるまで競合候補を検証できなければ、採用せず理由を残す。再探索の一致度は仮説選択用であり、5 章の差分判定の代用にはしない。

画像一致度・支持・切断条件を満たした最良仮説について、次を実行する。

- **基準実行**：全体補正後・行整列前の A/B を既存の 5.2〜5.4 で比較した生差分。領域ごとの合成とユーザー除外を含む。
- **候補実行**：承認済みの[補足仕様](t3-1b-common-surface.md)に従い、構造帯を外し純白余白を残した内容比較面Cを同じ5.2〜5.4で比較する。写像した領域とユーザー除外を適用する。表示の詰め物を含む画像で比較して後から構造帯の生差分を消す経路は使わない。
- 改善率は `(基準の生差分画素数 - 候補の生差分画素数) / 基準の生差分画素数`。基準が 0 なら採用せず、`low_improvement` とする。詰め物で増えたキャンバス面積を分母に使わない。
- `min_improvement` を満たせば採用。満たさなければ、基準実行の出力を返す。採用した方の生差分を再利用して、既存の 5.5 と分類・移動注釈を実行する。

構造帯を比較から外した効果も改善率に含むため、この数値だけでは採用しない。独立した支持と帯の過不足の制約を必須とし、除外した画素数・帯・本文を別途報告する。候補を成立させるために生差分の式・クラスタ化・二段目の吸収条件を変更しない。

通常は基準と最良仮説の 2 回分の生差分生成で済ませる。regions に複数の実効 diff がある場合は、各実行内で従来どおり設定ごとの全ページ計算が必要。「2 回」は候補選択やテキスト抽出を含む全処理の回数・時間保証ではない。

## 固定フッターと余白

R05 では明細の下だけが移動し、フッターは元の y に残る。明細の追加量をページ末尾まで一律に適用しない。短くなった明細下の白い余白を対応付け、必要な詰め物を両側に配置して固定フッターを合わせる。

片側だけになる余白が純白なら、`white_space` の帯として写像と詰め物量を記録し、行の挿入・削除件数には含めない。インク判定だけで「純白」としない。薄い塗り・印・線がある余白は内容であり、捨てたり白い余白と呼んだりしない。ページ端も同様。できなければ行整列を見送る。

R01〜R07 の合成 PDF は、明細の前後・移動区間・固定フッターについて、仕様どおり複数の支持帯を用意する。支持条件を外して単独の図形や 1 行だけを整列させるテストにしない。

## 座標・領域・除外 YAML

設定の基準は行整列前の A 側（全体補正後の共通キャンバス）とする。PageMap の A→比較キャンバスで矩形の上端・下端を写す。中に挿入された帯をまたぐ領域は、その詰め物の高さぶん伸びる。B に全体補正を二重適用しない。

領域の優先順位は元の宣言の内包関係を保ち、mm と px の入力検証も維持する。写像後の矩形だけを比べ直して優先順位を逆転させない。出力に設定の元矩形と、実際に使ったキャンバス矩形を両方残す。画素の所有・生差分の合成・分類・移動検証・黄色の除外表示・青い領域枠で同じ写像を使う。

設定が除外した範囲は、候補生成・支持からも外す。構造変化の内容がすべてユーザー除外に含まれる場合は、構造変化リストに `excluded: true` と理由を残し、相違件数に加えない。一部だけ除外された構造変化は 1 件として残す。単なるブロック移動も、元／先の評価対象の内容がすべて除外される場合だけ除外扱いにする。

行整列後の通常クラスタの `bbox_px` / `bbox_mm`、切り出し、判定画像は比較キャンバス座標。追加の `source_a` / `source_b` に元画像の座標系、外接矩形と帯別の矩形列を出す。片側に実体がなければ null。帯別の矩形列で、外接矩形が詰め物や別区間まで覆う場合も区別できるようにする。PageMap の既存の外接矩形 API は維持し、矩形を分ける必要がある呼び出し用に帯別写像を追加する。

PDF 注釈は元 A/B の単語をそれぞれ同じ PageMap で写す。挿入・削除の本文は通常クラスタが 0 件でも抽出する。本文の文字数上限と省略の警告は T2-3 に合わせる。注釈の除外は従来どおり丸めない連続座標を使う。

T3-4a の YAML は、余白を加えたクラスタ範囲を A 側の設定座標へ逆写像し、0.5mm 刻みの外向き丸め・元キャンバスへのクリップを行う。必要なら複数行を返す。JSON/HTML で見る bbox とは座標系を区別して表示する。採用時だけこの経路を使い、無効・見送り時の既存の YAML は維持する。構造変化の全幅帯を自動的に除外する YAML は今回追加しない。

具体例：A の y=60mm に高さ 8mm の B の行が入れば、A の y=100mm の欄は比較キャンバスの y=108mm へ写る。この欄を除外する YAML は y=100mm 側へ戻して出す。実装時は挿入・削除・全体補正との併用で、実 CLI に貼り付けて再比較する。再実行で支持が不足して整列が見送られた場合も、その理由を表示する。

## JSON・件数・表示

`schema_version=1` の追加項目とする。既存項目を別の意味に転用しない。

| 位置 | 内容 |
|---|---|
| `config.rows` | 全実効設定 |
| `pages[].row_alignment` | `status` / `reason` / `detail` / `source`、`segments`、`structural_changes`、基準と候補の生差分数・改善率・一致度・次点との差・支持数 |
| `row_alignment.segments[]` | PageMap のキャンバス開始 y・長さ・元 A/B 開始 y・追加 dy。詰め物と白い余白を区別 |
| `row_alignment.structural_changes[]` | 独立した ID、`inserted` / `deleted` / `block_moved`、キャンバス矩形、元 A/B 座標、本文、帯数、移動量、除外状態、同値な位置の範囲 |
| `row_alignment` の比較省略情報 | 片側帯の面積・その中の候補生差分画素数。ユーザー除外・regions の抑制とは別にし、重複加算しない |
| ページ・`summary` | `structural_change_count`、`difference_count`。構造変化の種類別内訳も出す |
| 通常クラスタ | `source_a` / `source_b` を追加。既存 bbox・ID・kind・related_cluster_ids は維持 |

PageMap の合成 dy は元 B→元 A の方向を維持する。行の `additional_dy_px` はそこから全体補正の dy を引いた値。構造変化の `displacement_px` は全体補正後の A→B の移動量とし、HTML に方向を明記する。全体補正による移動をブロック移動として数え直さない。

構造変化の連続する片側帯は、同じ挿入／削除操作として 1 件にまとめ、帯数を内訳にする。ブロック移動は、同じ非ゼロの追加 dy を持つ連続した対応区間ごとに 1 件。元／先を 2 件にはしない。同値な繰り返し位置の数も相違件数にしない。ID は通常クラスタの ID と別の名前空間にする。

```
structural_change_count = 除外されていない構造変化の件数
difference_count = clusters の実件数 + structural_change_count
```

summary はページ別値を合計する。R01 はクラスタ 0・構造変化 2・総箇所数 2、R02 は 1・2・3。構造変化だけでもページを `different`、文書を `different`、終了コードを 1 にする。`too_different`、クラスタ数の上限適用、片側だけのページでは「総箇所数で網羅できない」という現在の状態を維持し、0 箇所から相違なしを推論しない。比較後の `absorbed_groups` / `max_shift_px` は採用した実行の値とし、基準実行と足し合わせない。

CLI の例：

```
相違あり: 1 ページ中 1 ページ、3 箇所（行の挿入 1、ブロック移動 1 を含む） → out/report.html
```

構造変化が 0 件なら従来の 1 行書式を維持する。compare-dir のファイル状態・ファイル件数は変えず、各 `files[].comparison` に同じ追加件数を出す。一覧の箇所数は `difference_count` とその内訳を使う。文書をまたいだ原因の集約は行わない。

HTML は「内容の差分」と「行の構造変化」を別の一覧にし、ページと文書の総箇所数には同じ計数関数を使う。判定画像に構造変化の枠・番号と詰め物の範囲を示す。A/B の画像自体は転写と白埋めだけとし、一覧から各帯を確認できるようにする。JavaScript なしでも画像リンク・本文・件数を読めるようにする。

## 見送りと警告

`status` は `disabled` / `skipped` / `applied`。`source` は PDF 同士なら `pdf_text`、該当しなければ null。未計算の値は null とし、0 と区別する。

タスク案の理由に、未比較・高速パス・取得失敗・探索上限を区別する理由を追加する案とする。

| reason | 条件 |
|---|---|
| `disabled` | rows 無効 |
| `not_compared` | 片側だけのページ |
| `identical` | 全体補正後の画像が完全一致 |
| `no_text` | 画像入力、PDF/画像混在、または片側の文字層なし |
| `text_unavailable` | 解析失敗、取得上限、回転・UserUnit・非水平文字・座標対応を確認できない |
| `size_mismatch` | 元のページの描画寸法が違う |
| `no_bands` | 内容を切らずに帯を作れない |
| `insufficient_support` | 支持帯数、インク量、過不足の説明が不足 |
| `ambiguous` | 異なる量の仮説との差が不足 |
| `low_improvement` | 基準生差分 0、または改善不足 |
| `column_conflict` | 異なる列が矛盾するずれを支持する |
| `too_many_segments` | 内容区間数が設定上限を超える |
| `resource_limit` | DP・仮説数・画像寸法の計算限界。内容を削って続行しない |
| `applied` | 採用 |

無効、未比較、完全一致を先に処理し、その後は対象条件・文字取得 → 帯と列の整合 → 支持・候補の一意性 → 生差分の改善の順で理由を決める。複数の詳細があれば detail に残す。

見送りでも、有効なテキストから複数の帯に共通する非ゼロの追加 dy を確認できた場合は `ROW_SHIFT_SUSPECTED`。文字を読めないこと自体は行ずれの証拠としない。採用時はページ番号と量を含む `ROW_ALIGNMENT_APPLIED`。無効時に警告のためだけの行推定は行わない。

## raw evidence と出力の分離

確認用オーバーレイは元の正規化 A/B から生成し、全体補正・行整列・除外・構造変化を入力にしない。元カラー A/B の確認用切り替えも同じ画像を使う。

現在の ReportWriter は「判定用 A が正規化 A と同じ寸法」という前提を持つため、元の正規化画像と判定用の整列画像を別々に受け取る形へ改める。`images.a` / `images.b` は比較キャンバスとし、raw evidence の参照を無条件でこれらに共有しない。既存の `_raw_a.png` / `_raw_b.png` を必要に応じて使い、画素が同じ場合だけ既存画像を共有する。`images.b_original` の既存の意味も維持する。

構造変化だけでも判定画像を保存する。確認用画像は従来どおり明示的に有効化した場合に保存し、`--no-html` でも PNG と JSON を出す。Mat はページ単位で生成・保存・破棄し、PDFium は逐次、既存の保存失敗時の旧結果保持も維持する。

## 実装と受け入れの順序

1. 承認後、合成 PDF と独立した試行で、ベースライン、帯の切断、LCS、再探索を確認する。R01 / R02 / R05 / R06 / R09 を先に使い、変更保持・固定フッター・同値性・列の矛盾を確認する。採用条件や 5 章を変えないと成立しない場合はここで報告する。
2. Core のデータ型・設定・行の推定と PageMap の合成を実装する。生差分の式は維持し、採否で基準と候補のどちらを返すかを制御する。
3. Pdf の取得・注釈、領域と除外の写像、YAML の逆写像、JSON / HTML / CLI / compare-dir を接続する。
4. SPEC・CONFIGURATION・設定例・既知の限界と検証記録を更新する。全検証後に T3-1b の完了を記録し、1 ローカルコミットにまとめる。

必須の確認：

- R01〜R09 を元の期待のまま確認する。合成フォントは T2-3 の埋め込み Type3 方式を使う。R02 の数値変更、R07 の連番の変更を通常クラスタとして残す。L03 は結果の記録だけとする。
- 行の置換、挿入と同時の小数点・マイナス・塗り・罫線の変更、同じ文字列でも画素の異なる繰り返し、短い支持、切れない帯、ページ端、薄い色の余白、設定／探索上限、文字の省略と解析失敗を確認する。
- A/B 交換で挿入と削除、追加 dy と移動量が反転し、件数と残存クラスタが対応する。設定に A 固有の座標がある場合は、同じ物理対象へ写した設定でも確認する。同じ数値の YAML が別の A 上でも同じ対象を指すとはみなさない。

- 全体補正と行整列の併用、挿入／削除の前後・境界をまたぐ領域、内包と除外優先、PDF 注釈、HTML の除外 YAML を貼り付けた実 CLI 再比較を確認する。ユーザー除外で消した構造変化の記録も確認する。

- Chrome の file://・1280 / 390px・キーボード・JavaScript 有効／無効で構造変化一覧、詰め物、A/B、確認用オーバーレイ、YAML を確認する。外部通信・スクリプトエラーを確認する。

## 承認の境界

[TASKS の共通条件](../TASKS.md) は「着手時に `docs/planning/` に仕様案を作り、各タスクの『着手前に確認する判断』の承認を得てから実装する」と定めている。[CLAUDE.md の進め方](../../CLAUDE.md) も「仕様にない判断が必要になったら、選択肢と推奨を示して確認を取る。黙って仕様を広げない」としている。

今回は次タスクへの着手依頼を受けて、上記の件数・設定・座標と採用条件を具体化した。仕様案の提示後に「次に進んでください」と指示されたため、承認済みとして事前検証・実装へ進む。既存の v0.1.3 のコミット・push・公開は完了しており、このタスクで再リリースは行わない。
