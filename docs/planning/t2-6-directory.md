状態：2026-09-21、ユーザーが推奨案を承認。開始点は `5ae2923`（T2-5）。この仕様で実装・検証を完了し、T2-6 のローカルコミットで停止する。T2-7 と push は行わない。確定仕様は [SPEC 11.6](../SPEC.md#116-フォルダ一括比較t2-6)、確認結果は [検証記録](../verification/t2-6-directory.md)を参照。

## コマンドと対象

```powershell
.\reportdiff.exe compare-dir old new --out batch-result `
  --config common.yaml --rules rules.yaml
```

`compare-dir <dirA> <dirB>` を追加し、既存の `compare` は互換性を維持する。`--out` は必須。任意の `--config`、`--profile`、`--dpi`、`--pages`、`--save-all-pages`、`--no-html`、`--force`、`--quiet` は単一比較と同じ意味で全ファイルに適用する。`--rules` は compare-dir 専用で、compare に指定した場合は引数エラーとする。

- 入力のサブフォルダを再帰的に探索する。隠しファイル・隠しフォルダも含め、読み込めないディレクトリを黙って省略しない。ファイルを逐次比較し、PDFium の同時描画は増やさない。
- 対象拡張子は `.pdf` / `.png` / `.jpg` / `.jpeg` / `.bmp` / `.tif` / `.tiff`（大小文字を区別しない）。それ以外と拡張子なしは比較せず、入力 A/B・相対パス・理由を対象外一覧へ記録する。空のフォルダは比較項目にしない。
- 拡張子は列挙時の候補選択だけに使う。比較するファイルの実形式は従来どおり先頭バイトで判断する。たとえば `.png` という名前の PDF は PDF として処理する。対象拡張子なのに未対応・破損・読み込めない場合は、そのファイル対のエラーになる。
- 対象ファイルの追加・削除・書き換えがない入力フォルダで実行する。列挙後に消失した比較対象は個別エラーとするが、実行中のファイル更新を一貫したスナップショットとして扱う機能は追加しない。

## 相対パスの対応付け

Windows の主用途と macOS の日本語ファイル名を考慮し、相対パスを `/` 区切り・Unicode NFC に正規化し、`OrdinalIgnoreCase` で対応させる。`請求/Invoice.PDF` と `請求/invoice.pdf`、合成文字と結合文字の日本語名を同じ対応先とする。元の A/B のパス表記は一覧にそれぞれ残す。

- 同じ側に、正規化後のキーが重なるファイルやディレクトリが複数あれば、曖昧なので全体を開始前エラーにする。異なる側で同じキーがファイルとディレクトリになっている場合も開始前エラーにする。対象拡張子だけでなく探索した名前全体の衝突を確認する。
- 名前変更や拡張子違いの推測対応は行わない。`a.pdf` と `a.png` は別項目になる。
- 片側だけにある対象ファイルは `only_in_a` / `only_in_b` として一覧に記録し、相違扱いにする。**存在の比較だけで、内容の検査・描画・個別レポート生成・帳票別設定の適用はしない**。未検査であることを表示する。
- 対応キーの順序を固定し、OS の列挙順に依存しない ID `f000001`、`f000002`…を全対象項目に割り当てる。出力パスには入力のファイル名を直接使わない。
- A/B が同じ入力フォルダでもよい。片方が他方の配下になる指定は、入力範囲が混ざるため拒否する。

## パスと既存出力の保護

- 入力ルートそのものと配下のシンボリックリンク・ジャンクション・その他の再解析ポイントは追跡しない。発見した場合は開始前エラーにする。対象外拡張子のリンクや壊れたリンクも含む。
- 入力ルートの親にある通常のリンクは既存と同じく実体を解決し、包含・衝突を確認する。`/tmp` のような OS の親パスの別名を一律には禁止しない。
- 出力は A/B それぞれと同一・祖先・配下のどれにも置けない。実体のパスでも確認する。入力内へ出力して次回の比較対象を増やすことや、入力ごとの削除につながる指定を防ぐ。
- 共通設定、rules.yaml、参照する全設定ファイル、作業ディレクトリと実行ファイル保存先を含む出力先は既存と同様に拒否する。出力そのもののリンクも拒否する。
- `--force` は出力全体を置き換える。列挙不能・共通設定不正・一覧や画像の書き込み失敗など、バッチ全体を完了できない場合は旧結果を保持する。
- **個別の入力・比較エラーは一覧を作成できた「一括処理の完了」とするため、`--force` ならエラー行を含む新しい一式で旧結果を置き換える。終了コードは 2。** 旧結果を残したい場合は別の出力先を指定する。
- 出力全体は既存の staging / rename 方式を使う。個別の比較が失敗した場合、その途中の個別出力を除き、存在しないレポートへのリンクを一覧に残さない。電源断・強制終了からの復旧保証は従来どおり対象外。

## コメント付き YAML による帳票別設定

利用者が編集する設定は承認済みの YAML 方針を継続する。共通設定は既存の `--config`、自動選択の定義は新しい `--rules` で渡し、通常の設定ファイルに別用途のキーを混ぜない。

```yaml
# rules.yaml。config の相対パスは、このファイルの置き場所が基準。
schema_version: 1
rules:
  # 比較する相対パス全体に一致させる例。シングルクォートなら \ を保てる。
  - pattern: '\A請求/[^/]+\.pdf\z'
    config: settings/invoice.yaml
  - pattern: '\Aスキャン/[^/]+\.(png|jpg|jpeg)\z'
    config: settings/scan.yaml
```

- `schema_version: 1` と `rules` 配列を必須にし、各規則には空でない `pattern` / `config` が必要。`rules: []` は許可する。未知・重複キー、不正な型・版・正規表現、読めない参照設定は開始前エラーとする。`--rules` の省略時は共通設定だけを使う。
- `pattern` は NFC に正規化した `/` 区切りの相対パス（拡張子を含む）を対象にする。A/B のどちらかに一致した規則を候補とし、同じ規則が両方に一致しても 1 件と数える。この方法で A/B を逆にしても選択候補を維持する。
- 正規表現は既定で大小文字を区別せずカルチャ非依存とし、.NET の非バックトラック方式を使う。通常の文字列・選択・繰り返し等に対応し、先読み・後読み・後方参照等の非対応構文は日本語で読み込みエラーにする。部分一致を許可し、相対パス全体に限定するときは例のように `\A` / `\z` を使う。新しいタイムアウトの調整パラメータは追加しない。
- 一致が 0 件なら共通設定、1 件ならその設定を上書きとして使用する。複数一致は先勝ち・後勝ちにせず、**そのファイル対の `CONFIG_RULE_AMBIGUOUS` エラー**として、該当する規則番号とパターンを一覧に残す。同じ config を指す規則でも複数一致はエラーにする。
- 設定の順序は **既定値 → 共通 YAML → 一致した帳票別 YAML → 明示 `--profile` → CLI**。帳票別 YAML は既存と同じスキーマの部分設定で、省略した項目は共通設定を引き継ぐ。ネストした項目は指定したキーだけを上書きし、空のマッピング `{}` は上書きしない。
- `exclude` は指定があれば配列全体を置換する。`exclude: []` は共通の除外を解除し、省略は共通の除外を継承する。配列の自動連結は行わない。
- `image_dpi` の明示指定を全レイヤーで追跡し、どちらの YAML にもなければ最終 `dpi` に追従する。明示した場合は保持する。PDF/画像混在での DPI 不一致は既存どおり個別エラーにする。
- 各 YAML は、後で上書きされる値も含めて既存の型・範囲を検証する。全参照設定を開始前に読み込み、合成した各設定も検証する。実行中に同じ設定ファイルを繰り返し読み直さず、入力 YAML への書き戻しはしない。
- 共通設定・選択定義・帳票別設定のパスと SHA-256、適用した CLI 値を一覧 JSON に記録する。各成功項目に選択した規則番号・パターン・設定パスを残し、個別レポートの config には従来どおり全実効設定を記録する。

設定例は `examples/batch/rules.yaml` に置き、既存の strict / scan 等と同じ通常設定を参照する。配布ツールは下位フォルダを含む YAML を同梱するよう更新し、通常設定例と選択定義を別々のローダーで検証する。

## 一覧・個別レポートと終了コード

```text
batch-result/
  index.html
  index.json
  files/
    f000001/
      report.html
      result.json
      pages/...
      crops/...
    f000003/...
```

既存の単一比較処理を共用し、成功したファイル対は今までと同じ JSON・HTML・画像を出す。片側のみ・個別エラーには個別レポートを作らないため、ID に欠番があってもよい。`--no-html` は一覧・個別両方の HTML を省略し、JSON と画像は保存する。

一覧 JSON は個別 result.json と別の形式として `schema_version: 1`、`report_type: "directory_comparison"` とする。

| フィールド | 記録する内容 |
|---|---|
| tool / generated_at | ツール名・版・生成日時 |
| inputs | A/B の入力フォルダ |
| configuration | 共通 YAML・規則 YAML・参照設定の出典と SHA-256、CLI の適用値 |
| summary | status（same / different / error）、全対象項目数、比較成功数、same / different / only_in_a / only_in_b / error の件数、対象外の件数 |
| files[] | ID、代表相対パス、A/B それぞれの元相対パス（欠ける側は null）、状態、選択規則、成功時の比較サマリーと警告数、個別 JSON / HTML への相対リンク、個別エラーの code / message |
| ignored[] | 対象外拡張子の入力 A/B・相対パス・理由。件数は A/B の延べ数 |
| warnings[] | NO_TARGET_FILES 等の全体の説明。個別の警告本文は個別レポートに保持する |

一覧 HTML は日本語の全体集計、各ファイルの状態・ページ差分数・クラスタ数・警告数・適用設定・個別結果へのリンク、エラー理由と対象外一覧を表示する。未比較・失敗時のページ数や警告数を「検査して 0 件」と誤解させず、JSON では比較サマリー・警告数を null、HTML では未比較と表示する。すべてオフラインで、相対リンクと HTML エスケープを使い、390px の表示とキーボード操作も検証する。検索や新しい対話的フィルターは追加しない。

| 状況 | 動作・終了コード |
|---|---|
| 比較成功分がすべて same、片側のみ・エラーなし | 一覧を保存、0。フォント警告等だけでは 1 / 2 にしない |
| different または片側のみがあり、個別エラーなし | 一覧を保存、1 |
| 読めない・破損した比較入力、ページ範囲、比較処理の個別失敗、規則の複数一致 | error 行を残して他の対を継続。一覧を保存、2。状態の優先順位は error → different → same |
| 対象項目が 0 件（空同士・対象外拡張子しかない場合） | NO_TARGET_FILES と対象外一覧を保存、summary.status=error、2。「全一致」とは扱わない |
| 引数・共通設定・規則・参照設定が不正、名前衝突、入力列挙不能、リンク、入力/出力の包含 | 比較開始前に中止、2。新しい一覧を確定せず旧出力を保持 |
| 画像・個別レポート・一覧の書き込み失敗等の出力障害 | 全体中止、2。旧出力を保持。書き込み失敗を単なる入力エラー行として隠さない |

`--quiet` は通常の完了表示を省略する。エラーの標準エラー出力は維持する。一覧を保存できた場合は出力先を案内し、個別レポートの完了メッセージをファイル数分繰り返さない。

## 比較した代案

| 判断 | 推奨と代案 |
|---|---|
| 対応キー | 推奨は NFC・大小文字を区別しない相対パス。厳密一致なら表記差を片側だけのファイルと扱うが、Windows/macOS 間で結果が変わりやすい |
| 対象ファイル | 推奨は対応拡張子から候補を選ぶ。全ファイルの内容を開く方式では README 等も大量のエラーになりやすい |
| 設定選択 | 推奨は共通設定への部分上書き・複数一致エラー。一致設定による全置換や先勝ちは、共通設定の意図しない消失や規則順への依存が生じる |
| 個別エラー | 推奨は継続してエラー一覧を保存。最初の失敗で全体中止なら旧結果は残るが、他のファイルの結果を得られない |

## 実装の分担と受け入れ条件

1. CLI の compare / compare-dir を明示的に区別する。既存の単一比較を、呼び出し側が結果と出力確定を管理できる処理として共用する。比較式・既定値・ページの判定・個別 schema_version は維持する。
2. パス保護と列挙・対応付けを独立した処理にする。再帰・隠し項目・日本語・空白・大小文字・Unicode・衝突・片側・空・対象外・ファイルとディレクトリの衝突・リンクを検証する。権限やアクセス失敗は無理に実機確認済みとせず、注入できる列挙失敗と実環境の結果を区別する。
3. 選択定義と YAML レイヤーを検証する。未知・重複キー・非対応正規表現・0/1/複数一致・相対設定パス・A/B 反転・省略値・配列置換・image_dpi の明示・既存の profile / CLI 優先順位を確認する。実効設定を同じにした単一比較と結果を照合する。
4. 合成 PDF / 画像を使う実 CLI の一式で、same / different / 片側 / 個別エラー・成功と失敗の混在・ページ選択・フォント警告・--no-html / --quiet / --force を確認する。成功項目の個別結果と既存 compare を照合し、失敗項目の不完全な出力や無効なリンクを残さない。
5. 出力が入力と重なる場合の拒否、参照設定の保護、全体エラー時の旧結果保持、個別エラーを含む完了時の置換を区別して検証する。大きな入力は逐次処理し、小規模の一式と多数の小さなファイルで時間・メモリを記録する。
6. 一覧 HTML の 1280/390px、長いファイル名・特殊文字、エラーと対象外の説明、相対リンク・キーボード・外部通信なしを確認する。既存個別レポートの表示も維持する。
7. ビルド警告 0、全テストと既存 37 ゴールデンを確認。SPEC・設定リファレンス・README・TASKS・コメント付き設定例・検証記録を更新し、Windows publish・バンドル・ZIP の静的検証を行う。Windows 実機・リンク/ジャンクション・権限・Edge/Chrome は別の未確認項目として残す。
8. 1 ローカルコミットで T2-6 を完了し、T2-7 と push の前で停止する。

## 承認前の試行と根拠

`out/t2-6-probe/` の独立したプログラムで、既存の .NET / YamlDotNet / ConfigurationLoader を使った 9 条件を確認した。製品コードや正式なスキーマを実装したものではない。

- 大小文字・日本語の合成/結合文字を同じキーとして対応でき、同じ側の衝突を検出できた。
- 正規表現でディレクトリと拡張子を指定でき、非対応の後読みは読み込み時に拒否された。
- 共通 YAML の色しきい値 8 を残し、帳票別の dpi と除外配列を上書きし、最後に strict / --dpi 400 を適用できた。未指定 image_dpi は 400、明示済みの image_dpi: 200 は 200 を維持した。
- 空のマッピングでは共通の指定を残し、exclude: [] では共通の除外を解除できた。
- 列挙オプションを明示することで、隠しフォルダ内の日本語名の PDF 候補も列挙できた。

根拠：[.NET の正規表現オプション](https://learn.microsoft.com/en-us/dotnet/standard/base-types/regular-expression-options#nonbacktracking-mode)、[列挙時に省略する属性の設定](https://learn.microsoft.com/en-us/dotnet/api/system.io.enumerationoptions.attributestoskip?view=net-10.0)。非バックトラック方式の対応構文と列挙の既定の省略を確認し、上記の試行で手元の .NET 10 の動作を確認した。
