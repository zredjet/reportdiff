# T2-4a 承認済みパラメータの外部設定整備

状態：2026-09-21、ユーザーから、これまで承認したパラメータを最終的にコメント付き外部定義ファイルで調整可能にするよう依頼された。方針とタスク化は確定。実装は T2-4 完了後の別タスクとして扱う。

## 方針

既存の `--config <settings.yaml>` と YamlDotNet を継続して使い、UTF-8 の YAML を外部定義形式とする。`#` のコメントで用途・単位・既定値・範囲・影響を書ける。ユーザーの希望する YAML / TOML のうち、既存の運用・配布例・依存を維持できる YAML を採用する。

現在も `dpi` / `image_dpi`、`diff`、`cluster`、`move`、`exclude`、`report` は外部設定可能で、T2-4 では `align` の有効化・探索距離・一致度・候補差・改善量も追加する。T2-4a は読み込み機能の新設ではなく、残る承認済みパラメータの網羅と文書・既定値・検証の統一を目的とする。

## 作業と受け入れ条件

1. SPEC・承認済み計画・実装を照合し、全パラメータの台帳を作る。設定キー、意味、単位、既定値、許容範囲、適用箇所、変更時の影響、実装済み／未対応を列挙する。分類の局所背景半径・インクのしきい値、移動判定の条件、PDF 注釈の出力／抽出件数上限、全体補正の縮小探索・支持セルの条件も対象に含める。
2. 未対応の調整パラメータを同じ YAML で指定できるようにする。整数格子や固定カーネル等のアルゴリズム構造と、利用者が調整する値を台帳で区別する。設定化できない値・意味や保証が変わる値は理由と対応案を明示し、未確定のキー・範囲は実装前に具体化する。承認済みパラメータを黙って対象から落とさない。
3. 承認済みの値を既定値として維持する。設定を省略した既存利用とゴールデンの結果を変えない。長さは mm とし、換算を `Units` に集約する。定数の設定化で SPEC 5 章の式を変更する場合は CLAUDE.md の同期ルールに従う。
4. 未知・重複キー、型、有限値、範囲、項目間の矛盾を検証し、キー名を含む日本語エラーを出す。既定値 → YAML → 明示プロファイル → CLI の優先順位と、各段階が上書きする項目を説明する。
5. `examples/settings.yaml` に調整可能な項目を網羅し、各項目に日本語コメントを付ける。コピーして実行できる最小例と、用途別の調整例を用意する。説明と実装の既定値が一致することを確認する。
6. 実効設定を `result.json` と HTML に記録する。入力の YAML を書き戻さず、利用者のコメントを保持する。JSON は引き続き機械処理用の結果出力形式であり、利用者が編集する外部設定形式は YAML とする。
7. コメント付き設定・部分指定・省略・異常値・優先順位・既存ファイルとの互換性・実 CLI への反映を検証する。Windows 配布 ZIP に更新済み設定例を含める。

## 実施位置と境界

T2-4 の次、T2-5 より前に実施する追加タスク **T2-4a** とする。既存の T2-5〜T2-7 の番号は維持する。T2-6 の帳票別設定選択は、この共通 YAML スキーマを再利用する。T2-7 の実帳票評価で調整した値も同じ設定として記録できるようにする。

今回の追加依頼では本計画・TASKS・SPEC の方針を更新し、T2-4a 自体の実装完了とはしない。T2-4 の実装・検証・コミット後は、元の停止位置どおり停止する。
