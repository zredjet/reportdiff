# T3-4b 領域別設定

対象は [TASKS の T3-4b](../TASKS.md)。2026-09-22 着手。T3-6 完了コミット `bbf14cf` を互換性の基準にする。T2-8 の保留分は維持する。状態：2026-09-22 承認済み・実装とローカル検証完了。境界の分類・移動、内包時の設定継承、抑制箇所の定義を含め、以下の仕様で進める。

## 設定の意味

```yaml
regions:
  - {name: 明細欄, page: all, x: 10, y: 60, w: 190, h: 180, profile: strict}
  - {name: 小計欄, page: all, x: 150, y: 200, w: 40, h: 20, diff: {color_threshold: 1}}
  - {name: ロゴ, page: all, x: 10, y: 8, w: 40, h: 12, mode: exclude}
```

name・page・x・y・w・h は必須。name は非空文字列で設定内で一意、page は all または 1 以上の整数。x/y は 0 以上、w/h は正の有限 mm 値。mode は compare（既定）または exclude。compare は profile と diff の 3 項目だけを上書きできる。exclude に profile / diff があれば、無意味な指定を見逃さないようエラーにする。anchor / float_mm を含む未知キー、型・数値範囲・最終 DPI での変換限界をキー名付きで拒否する。

各 compare 領域の実効値は、**最終ページ設定 → 領域の profile → 領域の明示 diff** の順に決める。profile の定義は従来どおり max_shift_mm と edge_tolerance の上書きで、color_threshold は継承する。CLI の --profile はページの基準値を変えるが、領域の明示 profile / diff を消さない。

内包関係は画素の所有を決めるもので、親領域の設定は継承しない。上例の小計欄は「ページ設定＋色しきい値 1」となる。小計欄も strict にしたい場合は profile: strict を明示する。設定の由来を YAML の位置や親の追加で変化させないための仕様。

compare-dir は配列全体を置換する。空配列で解除、省略で継承する。共通・帳票別の各 YAML は、後から上書きされる内容も検証する。

## 座標と優先順位

領域は現在の判定座標、すなわち A／全体補正後 B の左上が原点。T3-6 の確認用画像には適用しない。

同じページに適用される領域は、交差しないか、片方がもう片方を完全に内包すること。完全に同じ矩形は優先順位を決められないため拒否する。辺で接するだけは交差ではない。内包される小さい領域を優先する。除外は compare より常に優先し、外側の exclude を内側の compare で解除しない。既存 exclude との重なりは許可する。

名前付き領域同士の部分交差は mode によらず設定エラーとする。mm で検査し、描画後にも px で検査する。左上は切り捨て、右下は切り上げるため、mm で隣接する領域が 1px を共有することがある。この場合も暗黙に片側を勝たせず、該当する regions の番号・DPI を示してエラーにする。mm で内包する矩形が丸め後に同じになった場合は、元の内側を優先する。

ページからはみ出す範囲は既存 exclude と同様にクリップする。元の mm 矩形、クリップした px 矩形、実際に所有する画素数を記録する。ページ外や内側領域・除外によって有効画素がない場合は、その理由を記録し、不要な比較を省く。部分的にはみ出すこと自体はエラーにしない。

## 生差分の合成

1. ページ既定の diff で、従来の 5.2〜5.3 をページ全体へ一度実行する。これを基準実行とする。
2. 有効画素を持つ領域の diff を値でまとめる。基準と異なる実効値ごとに、同じページ全体へ 5.2〜5.3 を実行する。領域で切り出さない。同じ diff は複数領域でも再実行しない。
3. 各画素について、所有する領域の実行結果を選ぶ。領域外は基準実行。既存 exclude と mode: exclude の和集合を最後に 0 にする。
4. 合成した生差分に対して、従来の 5.5 によるクラスタ化を一度だけ行う。クラスタ・結合・ノイズ閾値・番号付け・上限はページ設定のまま。

比較式・端の処理・二段目のグループ・同点の選択順は変更しない。Core の生差分生成とクラスタ化の入口を分離し、領域なしは既存の経路を使う。

基準実行の absorbed_groups / max_shift_px は、従来のページ項目と summary に残す。他設定の実行分を加算しない。各設定の全ページ実行の吸収数・最大ずれを別の実行情報に記録し、領域はその実行を参照する。この吸収数は「領域内だけの吸収数」ではないことを明記する。

## 境界をまたぐ分類・移動

### 分類

インク抽出の条件はページ共通。分類に使う各画素で、その座標の実効 edge_tolerance が 0 なら元のインク、0 より大きければ従来の 3×3 膨張後インクを参照する。膨張の近傍は領域の境界で切らない。形状一致は従来どおり元のインクで確認する。

クラスタを境界で分割しない。各画素の added / removed / 両側 / 背景という状態を、既存の分類規則で一つのクラスタに集計する。削除の緑色も同じ画素条件で作る。代表点や面積の多数決でクラスタ全体の設定を選ばない。

### 移動

探索範囲・テンプレートの余白・スコア・一意性・双方向性・元位置の残差説明・競合時の保留は現在のまま。

移動の画素検証は従来どおり max_shift_mm=0。比較するテンプレート全体を各実効 diff で計算し、**対応する画素が、移動元の座標と移動先の座標の両方の diff を満たすこと**を要求する。領域境界ではテンプレートを切り出し直さず、同じ窓の結果から該当画素を選ぶ。移動候補・関連クラスタの説明に使う前向き／逆向きの全窓へ同じ規則を適用する。

例：strict の欄から loose の欄へ移る内容が loose の条件だけで一致しても、strict で色・輪郭の差が残れば moved を付けない。差分やクラスタを消すことはなく、通常の分類を残す。両側の条件で一致し、一意な移動が全残差を説明できれば、境界をまたいでも moved を付ける。

ページ全体が単一の設定なら、生差分・分類・削除色・移動量・関連 ID が、その設定をページ全体に指定した従来の実行と一致することを必須とする。吸収数と最大ずれは前節の基準実行という別の定義を保つ。

## --no-regions と全体補正・注釈

--no-regions は regions と既存 exclude の両方を比較・全体補正・PDF 注釈・判定画像から外す。CLI の profile や全体補正機能そのものは維持する。raw evidence は引き続き同一画像になる。

通常時、mode: exclude を既存 exclude に合成して、比較、全体補正の除外、PDF 注釈の除外、判定画像の黄色表示で共用する。compare 領域の diff は全体補正の探索条件を変えない。

無視した宣言を失わないよう、実効 config は無効化後の exclude / regions を記録し、別の監査項目に元の宣言と --no-regions による無視を記録する。HTML にも表示する。無効化で不正 YAML の型・範囲・曖昧な重なりを見逃さず、入力設定としての検証は行う。

## 報告

schema_version=1 の追加項目として、領域の宣言・実効 diff、適用ページ・実効 px 範囲・所有画素数・生差分画素数・実行参照を記録する。片側ページは未比較、対象外ページは非適用として扱う。

compare 領域では、`基準実行の生差分 AND NOT 合成後の生差分` の画素を、その領域の所有画素に限って「領域設定で抑制した差分」とする。既存 exclude と mode: exclude による消去は別に集計し、重複加算しない。領域ごとの抑制画素と、ページ全体の和集合を報告する。

「抑制した箇所」はこのマスクの 8 近傍連結成分数と定義する。ノイズ除去・結合・上限適用後の通常の clusters とは別の数で、summary.clusters に加えない。元の差分が基準のノイズ閾値未満でも、生差分として抑制量には含まれることを説明する。

判定の重ね描きに薄い色で抑制画素、青の破線と領域名で領域を示す。既存の差分・輪郭・番号を識別できる描画順にする。相違がすべて抑制された場合も、この確認に必要な判定画像を保存する。元 A/B と raw evidence に領域枠や色は描かない。領域名は HTML に全文表示し、PNG は既存 SkiaSharp による日本語描画と領域番号を使う。

## 実装と確認の順序

1. 型・設定合成・重なり／px 化・監査モードを実装し、単体検証する。
2. 生差分生成とクラスタ化を分離し、領域なしと全面単一領域の完全一致を確認する。
3. 画素ごとの分類と移動の両側検証を追加し、境界をまたぐ回帰ケースを確認する。
4. JSON / HTML / PNG と CLI・compare-dir を接続する。SPEC・設定例・リファレンスを同期する。
5. 全回帰・42 ゴールデンの既存出力互換性、T3-6 の PNG 不変性、実 CLI、ブラウザ 1280/390px・キーボード・オフライン、2/3 設定の A4 時間・最大 RSS、Windows publish / ZIP 静的検証を行う。

比較は実効 diff ごとに逐次実行し、特徴量・探索データを設定数ぶん保持しない。ページ単位で設定の所有マップ、基準・合成・抑制マスクを持ち、不要になった Mat を破棄する。比較式・解像度・既定値・ゴールデン期待は変えず、新規依存も追加しない。

## 着手時に用意した検証基準

`bbf14cf` の CLI を `out/t3-4b-baseline-src` で別ビルドした。42 ゴールデンを保存済みの params・--save-all-pages・--raw-overlay で実行し、JSON と全 PNG の SHA-256 を `out/t3-4b-baseline/manifest.json` に保存した。変更後は日時と承認した追加項目を除き、これに照合する。

境界の移動検証用に、320×240px・300dpi の白地で、(180,100) の非対称図形を右へ 50px 移すケースを作った。図形は基準位置からの相対矩形 (0,0,4,22)、(0,18,18,4)、(14,0,4,6) の和集合。色は A が黒、B が黒または RGB(32,32,32)。現行 CLI の max_shift_mm=0 / edge_tolerance=0、color_threshold=3 / 20 で次を確認した。

| B の色 | 色しきい値 3 | 色しきい値 20 | 生差分・クラスタ |
|---|---|---|---|
| 黒 | moved、(+50,0)px | moved、(+50,0)px | いずれも 336px・1 個 |
| RGB(32,32,32) | changed、移動量なし | moved、(+50,0)px | いずれも 336px・1 個 |

この入力に x=220px の領域境界を置くことで、「分類だけが偶然一致する」テストを避け、移動元／先の両側検証を確かめられる。黒同士は moved、色変更併発は changed を期待する。これは着手時に行った領域なしの基準実験であり、実装後の確認は [検証記録](../verification/t3-4b-regions.md)に分けて記録する。入力・各実行結果は `out/t3-4b-probe/` に保存した。
