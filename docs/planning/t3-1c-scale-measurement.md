# T3-1c A4・多ページのCLI全工程計測

2026-09-23。[CLI接続後の残件](../verification/t3-1c-cli-integration.md)に従い、製品の比較式・採用条件を変更せず、サイズ・ページ数・密度を増やして処理時間・最大RSS・出力量・再描画回数を確認する。今回の製品ソース99ファイルは前段階のハッシュと照合する。

## 入力と区別

- SkiaSharpと自作TrueTypeによるA4指定の2・8・16・30・31ページ。本文24行、末尾2行の空きを残した単一挿入。2ページの本文48行、対応本文の濃淡変更、送り帯の濃淡変更も含める。
- 元のSkia入力は本文末尾の1px超過で送りが成立しなかった。元PDFと期待を保存し、採用成功のケースへ差し替えない。
- 描画端を0.12pt内側へしたSkia対照、Type3の分数寸法対照、整数pt寸法対照を別々に保存する。範囲を確定できても移動前後の罫線画素差や改善不足で採用できない場合があり、それも未成立とする。
- 別の疎なType3対照は1ページ6行・2／16ページとする。A4相当の面積で採用経路の負荷を測るための入力であり、24／48行の帳票の成立を代用しない。

生成器の行ID・期待所属は検証ツールだけが保持する。製品にはPDFと既定のrows設定だけを渡す。OCR、全体補正、除外、比較しきい値の緩和は使わない。SkiaのMediaBoxの丸めと実ラスタ寸法も記録し、「指定A4」と整数画素用の対照寸法を混同しない。フォント字形は試験用の自作図形であり、実帳票の可読性評価ではない。

## 計測

製品CLIは同条件を原則3プロセスで反復し、30・31ページと補助的な描画対照は各1回の観測とする。起動、PDF読込・描画、事前収集、帯検証、採用判定、最終比較、注釈、JSON／HTML／PNG／raw overlay保存を含む。独立したプロセスを逐次実行し、ビルド・テスト・他の比較を同時実行しない。時間の中央値と範囲、子プロセスごとのwait4による最大RSS、出力バイト数を保存する。OSキャッシュは消去せず、コールド起動の保証はしない。

out配下に製品ソースをコピーしてタイマーだけを挿入する。段階別の時間は親子IDを持ち、親子を二重加算しない。PDF描画回数はこのコピーで実測する。計測コピーは各条件の最初の反復で確認し、製品の時間集計へ混ぜない。生成日時以外の全JSON／HTMLと全PNGを製品・コピー・反復間で照合する。

## 安全条件と未成立の扱い

- 送り見送りでは有効／無効の全ページDTOとraw evidenceが一致すること。
- 採用した疎な対照では内容差分0、ページ別内訳3P−1、集約後1、全構造IDの参照と元帯を確認すること。
- 元のA4正例の期待が成立しなくても、その期待を下げて合格にしない。`expectation_unmet` と実際の理由・件数を記録する。性能値はその経路の観測結果として扱う。
- 30ページは画素予算内、31ページは `flow_pixel_limit` で送り全体を見送り、通常比較を最後まで完了すること。
- 記述64MiBの上限はプロセスのRSSを制限しない。高いRSSを観測した場合は別の残件として記録し、上限を緩めない。

## 境界

合成PDFの自動検証とPNGの静的確認まで。実帳票・Windows実機・保留中のブラウザー操作は実施しない。送りが成立しない一般的なA4の描画条件、複数原因、数値変更、全体補正の座標合成の解決を今回の性能計測の完了に含めない。測定結果を確認してから、原因調査や性能改善を別の作業として判断する。
