# T2-4 全体のずれ：仕様・実装計画

状態：2026-09-21、ユーザーの「仕様案はOK」により承認。開始点は `b549c2a`（T2-3）。実装・検証済み。[確認結果](../verification/t2-4-alignment.md)を参照。ローカルコミットまでで停止する。追加依頼の外部設定整備は [T2-4a](t2-4a-configuration.md) としてタスク化し、このタスクでは承認済みの `align` 設定を既存の YAML に追加した。

## 推奨する動作

全体補正を任意の前処理として追加する。既定は無効とし、有効な場合だけ、ページ全体に共通する整数 px の平行移動を推定して B を A の座標に合わせ、その画像を既存の比較処理へ渡す。拡大縮小・回転・傾き・サブピクセルの補正は行わない。補正後も既存の局所ずれ吸収・差分分類・移動注釈を実行する。

```yaml
align:
  enabled: false
  max_shift_mm: 5.0
  min_score: 0.98
  min_score_gap: 0.02
  min_improvement: 0.05
```

- `max_shift_mm` は上下左右それぞれの上限。0〜20mm とし、整数 px への換算は `Units` を使って切り捨てる。0 は探索せず補正しない。
- スコアは 0〜1。`min_score`、`min_score_gap`、`min_improvement` は有限かつ 0 より大きく 1 以下。画像上の一致度の指標であり、統計的な信頼確率ではない。
- `strict` / `normal` / `loose` は既存の局所ずれ・輪郭許容だけを変更し、`align` は YAML の明示設定を維持する。新しい CLI 引数や依存は追加しない。

## 探索と採用条件

1. 描画・サイズ正規化後、既存の差分比較より前に実行する。元の A/B のサイズが異なる場合、片側しかないページでは補正しない。
2. グレースケールの暗さ `255 - gray` を推定に使う。長辺が 800px 以下になるまで 2 の累乗で面積平均縮小する。セルの座標倍率を整数に保つため、必要な右・下の端数だけ白で埋める。この計算用の余白は比較画像へ加えない。
3. 縮小段階で指定範囲の全候補を評価し、以後は倍率を半分ずつ戻して直前の候補付近 ±2 セルを評価する。元解像度の最終候補を指定範囲内の整数 px に限定する。縮小段階の丸めで指定範囲の外側を評価しても、それを適用しない。
4. 全候補で同じ画素を評価する。探索上限の分だけページ端を除き、除外領域も同じ上限分だけ拡張して推定から外す。縮小セルの一部だけが評価領域に入る場合も使わない。これは推定専用の領域であり、差分比較は補正後のページ全体を対象とする。
5. 一致度は `1 - sum(abs(A_dark - B_dark_shifted)) / sum(A_dark + B_dark_shifted)`。白紙の一致でスコアが高くならないようにする。分母が 0 の候補や評価画素が不足するページでは採用しない。
6. 最終一致度 0.98 以上、補正なしからの改善 0.05 以上を要求する。元解像度の最終探索窓内で、次点候補との差を 0.02 以上とする。さらに縮小探索でも、最良候補の隣接 1 セル以内を除く別のピークとの差を 0.02 以上要求する。候補が同点・曖昧な場合は補正しない。元解像度で全範囲を総当たりする方式ではなく、縮小で区別できない候補は見送る方式。
7. 局所的な 1 図形だけを全体移動と扱いにくくするため、ページを 3×3 に分け、2 行・2 列以上にまたがる少なくとも 3 セルで同じ補正を支持することを要求する。各支持セルは A/B それぞれに黒換算 1mm² 以上の暗さがあり、同じ一致度・改善条件を満たすこと。情報の少ないページは補正を見送る。
8. 補正は整数移動なので再補間せず、空いた端は白で埋める。ただし B のページ外へ押し出される帯に白以外の画素が 1 個でもあれば、内容を捨てず補正そのものを見送る。この確認では除外領域内の画素も省略しない。

採用されない場合は元の画像で通常の比較を続ける。エラーにせず、JSON / HTML に省略理由と取得できた候補・スコアを残す。無効時は画像処理を実行せず、既存の比較結果を維持する。

## 座標と出力

- `pages[].global_shift_px` は **B に実際に加えた補正量（B→A）**。右・下を正とし、適用しなかった場合は null。B が右へ 10px ずれていた場合は `{ "dx": -10, "dy": 0 }`。クラスタの `shift_px` は従来どおり **補正後の A→B の残存移動量**なので、HTML で方向を区別する。
- `pages[].alignment` に適用／未適用の状態、理由、推定候補、補正前後のスコア・候補差・支持セル数を記録する。未計算の数値は null。実効 `config.align` も記録する。schema_version は 1 を維持し、既存項目の型は変更しない。
- 採用時は `GLOBAL_SHIFT_APPLIED` にページ番号・補正方向・量を必ず記録する。補正により `same` になった場合も A・補正後 B・補正前 B・重ね描きのページ画像を保存し、HTML で補正前 B を確認できるようにする。`images.b_original` を追加する。
- 差分の矩形・切り出し・重ね描き・除外領域は **A／補正後 B の座標**。除外領域は補正後の座標に固定し、画像を補正した後に既存どおり差分から除く。
- PDF の B 側は元のページ寸法でテキスト座標を求めた後、同じ補正量を単語矩形に足して、クラスタ・除外領域と対応付ける。テキスト抽出の省略条件は T2-3 のまま。
- 補正は差分数・状態・終了コードを変えることがある。最終結果は補正後の比較結果とし、補正した事実は警告と画像で残す。

## 限界と代案

合成例で保守性を検証するが、画像だけから「出力装置のずれ」と「意図的に帳票全体を移動した変更」は区別できない。有効にした利用者が全体移動を許容する機能とする。少数の図形、背景色が端まであるページ、曖昧な繰り返し、広い除外領域、サイズ差、整数移動で説明できないページは補正を見送りやすい。

| 案 | 特徴 |
|---|---|
| 明示的に有効にした場合だけ、確度と端の内容を確認して補正（推奨） | 既定の検出結果を維持し、推定が不十分なら元の比較へ戻せる |
| 推定量だけを報告し、B は補正しない | 差分を吸収しないが、SPEC の「補正してから比較」は満たさない |
| 既定で自動補正する | 設定の手間は少ないが、従来は検出していた全体移動で結果が変わる |

- 承認後は、無効時の既存 37 ゴールデンと全テストを維持。全方向・上限内外・複数 DPI・内容変更併存・局所移動・白紙・少ない情報・繰り返し・ページ端・除外・サイズ差・片側ページを検証する。
- PDF テキストの補正座標、画像/PDF 混在、JSON / HTML / 終了コード、補正で相違なしになったページの証拠画像を実 CLI でも確認する。HTML は 1280/390px・キーボード・外部通信なしを確認する。
- A4・300dpi の時間とメモリを記録。Windows publish とバンドル・ZIP の静的検証を行い、Windows の実行確認は別の未確認項目として残す。
- SPEC・設定例・TASKS・検証記録を更新し、ビルド警告 0・全テスト成功の後に 1 ローカルコミット。T2-5 へ進まず、push は行わない。

## 承認前の合成画像での試行

既存の OpenCvSharp と比較コアを参照した独立した試行コードを `out/t2-4-probe/` に作成し、上記方式の候補推定・判定を試した。製品コード、既存の設定・比較式・ゴールデン期待値は変更していない。100 / 300dpi の A4 合成画像で、下表の 12 条件ずつ、計 24 条件を実行した。

| 条件 | 試行結果 |
|---|---|
| 同一ページ | 候補 (0,0)、補正なし |
| 右下／左上への全体移動 | 正しい逆方向の補正量を採用。補正後の既存コアは相違なし |
| 右上への全体移動＋数値 5→1 | 正しい補正量を採用。100 / 300dpi とも既存コアに 1 クラスタの内容変更が残る |
| 上限の移動（100dpi は ±19px、300dpi は ±59px） | 文字に変化のある配置では正しい補正量を採用。補正後は相違なし |
| 上限を 5px 超える移動 | 最終一致度不足で補正なし |
| 同じ文字を並べ、上限まで移動 | 別の繰り返し位置に候補が寄るが、最終一致度不足で補正なし |
| 白紙 | 補正なし |
| 中央の単独図形だけの移動 | 支持セルが 1 個のため補正なし |
| 補正で押し出される端に 2×2px の内容がある | 端の内容を失うため補正なし |
| 周期的な縦横罫線 | 別ピークとの差が不足して補正なし |
| 除外領域内の変更＋全体移動 | 正しい補正量を採用。補正後の座標で除外し、既存コアは相違なし |

300dpi の全体移動＋数値変更の一致度は約 0.9988。初回を含む 1 条件 1 回の探索試行は、A4・300dpi で約 187〜357ms。これは画像生成・既存コアでの比較・PDF・レポートを含まない予備値であり、正式な性能計測や受け入れ完了ではない。生の結果は `out/t2-4-probe/results.json`。

初期の試行では、小さな 5→8 の変更は 100dpi の既存コアで吸収されたため、検出される 5→1 の例で補正後の変更保持を確認した。また除外領域の境界ぴったりに変更を描くと既存の輪郭処理が領域外にも差分を作るため、座標確認用の例は境界から 3px 内側へ変更を置いた。いずれも検出条件を緩めず、既存の挙動を維持している。実装後のテストには補正前後の参照画像との一致も加え、補正の影響と既存検出の限界を区別する。

PDF テキスト、レポート、設定読み込み、サイズ不一致、全方向・複数の境界条件、Windows 配布物はこの承認前試行の対象外だった。承認後の製品への組み込みと検証は [確認結果](../verification/t2-4-alignment.md) に記録した。
