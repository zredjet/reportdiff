# T3-1b：元画像の特徴量を帯ごとに写す案の検証

2026-09-22。基準は v0.1.3（`f77ac1c`）。「次の検討候補に進んで」の指示により、[前回提示した案](t3-1b-white-band.md)を独立した試行で検証した。

**今回の具体案も不採用。** 前回の黒い縦罫線の反例は解消する。しかし灰色の縦罫線では、検出できていた濃淡変更が二段目でノイズ扱いになり、A/B 交換でも結果が対応しない。さらに、挿入帯の内容が元画像の局所近傍に入ると、一段目でも見逃す。特徴量の取得場所を変えるだけでは解決しない。

製品・参照実装・既定値・ゴールデンの検出期待は変更していない。行整列の実装へは進めず、T3-1b は未完了のまま維持する。

## 試した処理と座標

行推定を使わず、既知の正しい PageMap を与えた。比較対象の帯の B 全画素が、行挿入前の「内容変更だけを加えた B」を写した画素と一致することを検査した。

1. 全体補正後・行整列前に相当する元 A/B 上で、Lab、3×3 ぼかし、5×5 局所コントラスト、局所背景に基づくインクを計算する。strict は既存どおりぼかさない。
2. これらの特徴量を PageMap の帯どおり整数転写する。詰め物は一様な純白の特徴量（Lab=(100,0,0)、コントラスト=0、インクなし）。転写後に近傍の特徴量を再計算しない。
3. 一段目の式、インクの連結、候補近傍の膨張、二段目の探索は既存の 5.2 / 5.3 と同じ。**group とシフトの座標は、詰め物を含む表示キャンバスのまま**。B のシフトはキャンバス端を複製し、詰め物との境界を越えることもある。
4. 承認済み案と同じく、片側だけの構造帯を生差分から除くのは二段目の後。帯の外側は追加で消さない。その後、既存のクラスタ化を使う。

元画像の全行は一度ずつ順序どおりに写し、切り捨て・複製を検査する。横ずれ、異なる幅、複数挿入は今回の試行範囲に含めない。C# は比較用の独立した逐次実装、Python は参照実装の特徴量関数とクラスタ化を再利用した独立実装。製品コアに試行用の API は追加していない。

## 反例1：初期候補が正しくても二段目で失う

挿入帯も一様な灰色罫線とした、最小の反例。normal / loose の結果は以下。基準の濃淡変更は通常クラスタとして検出される。

| 比較 | 初期候補のうち対応帯の画素 | 最終生差分 / クラスタ | 判断 |
|---|---:|---:|---|
| 挿入前の基準 | 4 | 4 / 1 | 検出必須 |
| 今回案・A→B | 4 | **2 / 0** | 1ノイズとして捨てられ、見逃す |
| 今回案・B→A | 4 | **8 / 1** | 交換前とマスク・検出結果が対応しない |
| 内容変更なしの挿入 | 0 | 0 / 0 | 対照例は成立 |

変更画素のぼかし後 L 差は基準・今回案とも約8.158、しきい値は約6.671。一段目では同じ4画素が候補になる。

しかし表示キャンバス上の罫線の group には、片側だけの100pxの帯も含まれる。A→Bでは、ずれ0の604候補（構造帯600＋対応帯4）より、dy=-1の602候補（構造帯600＋対応帯2）が選ばれる。変更のうち1行が構造帯側へ移る。構造帯を最後に除いたあとには2画素しか残らず、既定の最小4画素に届かない。

逆方向ではdy=+1が選ばれ、構造帯の差分が対応帯へ入り、8画素が残る。元画像で特徴量を計算しても、**表示上の詰め物をまたいで探索する問題は残る**。境界から離れた黒い部分を追加した場合も同じ現象があり、20pxの局所余白だけではこの反例を防げない。

## 反例2：元画像の近傍にも挿入内容が入る

挿入帯の末尾を黒くすると、B の元画像上でも、対応帯の先頭の5×5近傍に黒が入る。A の元画像にはその挿入内容がない。

| 変更先頭の画素 | L差 | しきい値 | 対応帯の初期候補 / 最終生差分 / クラスタ |
|---|---:|---:|---:|
| 挿入前の基準 | 8.158 | 6.671 | 4 / 4 / 1 |
| 黒い部分まで0px | 9.703 | 22.746 | **0 / 0 / 0** |
| 黒い部分まで1px・A→B | 8.158 | 22.746 | **2 / 2 / 0** |

0pxではnormal / looseの両方向で消失。1pxでは一段目から半分が落ちる。strictの変更あり10条件では12画素／1クラスタのまま保持されたが、strict強制で要件を置き換えない。

## 採否と次の設計課題

[CLAUDE.mdルール2](../../CLAUDE.md)の「『無視必須』のテストを通すために『検出必須』のテストを緩めない」に従い、この具体案を採用しない。しきい値・ノイズ条件・境界の強制strict化・A/B交換の期待変更は行っていない。

次は、**表示用の詰め物から切り離した共通の比較座標を設計し、近傍・インク連結・ずれ探索をその同じ座標で完結させ、結果だけ表示へ戻す方式**を検討するのが妥当。単に除外を前倒しするだけでは、欠けた比較画素を0として数えることで都合のよいずれが選ばれる危険が残る。

具体化が必要な契約は次のとおり。これは次の検討項目であり、採用済みの仕様ではない。

- 比較対象の帯だけで共通の仮想面を作る場合、削除・挿入部分の近傍を何で置き換えるか。帯を詰めて隣接させることで、新しい偽の近傍を作らない条件を決める。
- すべてのずれ候補で同じ評価範囲を使う。対応しない側へ出た画素を差分0として扱わず、仮説を無効にするか行整列を見送る条件を定める。
- 境界を横切る罫線や文字のgroupを都合よく分割しない。複数帯にまたがる一つのgroupのずれと、A/B交換の対応を定義する。
- 今回までの検出必須・無視必須ケース、周期ケース、regions / exclude を同じ仕様で両立させる。成立しない場合は元の比較へ戻す。見送りでR01〜R09を満たしたことにはしない。
- 比較面から表示面へ戻す際のクラスタ分割・件数・bbox、分類・移動、設定座標との関係を、実装前に確定する。

この設計は5.2 / 5.3が参照する座標・対象範囲に関わり、元の「表示キャンバスを既存比較へ渡す」契約の具体的な変更となる。[TASKSの停止条件](../TASKS.md)と[CLAUDE.mdの進め方](../../CLAUDE.md)に従い、製品へ黙って組み込まない。

後続の「次に進んでください」による[共通の比較面の検証](t3-1b-common-surface.md)と[補足仕様案](../planning/t3-1b-common-surface.md)を追加した。本記録とJSONは、特徴量写像の案を試した時点の証跡として保持する。
