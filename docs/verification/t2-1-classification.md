# T2-1 差分分類と切り出しの確認

確認日：2026-09-21。対象は T2-1 の実装・検証まで。確定仕様は [SPEC 11.1](../SPEC.md#111-追加削除変更の分類t2-1)、後続の未承認案は [Phase 2 計画](../planning/phase2.md) に記載する。

## 実装

既存の局所背景によるインク処理を `ImageInk` に共通化し、採用クラスタの連結成分に対して `DifferenceClassifier` が A→B の `kind` を付ける。検出マスク・状態・クラスタ数・矩形・画素数を変えない。外枠の矩形内にある別のクラスタを混ぜず、除外・ノイズ・上限で落とした画素を削除の緑マスクに含めない。

インク計算は採用クラスタの成分を含む範囲に局所背景・膨張用の余白を足して行う。全ページの Lab 画像を分類用に保持しない。A だけの差分がある場合のみページサイズの `RemovalMask` を作り、`PageComparison` が他のマスクと一緒に破棄する。

JSON は予約済みの `kind` を使用し、schema_version=1。`shift_px`・`text_a`・`text_b` は null。切り出しは A だけの差分が緑、それ以外が赤。全体の重ね描きは赤のまま。HTML に日本語の分類・推定の説明・凡例を追加した。分類名の改行や隣の列へのはみ出しを防ぐため、番号・分類列の幅を調整した。新規依存・設定の追加はない。

## 検証

macOS 26.5.1 / Apple Silicon、.NET SDK 10.0.401 / Runtime 10.0.12 でビルド警告 0・エラー 0、全 **450 件成功**。T1-12 の 423 件に 27 件を追加した。

- 既存 37 ゴールデンの状態・検出数・位置・統計が期待値と一致。分類あり／なしで生差分マスクと輪郭用マスクが完全一致し、クラスタの種別以外の値も一致。
- 最適化前後の 37 ケース＋画像端・非連続 Mat の 3 条件で、種別と削除マスクも一致。
- 追加・削除・混在・色変更・薄い塗り、A/B 反転、通常／厳密設定、300/400dpi、画像端、非連続 Mat を確認。
- 入れ子の削除枠と内部の追加を別々に分類。ノイズ・除外・上限で落とした差分を緑マスクから除外。1px の穴が膨張で消えても元の形状差により changed を維持し、除外された穴は形状比較に混ぜない。
- ROI の外にある背景を含めて、ページ全体から計算したインクと削除マスクの一致を確認。
- JSON の kind と既存キー構成、純粋な削除の緑、混在したクラスタの緑／赤、全体の重ね描きの赤、入力画像の不変を確認。
- 合成 PDF の実 CLI プロセス結合は既存 6 件＋追加 2 件。分類用 PDF を A/B 双方向に比較し、JSON・PNG・HTML の 4 種類のラベル、切り出し画素、埋め込み JSON の一致、終了コード 1 を確認。

参照実装・ゴールデン PNG・期待値・検出の式と既定値は変更していない。

### 分類例

| ケース | kind | 理由 |
|---|---|---|
| D01 小数点削除、D02 マイナス削除 | removed | A のインクだけ |
| D03 数字変更 | changed | 追加・削除・両方が混在 |
| D07 青→赤の線 | color_changed | 両方にインク、元の形状が一致 |
| D09 淡いセル塗り | changed | インク基準を満たさない差分 |
| D10 マーカー追加 | added | B のインクだけ |
| D14 線の濃淡変更 | changed | 元のインク形状に 4px の差 |

D14 は生差分の 1,418px が両方のインク上にあるが、連結成分内の膨張前のインクに 4px の差がある。色の変化でもインクしきい値をまたぐため、採用した保守的な仕様では色変更と断定しない。これは検出を落とした結果ではない。

## 時間とメモリ

T1-4 と同じ合成 A4・300dpi・2480×3508px・数字 600 文字を使用。画像生成・PDF 描画・ファイル I/O は対象外。Release 構成。各シナリオで測定前に 2 回の検証実行を行い、測定前に GC を実行する。検出マスク・クラスタ・統計の一致も確認する。

既存の最適化前後計測を 3 回ずつ再実行した。分類ありの最適化後中央値は、完全一致 **5.0ms**、1 か所変更 **219.3ms**、変更＋全体 1px ずれ **230.9ms**。[全サンプル](t2-1-a4.json)。

分類による影響は、最適化後の比較を分類なし／ありの別プロセスで各 5 回計測した。両者は同じ実装の内部計測経路で、製品設定として分類を無効化するオプションは設けていない。

| ケース | 分類なし中央値 | 分類あり中央値 | 分類部分（全体中央値の回） |
|---|---:|---:|---:|
| 完全一致 | 5.1ms | 5.9ms | 0ms |
| 1 か所変更 | 221.4ms | 224.5ms | 1.02ms |
| 変更＋全体 1px ずれ | 232.7ms | 233.8ms | 0.82ms |

全体時間の差には実行間の揺れも含む。分類部分は両方の変更ケースで約 0.8〜1.0ms。変更を含む比較も目標の 2 秒以内。完全一致・ノイズだけ・差分過多では分類を省略する。[分類なし](t2-1-classification-off.json)、[分類あり](t2-1-classification-on.json)。

変更ケースの分類処理のマネージド割当量は各 **8,715,928 bytes（約 8.31MiB）**、保持するネイティブ削除マスクは **8,699,840 bytes（約 8.30MiB）**。前者は ROI の配列等を含むスレッド別割当量で、後者は戻り値が所有するマスクだけ。一時的な Mat やプロセス全体のピークとは異なる。削除画素がなければ削除マスクは作らない。

同じ別プロセスの `/usr/bin/time -l` による最大 RSS は、分類なし 2,150,121,472 bytes、分類あり 2,167,947,264 bytes（差約 17.0MiB）。[記録](t2-1-memory.json)。これは入力画像・検証用の比較結果・GC・ネイティブ一時領域を含む計測プログラム全体の各 1 プロセスのピークであり、分類単体や CLI 1 ページ当たりの最大メモリではない。広く散在するクラスタではインクを計算する ROI も大きくなるため、この 1 か所変更の数値を一般化しない。
