# T3-1b：比較用の帯を両側とも白にする案の検証

2026-09-22。基準は v0.1.3（`f77ac1c`）。前回の停止後、「次に進んでください」の指示を受けて、[継ぎ目対策の第一候補](t3-1b-row-seams.md)を独立した試行で検証した。

**この案は不採用。** 継ぎ目の偽差分は消えるが、帯のすぐ外にある、本来検出できる濃淡変更まで消える。製品の実装、比較式、設定の既定値、既存の検出期待は変更していない。T3-1b は未完了のまま維持する。

## 比較したもの

前回と同じ PageMap に、既知の正しい帯の対応を与えた。挿入・削除に対応する片側帯だけを比較専用コピーの A/B でともに白くし、既存の 5 章の比較器へ渡した。帯の内側の生差分を除外する処理も維持する。

| 比較 | 入力 |
|---|---|
| 基準 | 行を挿入する前の A と、内容変更だけを加えた B。白い詰め物なし |
| 従来案 | 行を挿入した B を正しい PageMap で整列。片側だけの白い詰め物と、帯の内側の除外 |
| 今回案 | 従来案の表示用 A/B から作ったコピーで、対応のない帯を両側とも白くする |

基準 B を A と同じ写像でキャンバスへ運ぶと、帯の外側の全画素が整列後 B と完全一致することを検査した。基準との違いは、対応しない帯と、その追加によって変わる近傍だけである。

さらに次をプログラム内で検査した。

- 白くしたのは整数 px で指定した帯の内側だけ。コピー前後の、帯の外側の最大画素差は 0。
- mm→px の floor / ceil 後の除外範囲が、意図した整数の帯と一致する。
- 元の A/B、表示用の整列 A/B、元画像から作る raw evidence の PNG SHA-256 は試行の前後で不変。
- Mat はすべて所有側で破棄し、PDFium は逐次描画する。

## 検証条件

- 合成画像 30 条件：6px 幅の黒い縦罫線の一部 6×2px を RGB(64,64,64) へ変更。境界からの距離 0 / 1 / 2 / 4 / 8px × normal / strict / loose × A/B の両方向。
- 合成 PDF 42 条件：7 場面 × 3 プロファイル × 両方向。7 場面は、挿入のみ、挿入＋離れた合計の数値変更、境界から 0 / 1 / 2 / 4 / 8px の濃淡変更。
- PDF は前回と同じ埋め込み Type3 フォント、300dpi、999×1250px。挿入は y=400px の高さ 100px、整列後の境界は y=500px。縦罫線は 1.44pt（6px）、濃淡変更の高さは 0.48pt（2px）。

この「PDF 42 条件」は新しい試行の数であり、既存の 42 ゴールデンの再実行ではない。

## 結果

normal / loose の両方向で、次の結果となった。表は `生差分画素数 / クラスタ数`。画像と PDF の濃淡変更で同じ現象を確認した。

| 場面 | 基準 | 今回案 | 判断 |
|---|---|---|---|
| 挿入のみ（内容変更なし） | 0 / 0 | 0 / 0 | 従来案の偽差分 8 / 2 は消える |
| 挿入＋離れた合計数値変更 | 69 / 1 | 69 / 1 | この内容変更は残る |
| 境界から 0px の濃淡変更 | **4 / 1** | **0 / 0** | 本物の変更を見逃す |
| 境界から 1px の濃淡変更 | **4 / 1** | **2 / 0** | 残った差分が既定のノイズ条件で落ちる |
| 境界から 2 / 4 / 8px の同じ濃淡変更 | 4 / 1 | 4 / 1 | この条件では残る |

strict では濃淡変更がいずれも 12 / 1 のまま残った。strict を強制して既定の比較結果を変える対応は採らない。

検出が失われた条件は画像で 8 条件、PDF でも 8 条件（距離 0 / 1px × normal / loose × 両方向）。基準では `color_changed` の通常クラスタとして検出されていた。

PDF 42 条件について、基準・従来案・今回案の **計 126 回**を Python 参照実装と照合した。生差分マスクの全画素、状態、生差分数、ノイズ数、吸収数、最大ずれ、クラスタ数・矩形・画素数が C# と一致した。C# の分類名は観測値として保存し、分類のない Python との比較対象にはしていない。

## 原因

変更画素そのものは白く塗り潰していない。例えば基準 `(x=102,y=400)` と整列後 `(x=102,y=500)` では、どちらも A は黒、B は RGB(64,64,64) のまま。

違いは 5×5 の局所コントラストである。元の罫線の中では比較的低いしきい値で濃淡変更を検出できるが、近くに両側共通の白い帯を作ると局所コントラストが増し、一段目のしきい値が上がる。ぼかし後の差がそのしきい値を下回るため、実在する変更が候補にならない。距離 1px では半分だけ残り、クラスタ化時の最小画素数に届かない。

| 同じ変更画素での計算 | ぼかし後の L の差 | 判定しきい値 | 候補になるか |
|---|---|---|---|
| 基準 | 約 17.99 | 約 11.10 | なる |
| 今回案 | 約 17.99 | 33.00 | ならない |

今回の例で 2px 離すと残ったことを、一般的な「2px の余白で安全」という条件にはしない。二段目の探索、インクの局所背景、連結成分、領域ごとの設定も関与するため、その距離だけで採用を保証できない。

## 採否と再開位置

[CLAUDE.md ルール 2](../../CLAUDE.md)の「『無視必須』のテストを通すために『検出必須』のテストを緩めない」に従い、この方式を製品へ採用しない。しきい値の変更、最小クラスタ画素数の引き下げ、境界の強制 strict 化、見逃しの期待値への変更も行っていない。

次の検討候補は、元画像の近傍を使って計算した特徴量を帯の写像へ渡す方式。少なくとも今回の反例を維持したまま、5.2 のぼかし・局所コントラスト・インクと、5.3 の探索・group がどの画像座標の近傍を参照するかを定義する必要がある。これは未設計・未検証で、採用を決定したものではない。

後続の「次の検討候補に進んで」による検証は [特徴量写像の検証結果](t3-1b-mapped-features.md)に記録した。この文書と JSON は、白い帯の案を検証した時点の証跡として保持する。

本物の差分が消える反例で今回案を棄却したため、採用に向けた追加の文字／小数点／細線／色相・塗りの網羅、複数挿入、regions / exclude の境界、既存 42 ゴールデン、A4 性能、Windows 配布物の検証には進んでいない。前回保留した R01〜R09、行の推定・支持・一意性、設定・出力・HTML・YAML の実装も未完了。
