# 末尾の片側ページと独立した送り原因の検証

2026-09-26。[事前方針](../planning/t3-1c-unpaired-components.md)に従い、16ケース32PDF・111物理ページを生成してA/B両方向を検証した。**32方向の当初期待が一致し、追加の8方向が診断上成立した。製品へは未接続**。単一R11の受け入れを、新しい複数原因の一般化と混同しない。

後続の承認により、この8方向の[製品接続とローカル自動検証](t3-1c-unpaired-integration.md)を実施した。本書とJSONは接続前の診断記録であり、下記の「現CLI」は当時の実行ファイルを指す。再現ツールは接続後の製品結果も別項目で照合する。

既存成功4方向と追加候補8方向の計12方向で集約し、20方向を見送る。新規8方向では `PageFlowNonflow` が全ページ対応を要求するため、現製品は `unverified_candidates` で停止する。診断では、未一致候補の各行が反対側の同じ物理ページへ対応し、その境界を跨ぐ共通行がないことを証明すると、既存の写像・支持・改善率まで成立した。その後も現製品の複数成分集約は片側ページを対象外にしているため、診断だけで成分ごとの既存単一原因検査を適用した。

独立二原因と帯外残余が併存する4方向は、末尾レイアウトの規則性を満たさず非送りの追加診断へ進まない。残余だけで失敗を再現した単一R11の4方向、および成立入力の片側残余証拠を取り消す監査と区別する。前段で止まった例を、後段の残余判定の実行証拠として数えない。

## 画像・内容・網羅性

自作Type3の文字層付きPDFを300dpiで実描画した。正解の本文行列は生成記録と検証器だけが使用し、推定器へ渡さない。固定した入力SHA-256を保存し、既存のPDF・ゴールデン期待は変更していない。

Pythonの検証器は、元O画像からC/Dを再構成し、送り帯を全画素比較した。片側ページは全幅の固定部・送り帯・それ以外に分け、BGRのいずれかが255未満の画素を全て残余へ数える。固定部も他ページの元画素と照合した。本文のページ跨ぎから別にグラフを作り、編集列から原因を求めて、製品Coreが生成した実構造IDと各ページの収支へ突き合わせた。

| 検証 | 確認数 |
|---|---:|
| 既存Python参照とのC生差分マスク・件数 | 52ページ |
| 元画像から再構成したC/Dカラー画像 | 208枚 |
| C/D生差分マスク | 104枚 |
| 元帯の全画素一致 | 60組 |
| 同一ページ対応の非送り境界 | 8方向 |
| 診断で比較した実構造 | 142件 |
| 独立した編集列から確認した原因群 | 20群 |
| 片側ページの残余確認 | 残余0の14ページ、残余ありの12ページ |

残余0の14ページには、同一連鎖二原因で写像が成立しなかった2方向も含む。片側ページの残余0だけを文書全体の採用に使わない。残る8片側ページは固定部不足・固定部変更・空本文等で範囲が未確定のため、確認済みとしない。

内容の濃淡差は元PDFに描いた灰色文字であり、読込後のメモリ画像を変更していない。両方向ともC1に2,462px・1クラスタ、他のCには0。Dの投影で画素を落とさず、集約でも1内容件数を保持した。

## CLIと破損入力の監査

各32方向について、送り無効／有効を別の実CLIプロセスで実行した（64プロセス、全て終了コード1）。元A/Bとraw overlayの384画像が無効／有効でバイト一致し、うち存在する元入力222画像を診断のO画像とも全画素照合した。全ページの既存結果は送り見送り時に完全一致した。

片側ページは `only_in_a/b`、構造0・クラスタ0、未比較を保持。全方向で既存と集約後の網羅性はfalse。診断だけの原因群や補助帯をCLIの成功結果へ書き込んでいない。新しい8方向は実CLIでは19→19、診断候補とは別に記録した。今回、実ブラウザーは操作していない。

保存した集約入力を再読込し、行・ページ・リンク・構造の欠落／重複・座標破損、除外構造、残余証拠の取消、選択省略、ゲート失敗の**2,184条件を拒否**した。36列挙順で結果一致、44条件で追加した内容クラスタが1件ずつ残ることを確認。全ページにcomplete=trueを渡す12条件でも片側ページによる網羅性falseを維持した。集約不成立時に成功済みの他成分だけを残すことはない。

この監査の集約器は、診断用の成分分割と既存の単一原因検査を組み合わせている。独立した採否正解はPythonの編集列・元画素照合で確認した。製品の証拠型・資源予約・保存へ接続したテストではない。
