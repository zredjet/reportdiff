# T3-1c 同じ送り連鎖の複数原因の製品接続

2026-09-23。承認済みの[接続方針](../planning/t3-1c-shared-causes.md#製品接続の具体案)をCore・CLI・JSON・HTMLへ反映した。二挿入に付随する移動・送りを実構造IDのまま保持し、内訳7件を2原因へ集約する。色変更があれば8→3、独立原因との併存は12→3。前段の候補推定・元帯全画素一致・支持・C/D・採用評価とraw overlayは変更していない。T3-1c全体は未完了・未コミット。

## 出力と予算

従来の単一原因・独立成分が成功した結果を先に返し、それらが不成立の場合だけ共有原因を検証する。全ページが対応し、同じ成分内は同符号、一定行間隔・開始位置、共通行の順序と所属、累積移動量・送り量・ページ収支・実構造の一意な所属が成立することを要求する。実構造や帯を分割して原因を作らない。一成分でも不足すれば全成分を取り消す。

`page_flow.aggregation.shared_components` は成立時だけ出力する。原因・実構造・各移動と送りへの寄与原因・収支を持つ。`delta_px` と `dy` は全体補正後Gの座標で、`coordinate_system: globally_aligned` を明記する。既存の元矩形・送り帯画像はOのまま。HTMLの原因・移動・送り参照から実構造と元帯へ移動できる。原因k件・構造n件の成分について `U - Σ(n - k)` を適用し、内容クラスタ・網羅性・終了コード1を維持する。

共有検証の索引・原因・寄与参照は、元の文書記述・数値対応・非送り証明を差し引いた64MiBの残りへ確保前に計上する。[SPEC 11.8](../SPEC.md#118-隣接ページへの送りと文書集約t3-1c開発中)に計上式を記載した。上限ちょうど／1B超過を固定入力と実PDFのPlanの両方で確認し、超過時は `shared_descriptor_limit` として全集約を取り消す。確定済みの内容比較は残す。記述計上量はRSS上限ではない。

## 保存入力と最終ソース

固定26＋保存済み104の計130集約入力を製品Coreへ再生し、既存期待および共有原因の独立モデルの採否・件数・原因集合・寄与・収支と一致した。共有原因は計14入力。全ページ対応の成功入力に対する監査は列挙順210、破損拒否6,374、網羅性132、内容保持132の計6,848条件。片側ページは採否・件数の再生に含めるが、全ページ対応用の破損監査へは含めない。

最後に追加した整数長合計の防御条件を含む最終ソースで、固定26方向の1,154ファイルと数値50方向の1,594ファイルを再生成し、独立照合済みの出力と日時以外一致した。製品は既存102ファイル中5ファイルの変更とCore1ファイル追加。候補推定・採用評価・数値対応・支持・比較面・RawOverlay等、残る97ファイルのSHA256は接続前と一致する。新しい設定と製品依存は追加していない。
