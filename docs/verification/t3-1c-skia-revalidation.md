# V-02：既存Skia入力を現在の製品で再検証

2026-09-27。[進捗台帳](../PROGRESS.md)のV-02を実施した。初回の[CLI接続](t3-1c-cli-integration.md)で使用したSkia生成PDFを現在の製品で再実行し、元の独立期待と保存済み出力を維持した。**V-02は完了。T3-1b／T3-1c全体の完了・コミット・公開にはしない。**

## 対象を固定

- Skia絶対座標の12組24PDF、28条件（両方向24条件＋ページ選択4条件）。
- Skia行内座標の3組6PDF、両方向6条件。
- 合計30PDF・34条件を、送り無効／有効でそれぞれ実行し、計68プロセスを検証した。rowsとraw overlayは両方で有効。
- 元のPDFは再生成せず、初回接続の機械可読記録にある30PDFと、観測・候補・独立集約の6JSONのSHA-256を確認した。
- 旧出力は `out/t3-1c-cli/matrix-final/` の同じ条件を使用。送り有効34条件のJSON／HTMLは初回記録のハッシュとも一致した。新しい出力を旧結果の代用にしていない。

今回の入力は既存のSkia検証用合成PDFであり、残件R-02のA4用紙9条件や実帳票の代わりにはしない。

## 網羅性の比較と初回停止

最初の検証スクリプトは、ページ選択の条件で `summary.difference_count_complete` を独立集約の同名項目と直接比較して停止した。旧新の製品出力はこの時点でも一致していた。

既存のsummaryは比較対象ページ内の網羅性、`page_flow.aggregation`は選択外を含む文書全体の網羅性を扱う。例えばページ1・3だけを選んだ場合、前者はtrue、後者と集約後の網羅性はfalseとなる。検査をそれぞれの契約へ分け、元の期待値や製品コードは変えず、新しい出力先で全34条件を実行し直した。

初回の12プロセスは最終68実行の件数へ加算しない。失敗ログと未完了の記録も保持した。最終 `cli-final/verification.json` の `completed: true` を完了根拠とする。

## スナップショットと残件

製品・テスト・固定入力544ファイルは、前工程の全2,375テスト成功時と開始前・終了後ともSHA-256が一致した。新しく実施したのはReleaseビルドと上記実CLI検証であり、全2,375テストを今回再実行したとは記録しない。比較式・しきい値・製品コード・元入力・期待値の変更はない。

入力・独立期待・CLI実行ファイル群・旧出力の事前スナップショット、全実行ログ、最終出力ハッシュを `out/t3-1c-skia-revalidation/` に保存した。[機械可読記録](t3-1c-skia-revalidation.json)には集計、各条件の結果、検証ソースと証拠のハッシュを記載する。

Windows、実ブラウザー、実帳票、A4用紙の未成立9条件、支持不足2方向、薄色1px線2方向は今回の対象外で、従来の状態を維持する。静的なHTML照合を表示操作の合格にはしない。
