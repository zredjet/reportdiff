# T3-1c 全体補正と送り座標の合成の事前検証結果

2026-09-23、macOS arm64。**縦方向の整数補正について、元帯の全画素一致と既定の採用条件を維持した合成が、独立ツール内で成立した。製品CLIへの接続はまだ行っていない。** [検証範囲](../planning/t3-1c-global-composition.md)、[機械可読記録](t3-1c-global-composition.json)を参照。

## 入力と受け入れの境界

既存の固定R10／3ページ連鎖の4PDFから描画と文字を読み、整数移動した合成ラスタを試験入力にした。元のPDFを変更・再生成していない。補正は製品の `GlobalAligner` で推定し、移動量の正解を推定器や送り候補へ渡していない。設定のしきい値は既定のまま。

元のR10では送りによる画像差のため、全体補正のスコアが約0.9797／0.8647となり、既定0.98に届かなかった。3ページ連鎖も中間ページだけ補正を採用し、文書全体の送りは成立しない。この結果を残したうえで、上下に256pxの白余白と固定模様を加えた**別の合成対照**を作った。元の本文・フォント・行数は保ち、文字座標も余白分だけ移した。追加模様はPDFから抽出した文字とは重ならない。

固定模様の対照では、全体補正の既定スコア・一意性・複数箇所の支持条件を満たした。これは実帳票や通常のA4の成立証拠ではない。前工程のA4未成立9条件、Windows、保留中のブラウザー確認を受け入れた扱いにしない。

## 結果

18条件・38対応ページを実行し、診断上の採用10条件／見送り8条件だった。採用10条件には、全体補正量0の対照1条件を含む。非ゼロの全体補正と送りが両立したのは9条件。すべて事前に置いた期待と一致した。

| 条件 | 条件数 | 結果 |
|---|---:|---|
| 固定模様を加えないR10／3ページ連鎖 | 2 | 全体補正の低スコア等により送りを見送り |
| 固定模様あり・移動なし | 1 | 送りを採用、5→1 |
| 縦+4px／−6px、A/B逆向き、ページ別補正、補正不要ページとの混在 | 5 | 元帯を検証して採用、各5→1 |
| 3ページ連鎖・ページ別補正 | 1 | 各補正量を独立に適用し8→1 |
| 対応本文に10×10pxの濃淡変更 | 1 | 変更100px・1クラスタを保持し6→2 |
| 同じ本文変更をA基準の指定領域で除外 | 1 | 指定した内容差だけ除外し5→1 |
| 本文変更の領域を厳密条件で比較 | 1 | 変更100px・1クラスタを保持し6→2 |
| 横方向／両軸の補正 | 2 | Cは構築できるがB端点の元全幅帯を証明できず、送りを見送り |
| 送り帯の濃淡変更、同じ帯に除外を指定 | 2 | どちらも元帯の画素差を検出して見送り |
| 補正で切り落とす端に254の1画素を追加 | 1 | 2ページ目の全体補正が `edge_content`、送りも見送り |
| 4.5pxの入力移動 | 1 | 既定スコアを満たさず見送り |

「採用」「集約」は独立ツールの判断であり、現在のCLI結果ではない。横／両軸対照の候補Cは相違0、候補の論理集約も5→1になったが、**元帯の証明がないため、この件数を採用結果にしていない**。

## 座標合成と元画像の監査

全体補正後の共通座標をG、元A/BをO、内容面をC、表示面をDとした。Bへの全体補正が `(gx,gy)` の場合、Gから元Bへは `(x-gx,y-gy)` で戻す。C/DのB開始位置へ `-gy` を加え、横補正は一度だけ適用する。

- 38ページの入力生成とO→Gを、保存された既存PNGとNumPyから独立に再構成した。元画素と補正後画素の両SHA256が一致した。
- 1,448語の矩形・ベースラインについて、全体補正が一度だけ適用されることを照合した。
- 構築できた25ページのC/Dで、「Oから合成写像で直接描く結果」と「O→G→C/D」が全画素一致した。Dには元の非白画素をすべて保持し、Cの判定マスクをDへ写しても判定画素数は変わらない。二重補正の対照は一致しない。
- 63件の実構造IDと内容クラスタについて、補正後の元範囲をOへ戻した部分矩形を独立に照合した。A/B逆向きでは挿入／削除と行移動の符号が入れ替わった。
- 元全幅帯11組を元画像から切り出し、両端・両順序・既定／厳密／緩和等の既存置換検証132比較で差分0を確認した。送り帯の変更は、除外の指定があっても全画素一致を満たさず拒否した。
- 補正後画像を元画像の記述へ渡した28条件、元画素を変更して再読込した38条件は `flow_original_changed` で拒否した。各ページの比較後にも元画像のハッシュを確認した。
- 元座標のリンクをGの本文・構造へ混ぜた9条件は `flow_band_balance_not_proven` で集約を見送った。集約を成立させるために原座標の検証を省略してはいけない。

通常設定のCは23ページで既存Python参照実装とマスク全画素・画素数・クラスタ数が一致した。除外／領域を持つ2ページはこの参照比較へ混ぜず、変更矩形中心の検出・除外、元入力とC/D・元矩形の独立監査で確認した。全領域機能を今回新たに受け入れたわけではない。

## 製品接続へ引き継ぐ条件

元画像の記述と補正後の記述は別物である。補正後の帯で証明が成立しても、元帯を別に証明できない横補正の例がある。逆に元帯・元構造の座標をそのまま既存の因果集約へ渡すと、全体補正を行送りと誤解するため集約は成立しない。

次は、[縦方向の補正に限定した接続案](../planning/t3-1c-global-composition.md#製品接続へ進むための案)に沿って、Oの元帯・証拠とGの論理集約を別に保持する。横方向、片側ページを含む補正文書、元帯のクリップ、不確実な対応は従来の見送りを維持する。固定模様なしの不成立例を、しきい値の変更や既知の移動量で採用させない。

## 再現と検証状態

保存先は `out/t3-1c-global-composition/final-verified/`。`global-flow.json` は各条件の推定値・元帯検証・採用・C/D・構造と集約、`audit.json` は独立監査、`reference.json` はPython参照一致。各条件ディレクトリにO/G/C/D、元帯、文字座標を保存した。これは診断資料であり、製品レポートではない。[再現手順](../../tools/ReportDiff.PageFlowProbe/README.md#全体補正と送りの座標合成の事前検証)を参照。

ツールのReleaseビルドは警告・エラー0。製品99ファイルは全1,806テスト成功時のSHA256と一致し、今回は全テストを再実行していない。製品の依存・設定・公開API・レポート形式は変更していない。現CLIは引き続き、全体補正を採用した文書の送りを `global_alignment_applied` で見送る。

原PDFからの変形・描画、実CLIの分岐・出力・raw overlay不変性、保存失敗、資源上限、追加時間・RSS、Windows・実帳票の受け入れは製品接続時以降の確認が必要。T3-1c全体は未完了・未コミット。
