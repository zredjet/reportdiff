# 片側末尾へ続く共有原因：旧入力の前側支持1行の診断

2026-09-27。[前工程の限定接続](t3-1c-unpaired-shared-integration.md)で残った `original-ab/ba`（旧 `shared-unpaired` と同じPDF）の停止箇所を切り分けた。結論は、局所構造帯の検査だけを通しても、後段の既存採用検査が1行支持の移動区間を拒否する。正例の期待は維持し、製品対応済みにはしない。

## 診断方法

14ケース28PDFを同じ生成手順で再現し、固定入力とのバイト一致を確認した。製品の `PageFlowSurface` や支持数の設定は変更しない。診断ツール内だけに数値対応なしの写像作成手順をコピーし、次の内部帯を仮の原因として置ける分岐を加えた。

- 規則的な本文の内側にある1行分の未対応帯で、同一ページの前側支持が1行、後側支持が2行以上。
- 同じ側のページ先頭には、直前ページから届く画像検証済みの送り帯があり、仮の原因と重ならない。
- 仮置きには `experimental_single_before_cause` を記録する。送り帯を同一ページの支持行へ加算せず、製品の局所構造証明と区別する。

14ケースのうち、この分岐を使ったのは元ケースの2方向だけ。各方向の2ページ目・拡張側のy=500、高さ100pxの第2原因が該当した。製品の候補・元帯の検証・範囲条件・内容比較・採用検査はそのまま使用した。診断用計画はCLIへ渡していない。

## 結果

| 段階 | A→B／B→Aの結果 |
| --- | --- |
| 現製品の局所構造帯 | 前側1行・後側3行で `unverified_structural_band`、従来結果を保持 |
| 第2原因を仮置きした診断写像 | 両対応ページのC/D作成・範囲検査が成立 |
| 診断の内容比較 | 各方向2ページとも生差分0、内容クラスタ0 |
| 1ページ目の既存採用検査 | 成立。支持帯数 `[4, 3, 2]`、改善率1 |
| 2ページ目の既存採用検査 | `insufficient_support / support_bands` で不成立 |
| 文書全体の診断採用 | 不成立。成功した1ページ目だけを採用しない |

2ページ目の同一ページ対応は、`ITEM GGGG` が100px移動の1行、`ITEM HHHH / IIII / JJJJ` が200px移動の3行となる（A/B反転では符号が反転）。最低支持帯数は既定の2を維持している。直前ページから届く `ITEM FFFF` は別ページとの対応であり、GGGGと同じ局所移動区間の独立支持には数えない。後段は支持帯数で停止するため、その区間の画素再探索・インク支持・改善率が合格した証拠ではない。

内容差分0は、仮定した対応で作った画像の比較結果である。その対応を採用してよいことまで証明するものではなく、製品の結果は引き続き未集約10／集約10のままとする。

## 検証と変更範囲

- 固定28PDFは前段・固定fixtureとバイト一致。製品計画28方向も前段と一致。
- 元ケース以外の26方向は診断JSONの全フィールドと266画像が一致。支持位置6／9／10、送り帯変更、残余、固定部変更、反復本文、数値変更等の対照を維持した。
- 元ケースの実送り4組は元BGR全画素一致。候補、置換比較数、残余、局所支持の記録は前段と一致。
- 保存された写像を正解表として流用せず、元ケース用の独立した座標表からC/Dを再構成した。16カラー画像・8マスクが一致し、Dは元画像の全走査行を一度ずつ保持する。
- Python参照比較器による4ページの生差分マスクも一致した。
- 診断プローブのReleaseビルドは警告0・エラー0、1.86秒。製品・テスト・固定入力544ファイルは、前工程の全2,375テスト・ゴールデン40ケース成功時とSHA-256が一致した。今回、製品全テスト・CLI・ブラウザーは再実行していない。

今回の変更は診断ツールと文書だけ。機械可読の結果・証拠ハッシュは[検証記録](t3-1c-unpaired-local-support.json)に保存した。未成立ケースの期待やSPECの支持条件は変更していない。

## 再実行と再開条件

`out/t3-1c-unpaired-local-support/source-before.json` は前工程の `source-tested.json` と同じ544ファイルのスナップショット。次の出力先は未使用のディレクトリを指定する。

dotnet tools/ReportDiff.PageFlowProbe/bin/Release/net10.0/ReportDiff.PageFlowProbe.dll \
  --unpaired-local-support out/new-local-support/diagnosis
out/t2-4a/reference-env/bin/python tools/ReportDiff.PageFlowProbe/check-unpaired-local-support.py \
  out/new-local-support/diagnosis out/t3-1c-unpaired-shared-integration/diagnosis

チェッカーは新出力先の親に `source-before.json` を必要とする。製品接続前の診断結果や別の入力へ暗黙に差し替えない。

現行のページ内支持契約のまま、今回の前段の例外だけを製品へ追加しても元ケースは採用できない。再開時は、別ページの送り証明と局所移動の支持を混同しない証拠設計から検討する。1行へしきい値を下げる変更や、同じ画素を二重に支持として数える変更は行わない。T3-1c全体、旧入力2方向、既存のA4等の未成立と環境別受け入れは未完了のまま残す。
