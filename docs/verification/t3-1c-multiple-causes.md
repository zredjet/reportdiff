# T3-1c 複数原因の分離と非送り境界の独立検証

2026-09-23。[設計](../planning/t3-1c-multiple-causes.md)に基づく独立検証を完了した。異なるページ群で完結する単一原因を別グループに分ける限定案が成立した。製品C#95ファイルとプロジェクト4ファイルは不変で、製品CLIへはまだ接続していない。数値・入力・ソースハッシュは[検証JSON](t3-1c-multiple-causes.json)に保存した。

## 前段の問題と境界の証明

最初に独立したページ群を持つ12ケース・24方向を実行したところ、集約を期待した12方向が文書ゲートで不成立となった。現在の候補推定は、最後の行が同じページ内へ対応済みでも、正の行ずれから次ページへの候補を作る。その文字不一致が `unverified_candidates` になっていた。最初の失敗記録は `out/t3-1c-multiple/first/` に保持した。

追加した独立検証は、`text_mismatch` 候補の両端全行が同じ物理ページの相手側へ一意に対応し、どの共通行もその境界を跨がない場合だけ「送りではない」と証明する。全文の順序・一意性、対応ページの連続性、帯を隙間なく埋める行範囲も要求する。未検証の候補をまとめて捨てる処理はしていない。

この分類は画素を無視する証明ではない。該当帯は内容比較Cへ残る。末尾の色変更対照では、元の本文位置にある**2,850画素の生差分と1内容クラスタ**がC/Dに残った。末尾文字555→556、反復本文、同一ページ対応先の欠落、実送りを誤ってこの分類へ入れた負例は拒否した。元帯のBGR全画素一致と置換比較の条件は変更していない。

ツールは既存Coreが構築したC/Dと検証済みの帯をそのまま使い、証明できた非送り候補だけを文書ゲートの独立再評価から外す。反射による `PageFlowPlan` の生成は診断ツールだけの処理であり、製品接続案には含めない。

## 合成PDFと実CLI

自作Type3の28PDF・114ページを生成し、14ケースをA/B両方向の28実行で確認した。製品から独立した処理が、PDFの描画・文字抽出・候補推定・元帯検証・既存の行採用条件を経て、実構造IDと比較結果を取得する。生成時の期待本文やケース名を境界・集約器へ渡していない。元帯の置換比較は計600回。

文書の独立ゲートは20実行で成立し、そのうち14実行で分離集約、6実行で因果条件により集約を見送った。残る8実行は範囲・画像証明等の段階で見送った。28実行すべてが検証前に固定した採否期待と一致した。

## 独立照合と安全網

Python側は推定リンクの成分を流用せず、**共通する本文行が実際に跨いだページ**から成分を再構成した。編集列の挿入／削除区間から原因を求め、実構造IDの集合・各成分のページ・集約後件数を照合した。14採用実行の30グループが一致し、重複所属はない。

- 82ページのC生差分マスク・生差分数・内容クラスタ数が既存Python参照と一致。
- 元画像からC/Dの328画像を再構成して全画素一致。Dは元の非白画素数を保持し、CのマスクのDへの転写も一致。
- 208の実構造ID・投影結果を照合。
- 24の非送り境界について、全行の同一ページ対応と跨ぐ共通行がないことを独立確認。
- 生成PDFの元画像と実CLIのraw A/B画像228組が一致。今回raw overlayの全バイト比較は再実行していない。画像生成の製品コードは不変。
- 末尾色変更の表示画像を目視確認。PDFの文字はOSフォントに依存しない自作幾何グリフで、Unicodeの文字層を持つ。
