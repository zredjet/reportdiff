# T3-1c：Skia入力と文書単位の範囲確定

2026-09-22。[今回の方針](../planning/t3-1c-document-gate.md)に従い、Skia生成PDFと、構造写像が部分的に失敗する場合を独立ツールで検証した。**行内座標を共通にしたSkiaのR10・R11・3ページ連鎖が成立し、一つの範囲・写像が欠ければ文書全体を従来比較へ戻せた**。製品の送り・因果集約は未実装。T3-1cは未完了・未コミット。

## Skiaの入力と実際の罫線差

SkiaSharp 4.150.1の`SKDocument`から30PDF・72ページを生成した。既存の最小TrueType試験コードを基に自作ASCII字形を作り、`SKTypeface.FromData`から読み込む。OSフォント、代替フォント、追加パッケージを使わず、Type3の文字ストリームを後付けしない。

全ページでType0／CIDFontType2・埋め込みFontFile2・ToUnicodeを確認し、ヘッダー・本文・フッターの全文字列をpypdfでも期待と照合した。Popplerで全72ページを描画し、改ページ、固定部分、罫線、濃淡変更、追加の塗りがページ内に収まることを目視した。字形は試験用の図形であり、一般の和文フォントの描画品質を代表しない。

最初の24PDFはページの絶対座標で矩形を描く。R10・R11・連鎖の候補座標は正しく求まったが、送り前後の横罫線が794画素異なり、全画素一致を通らなかった。PDFの内容ストリームに次の高さが出力されていた。

```text
送り元の横罫線: 24 212 192 .47999573 re
送り先の横罫線: 24  92 192 .48000336 re
```

元のC#はどちらも高さ`.48f`を指定している。描画された帯を比べると、相対y=85、x=106〜899の1行が異なり、最大チャンネル差は255。文字の不一致ではない。現行コアでもこの差をnormal／looseで2,376画素、strictで794画素として検出する。単に完全一致条件が厳しすぎて止まったケースではなく、通常比較にも残る罫線差である。

失敗した24PDFは修正せずハッシュを固定した。別の6PDFでは、各行を`canvas.Translate`で配置して行内の描画座標を共通にした。こちらは送り5帯が両順序で全画素一致し、14対応ページの比較面Cも3プロファイルですべて生差分0となった。Skiaという生成器名で採否を分岐せず、同じ推定・画像検証を使っている。

絶対座標版を成功入力へ置き換えたり、罫線差を無視するよう比較式を変更したりしていない。実際の画素が変わる入力は、引き続き送り認定の対象外になる。

## 文書単位の確定と部分失敗

`DocumentGate`は候補・各ページの構造写像・両端の範囲がそろった場合だけ、検証済みリンクと比較面を選択する。未確認候補がある、写像が作れない、範囲が欠ける場合は、選択リンクを0件にし、成功したページを含むすべての対応ページで基準のRowComparer結果を選ぶ。Matを全文書分保持せず、ページ処理後の範囲と画像参照だけで確定する。

前回のType3の36実行について、新しいgateと選択画像の項目を除き、候補・写像・差分・基準値が以前の記録と完全一致した。

- 125px間隔のR10と連鎖は、最終ページの非白1pxを理由に一部の写像が作れない。両順序の4文書では、成功していた6比較面も採用せず、全10対応ページが基準マスクへ戻った。
- この4文書には画像一致したリンクが6件あり、うち2件は両端の範囲自体も成立していた。それも単独採用せず、選択リンク0件とした。
- 70実行中20実行で範囲確定が成立し、32リンク・44対応ページのCを選択。残る50実行は文書単位で見送り、102対応ページが基準マスクを選択した。
- 全146対応ページで、選択マスクが選択元のPNGと全バイト一致した。基準の箇所数は診断データに維持する。製品のJSON／HTML全体の互換性や集約後の件数を、この試行で受け入れたという意味ではない。

`gate.ready`は範囲の確定だけで、原因が同じことや「内容変更なし」の宣言ではない。Type3の対応本文の濃淡変更と挿入境界の変更は、gateが成立してもCのクラスタとして残った。

## 負例と片側ページ

Skiaの文字変更は文字不一致、同名反復は`repeated_body_text`として見送った。本文先頭2行を全ページで反復させる入力では、固定部分候補へ取り込んだ後の本文の画素範囲と行間隔が整合せず、`unproven_body_bounds`で見送った。ただし、この1例によって本文と固定部分の意味の曖昧さを一般に解決したとはみなさない。

片側ページは全例で`only_in_a/b`・`difference_count_complete=false`を維持する。Skiaの行内座標版R11は、送り帯と共通の固定部分の外に非白画素がないことを確認した。絶対座標版では帯自体が未確定なので、片側ページ全体を確認済みにしない。Type3の余分な塗り3,570画素、境界変更60画素の検出期待も維持した。

Skiaの最終ページに塗りを足した入力は、前段の罫線不一致でも見送りになるため、単独では「最後の写像失敗による全体見送り」の十分な証拠にしない。その条件は、前述のType3の実入力と、次の根拠欠落の検査で確認した。

## 検証数

旧32PDF・70ページに新30PDF・72ページを加え、両順序と選択ページを含め70実行を行った。すべて300dpi、補正・領域・除外なし。

| 参照比較 | 件数 |
|---|---:|
| 画像一致した38帯 × 両端・両順序・3プロファイル | 456 |
| 50比較面C × normal／strict／loose | 150 |
| 全対応ページの基準比較 | 146 |
| Skiaの非一致7帯 × 帯単独／両端全ページ・両順序・3プロファイル | 126 |
| 合計 | 878 |

全生差分マスク・生差分数がC#／Python参照実装で一致した。C・基準比較は状態とクラスタ数も一致し、Skiaの非一致帯126比較ではノイズ数・吸収数・最大ずれも一致した。正常な行内座標版で偽差分を増やさず、元の絶対座標版の検出も消していない。

これとは別に、候補・ページの列挙順を入れ替える210条件で採否が一致した。成立した実行から根拠を一つ欠かす160条件（範囲64・ページ写像44・候補32・レイアウト20）では、すべて文書全体の見送りとなり、選択リンク・部分採用とも0だった。これは小さな記述データに対する条件の検査で、追加PDFの実行数へは加算しない。

Releaseビルドは警告0・エラー0。製品ソース81ファイルはT3-1b受け入れ時のハッシュと一致し、比較式・既存ゴールデンの期待・依存は未変更。製品の全1,713テストと共通面174テストは今回再実行していない。
