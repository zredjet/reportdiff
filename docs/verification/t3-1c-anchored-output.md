# 元ページを保持する内容面：A3のCLI・出力・保存接続

2026-09-26。[接続仕様](../planning/t3-1c-anchored-integration.md)のA3を実装した。A1/A2の計画・比較を製品CLIへ接続し、内容の所有ページと別ページの参照表示を分けて保存する。A4の製品受け入れ、T3-1c全体、リリースは未完了。

## 接続した処理

既存の送り経路が文書全体で成功した場合は、その結果を優先する。既存経路が失敗した後だけ `AnchoredRun` を使い、全2ページ対応・選択なし・300dpi／normal相当・全体補正なし・数値対応なし・実効除外／領域なしの範囲をA1で検査する。新しい設定や比較式は追加していない。

事前比較のC画像・疎マスクは破棄し、比較値・内容ID・断片・採否・構造・集約と疎マスクのSHA-256から作った署名だけを残す。保存時に全Cを再比較し、署名が一致してからC画像を逐次保存する。Dのマスク・画像も一ページずつ生成して保存する。画像読込には `LoadedImage.TakePixels` で所有権を移し、転写時にドナーの全カラー画像をもう一枚複製しない。

PDFのファイルSHA-256は描画ハンドルを開く前、記述収集後、最終比較前、全JSON／HTML保存後に照合する。再読込画像も毎回、収集時の寸法・BGR SHAと照合する。設定ファイルは途中で再読込せず、実効設定オブジェクトと計画の結合・署名を照合する。

## JSON・HTML・注釈

- `page_flow.anchored_content` に候補ID、二原因、Oの送り元／先、前方・原因間・次ページ・跨ぎ行の元本文と対応、指紋、C面、予算、CとDの各全行被覆を出す。画素一致は帯検証にだけ付け、支持行の画素一致へ昇格させない。無効・既存成功・対象外ではこの追加項目を省略する。
- CのクラスタID・検出画素・ノイズ・吸収数を保持する。所有ページの `clusters` にだけ内容件数を置き、別ページの `content_references` は件数に加えない。`content_display.raw_pixels` はDの表示監査値であり、検出画素数へ加算しない。
- `source_parts` にC／D矩形、A/Bの元物理ページとO矩形、実際に表示した側を記録する。別ページを表せない旧 `source_a/b` と `row_parts` の該当側はnullとする。
- `row_alignment` は `reason: anchored_content`、旧 `content_canvas: null`、新しい `content_surface_id` を持つ。構造の `cause/carry/movement` と内容比較済みの別を出し、省略監査は二原因だけを数える。
- C画像とD画像のパスを分け、参照切り出しに表示ページ・所有ページ・内容IDを含める。HTMLには所有者と参照の双方向の静的リンク、C/D/Oと物理ページ、表示画素数を出す。元本文はエスケープし、外部通信を追加しない。
- PDF注釈はC/D断片の元物理ページの語を写す。長文の切り詰め・座標や回転による省略理由を残す。元Aを表示する断片をOへ戻した後に既存marginと0.5mm外丸めを適用する。Bだけを表示する参照位置からAの同じYの除外を作らず、所有者へ案内する。

追加保持は既存64MiB予算の残りへ予約する。CLIの出力証拠・署名用に `DisplayPart: 128 + 16×L` と文字4,096容量、保存モデルに `DisplayPart: 128 + 32×I`、文字容量 `(I+4)×max_runes_per_cluster×32 + 文書文字数×16` を保守的に予約する。Lは収集行数、Iは内容クラスタ・断片・実構造の合計。単語の取得後、注釈用の一時レコードは処理片ごとに `DisplayPart: 4×語数+4` と文字数×8を別予約する。実RSSの上限とはせず、A4で計測する。

## 保存の失敗と公開

新経路だけが所有する `.anchored-trial` を外側 `OutputWorkspace` のstaging内に作る。全ページ保存、JSON／HTML、所有者・参照・構造件数、画像リンクの検査と入力の最終照合が終わってから、外側の一回の公開へ渡す。

| 条件 | 確認した処置 |
|---|---|
| C画像保存後／一番目のD保存後の予約不足 | 試行内のPNG・モデルを全部破棄し、全文書を従来比較で再実行。追加監査はskipped |
| 再比較前／C保存後／D保存後／JSON後／公開直前の入力変更 | 処理エラー。旧出力を保持し、不完全なstagingを削除 |
| 保存段階のI/O・キャンセル・OutOfMemoryException（例外注入） | 通常見送りに変換せず処理エラー、旧出力を保持 |
| 公開前に画像リンクが欠落 | 出力検査で拒否し、旧出力を保持 |
| 出力置換失敗 | 既存契約どおり旧出力を復元 |
| 復元も失敗 | 旧結果のbackupを残し、場所を報告 |
| 公開成功後のbackup削除失敗 | 新結果を保持し、旧結果のbackup場所を報告 |

最後の三つは `OutputWorkspace` の同じDirectory操作を使い、内部の操作差し替えで失敗を独立に注入した。クラッシュ・電源断まで含む完全な原子的置換の保証にはしない。

compare-dirは個別Summaryを使う。別の対を処理している間に既に保存したPDFが変更された場合も、該当対の個別出力を消し、一覧へエラーを記録する。他の対の成功件数を維持する。一覧ファイルの書込中にさらに入力が変わった場合は公開自体を中止して旧一覧を保持する。
