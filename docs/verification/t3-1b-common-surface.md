# T3-1b：共通の比較面を作る方式の事前検証

2026-09-22。基準はv0.1.3（`f77ac1c`）。前回の「次に進んでください」を受け、比較面を表示の詰め物から切り離す案を独立試行で確認した。**純白余白を残す方式を、製品実装へ進むための仕様候補とする**。製品・参照実装・既存ゴールデンは未変更。T3-1b全体の受け入れではない。

## 結論

| 方式 | 確認条件 | 結果 |
|---|---:|---|
| 片側の帯を、白余白も含めて全て取り除く | 132 | 固定フッター前の濃淡変更を12条件で見逃すため不採用 |
| 内容のある構造帯を外し、純白余白は両側に残す | 174 | 全条件で、既知の基準A/Bの全画素と最終生差分マスクを復元 |

合計306条件について、PythonとC#の比較面・表示面の全生差分マスク、状態、生差分数、ノイズ数、吸収数、最大ずれ、クラスタ矩形／画素数、帯の写像が一致。C#は比較式をコピーせず、製品のPageComparerをそのまま呼ぶ。Pythonも参照実装のcompare_pageを変更せず呼ぶ。

元A/Bと帯の写像を入れ替えた場合、比較面のA/Bも正しく入れ替わることを306条件で両実装から確認。元画像のPNG SHA-256が比較前後で不変で、比較面の生差分を表示面へ戻しても画素数が変わらない。

残差マスクそのもののA/B対称性は別に検査した。保持案の66組中60組は全画素一致、固定フッターの濃淡変更3種×normal / looseの6組は、既存コアの基準時点から1pxの位置差がある。いずれも4画素／1クラスタで、順方向のbboxは `(41,77,4,1)`、逆方向は `(41,78,4,1)`。今回案はそれぞれの方向の基準マスクを完全に保持する。行整列で新しく完全対称な比較器になったという意味ではなく、[補足仕様の確認事項](../planning/t3-1b-common-surface.md)として明記した。

## 174条件の内訳

全て、行推定を使わず既知の正しい対応帯を与えた。今回の描画元として使ったPDFは以前の試行で生成した合成PDFであり、実帳票は使っていない。

| 群 | 条件数 | 対象 |
|---|---:|---|
| 黒い罫線の既存PDF | 42 | 挿入のみ、合計の変更、境界0 / 1 / 2 / 4 / 8pxの濃淡変更 |
| 灰色罫線の既存PDF | 36 | 挿入のみ、濃淡変更、挿入帯の黒い部分までの距離0 / 1 / 3 / 20px |
| 固定フッターの新しい合成画像 | 24 | 変更なし、濃淡変更3種。白い余白が短くなってもフッター位置は固定 |
| 別々の位置の挿入・削除 | 12 | 変更なし／あり。連続する罫線を帯別に分割しない |
| 離れた2箇所への挿入 | 12 | 変更なし／あり。累積した行送りを比較面で戻す |
| 挿入位置をまたぐ変更 | 6 | 1クラスタが表示面で2断片に分かれる |
| 恒等写像の既存ゴールデン | 42 | 全パラメータを引き継ぐ。周期I10 / I11 / I12、検出D20 / D21を含む |

PDF・新しい合成画像は、normal / strict / looseとA/B両方向。恒等写像の42ゴールデンは各ケースの元の設定と方向。前者132条件には、白余白も取り除く対照案も実行し、合計306比較となる。

純白余白を残す方式では、単にクラスタ数が期待と同じだっただけでなく、内容変更だけを加えた基準のA/B画像を全画素で復元できることを検査した。基準が持つ近傍・group・二段目の判定を、そのまま既存コアで再現する。この事実は、与えた写像が正しい合成条件についての証拠であり、任意の行推定の正しさを証明しない。

## 白余白を捨てると起きる反例

固定フッターの前に純白60pxの余白を置き、表の行挿入でその余白を消費する画像を用意した。表の縦罫線は6px幅の薄いグレー。末尾6×2pxの濃淡を変え、黒いフッターは同じページ座標に残す。

normal / loose、両方向で次の結果を確認した。

| 内容 | 行挿入前の基準 | 全て詰める | 純白余白を残す |
|---|---:|---:|---:|
| 変更なし | 0画素 / 0件 | 0 / 0 | 0 / 0 |
| RGB192→100 | 4画素 / 1件 | **0 / 0** | **4 / 1** |
| RGB200→128 | 4画素 / 1件 | **0 / 0** | **4 / 1** |
| RGB224→160 | 4画素 / 1件 | **0 / 0** | **4 / 1** |

全て詰めると、黒いフッターが変更画素へ近づき、局所近傍と連結が変わる。純白余白を両側に残すと、基準の表とフッターの間隔を復元できる。これは前回の「対応のない内容帯を白で塗り潰す」案とは異なり、内容帯は比較面から取り除き、元々純白だった余白だけを残す。

## クラスタを表示面で作り直さない

normalの境界をまたぐ変更は、比較面では `(42,78,2,4)` の8画素／1クラスタ。表示面では高さ60pxの詰め物を挟み、`(42,78,2,2)` と `(42,140,2,2)` の2断片になる。比較面で確定した1件を維持し、表示のために分裂させない。

試行ではクラスタbboxを帯で分けた断片を記録し、生差分を表示面へ全画素転写してC#と照合した。製品でのクラスタ別マスク・輪郭・ID再採番・fill_ratio・切り出し・HTMLは未実装である。

## 見送り条件の試行

- 同じ位置の内容置換を、Aだけの非白帯とBだけの非白帯として相互に削除する写像は、両実装の2方式で `unanchored_join` として拒否した。行の置換を差分0にしない。
- 各画素行の近傍が、少なくとも片側の元画像の連続範囲に対応するという追加条件をPythonで検査した。半径は `max(2+s, インク背景半径px)`。174条件を全て維持し、Aの削除とBの挿入が4pxしか離れていない例を両方向で拒否した。この例では32行の近傍に片側の連続した根拠がない。
- 近傍条件は採用範囲を保守的に狭める提案。製品C#への組み込み、設定全域、regionsとの併用、行推定後の見送り表示は未検証。固定の18pxを製品の安全距離にする提案ではない。
