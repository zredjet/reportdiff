# PERF-2d 特徴量生成の帯並列化

確認日：2026-09-21。変更前は中間画像の寿命短縮済みの `4dbbb1a`。承認済みの帯単位の並列化を導入し、一時画像の複製を抑えるため最終Matへの直接書き込みも組み合わせた。比較式、float32、設定、境界処理、検出結果は維持する。

## 実装と所有権

`FeatureStripeSchedule` が128行の帯をworkerの連続した担当区間へ分ける。帯処理のworker上限は `min(4, CPU数, 帯数/2)`。100万画素未満または4帯未満は逐次で実行し、並列時は各workerに最低2帯を割り当てる。各workerは入力画像を読み取り専用で共有し、カーネルと一時Matを自分で所有する。

全ページの値・コントラスト・インクのMatは一度だけ事前確保する。書き込み先は担当行だけで重ならない。画像Aの特徴量を完成させてからBを生成し、両方が完成してから候補抽出・グループ探索へ進む。PDF描画、画像A/B、特徴量生成とグループ探索を同時に並列実行しない。OpenCVのプロセス全体のスレッド設定も変更しない。

Labは従来どおり必要な余白を含めて生成し、その親領域に余白のある中央ROIへフィルターを適用する。平滑化を値の最終Matへ直接出力し、コントラストの最終Matを膨張の一時結果にも利用する。収縮結果だけをworker内の一時Matで保持し、減算後にコントラストが完成する。全workerの完了前にこの途中状態を公開しない。呼び出し元のROIの外側の画素はLabに取り込まない。

`Parallel.For` が開始済みworkerの完了を待ってから戻る。例外時もこの順序を守り、worker内の一時Matを解放した後、`ComparisonFeatures.Create` が出力Matを破棄する。入力の所有権は呼び出し元に残る。

公開API・CLI・結果JSONは変更しない。内部計測値にworker数と1workerの一時Mat見積もりだけを追加した。初期差分の行並列化とSIMDは別段階。

## 一時画像の予算

1workerの既知の一時Matの見積もりは次のとおり。

```
幅 × ((エッジ許容あり ? 12 × min(高さ,128) : 0)
      + (インクあり ? 25 : 24) × min(高さ,128+2×余白)) bytes
```

12は収縮結果のfloat3画像1枚、25はLabとインク生成用画像の同時保持、24は正規化BGRとLabの同時保持を見込む。余白はフィルターの2pxと、必要なインク背景半径を満たす。

worker合計 **96MiB** に収まるよう並列数を減らす。2worker分が入らなければ既存の逐次処理へ戻す。1workerだけでも96MiBを超える条件を拒否する制限ではない。入出力の全ページMat、カーネル、OpenCV内部の作業領域、アロケータが保持する空き領域、スレッドスタック等は別であり、プロセスRSSの上限ではない。

この環境の公開A3・通常比較では300dpiが3worker（1worker約28.0MB）、400dpiが2worker（約39.3MB）。背景半径が大きい画像ではさらに減らす。

既定値の選別では96/128MiBを比較した。128MiBでは300dpiが4worker、400dpiが3workerとなり、前処理は試測定でさらに約20ms／100ms短縮したが、RSSが約40〜50MB増えた。メモリ削減を先行してきた方針に合わせて96MiBを採用した。単純に各workerへ3枚のフィルター画像を持たせる初案より、一時画像を減らした最終案の方がRSSの増加を抑えている。

## 検証

Releaseビルドは警告0・エラー0。全 **939件成功、失敗・スキップ0**。追加16件。

- 1/2/4/8workerを指定し、float特徴量をbyte列として全ページ演算と完全一致比較。インクも一致。各設定を2回生成し、元画像・ROIの親画像が不変であることを確認。
- 幅1pxと73px、高さ2049pxの17帯、最後の1行、worker境界、非連続Mat、300/400dpi、エッジ許容0/0.3/0.6、インク有無、背景半径0.001/1.5/20mmを含む。
- 小画像・帯数・CPU数・メモリ予算による逐次復帰、予算の境界、巨大な余白、全帯を一度だけ割り当てること、例外時のworker完了待ちを確認。
- 生成失敗で入力を破棄しないこと、後続生成の成功、二重Dispose、破棄後のRead拒否も確認。既存の全ページ特徴量・インク再利用・グループ並列探索・分類・移動・CLIの回帰も通過。

変更前、直接書き込みを含む最終逐次対照、製品版で、100スナップショット（37ゴールデン、画像端/ROI/帯境界/設定60、大画像3）が完全一致。マスクSHA-256、統計、クラスタ、分類・移動注釈、警告を含む。

## 通常CLIの時間と最大RSS

Apple M4 Max（16コア・128GiB RAM）、macOS 26.5.1、.NET 10.0.12、Release。伊勢市の公開工程表1組。4/20ページは同じページを繰り返したPDF。起動、PDF描画、比較、注釈、PNG/JSON/HTML保存、終了までを含み、`--save-all-pages` を指定。RSSは `/usr/bin/time -l`、GBは10^9bytes。

各構成ウォームアップ1回後、4ページは7回、他は3回を独立プロセスで測定。構成を交互・往復順に実行し、ビルド・テスト・別の計測と同時実行しない。表は中央値。

| 条件 | 変更前 | 変更後 | 短縮率 | 変更前RSS | 変更後RSS |
|---|---:|---:|---:|---:|---:|
| A3・300dpi・1ページ | 1.566秒 | 1.357秒 | 13.4% | 1.924GB | 1.966GB |
| A3・400dpi・1ページ | 2.412秒 | 2.085秒 | 13.6% | 3.498GB | 3.507GB |
| A3・300dpi・4ページ | 4.368秒 | 3.606秒 | 17.4% | 2.108GB | 2.151GB |
| A3・300dpi・20ページ | 19.194秒 | 15.545秒 | 19.0% | 2.217GB | 2.268GB |

並列workerの一時領域が増えるため、今回の変更をメモリ削減とは扱わない。4ページのRSS範囲は変更前 2.014〜2.111GB、変更後 2.047〜2.158GB。20ページは変更前 約2.217GB、変更後 2.262〜2.268GB。GCやネイティブアロケータによる実行間のばらつきがあり、任意の帳票・機器での上限ではない。

## 並列化の効果と小さい処理

前処理時間は初期の完全一致チェックとA/Bの特徴量生成を含む。通常CLIとは別のステージ計測ハーネスで測定した。最終逐次対照は製品版と同じソースの既定worker上限だけを1に変更し、直接書き込みと並列化の効果を分けている。

| 解像度 | 変更前 | 最終逐次対照 | 製品版 | 製品版worker上限 |
|---|---:|---:|---:|---:|
| 300dpi | 386.3ms | 375.7ms | 193.1ms | 3 |
| 400dpi | 731.0ms | 713.5ms | 411.9ms | 2 |

合成A4・300dpi、局所変更の比較コアも確認した。各構成のウォームアップと結果検証後、同一プロセス5回の中央値。既存ハーネスは各測定前にGCを行うため、通常CLIの時間・RSSとは分けて評価する。検出の主要統計が構成間で一致した。

| 条件 | 変更前 | 最終逐次対照 | 製品版 |
|---|---:|---:|---:|
| 1 か所変更 | 204.5ms | 199.0ms | 109.3ms |
| 1 か所変更＋全体 1px ずれ | 211.3ms | 203.4ms | 115.0ms |

逐次になる小画像と幅広・低い画像でも特徴量を測定した。各構成3回ウォームアップ後、同一プロセス15回の中央値。値・コントラスト・インクのSHA-256は3構成で一致。32×32は数十μsで、微小な時間差を改善の根拠にはしない。

|---|---:|---:|---:|

## 証跡・再実行・残件

集計、各実行の時間・RSS・一致、入力/DLL/ソースのSHA-256、試作比較は [perf-2d-feature-parallel.json](perf-2d-feature-parallel.json)。公開PDF・生成画像・ローカル旧DLLはgit管理外。

```sh
dotnet build -c Release --disable-build-servers -m:1 -p:UseSharedCompilation=false -p:NuGetAudit=false --no-restore
dotnet test -c Release --no-build
python out/perf2d-features/check.py
python out/perf2d-features/measure.py probe-final 300 baseline,serial-final,optimized 3
python out/perf2d-features/measure.py probe-final 400 baseline,serial-final,optimized 3
python out/perf2d-features/measure.py cli-final 300 baseline,optimized 3
python out/perf2d-features/measure.py cli-final 400 baseline,optimized 3
python out/perf2d-features/measure.py cli4-final 300 baseline,optimized 7
python out/perf2d-features/measure.py cli20-final 300 baseline,optimized 3
```

出力先が既に存在する場合は測定名を変更する。計測スクリプト、旧DLL、入力はこの作業環境に保存したgit管理外のもの。テストのローカルIPCとRSS取得はホスト実行権限が必要。

- ページ並列化、候補ずれの並列化、配布物更新、pushは対象外。PERF-2全体は未完了。
