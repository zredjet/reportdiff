2026-09-23。[承認済みの接続条件](../planning/t3-1c-multiple-causes.md#製品接続の具体案)に従い、同一ページ対応済みの境界証明と、独立した送り連鎖ごとの集約をCore・CLI・JSON／HTMLへ接続した。単一原因の成立条件、元帯の全画素一致、比較しきい値は変更していない。証拠の数値とソースハッシュは[検証JSON](t3-1c-multiple-cli.json)に記録する。

## 接続した動作

`PageFlowNonflow` は候補両端の全行が反対側の同じ物理ページに対応し、本文が文書全体で一意・順序一致で、その境界を跨ぐ共通行がないことを証明する。全ページの対応と完全な選択範囲が必要。証明を元の文書記述へ結び付け、欠落・重複・別文書の証明は文書ゲートで拒否する。証明の固定費256B、行対応あたり512Bを既存64MiB予算に加算する。上限を超えたら部分証明を残さず、文書全体の送りを見送る。

元の候補ID・順序は変えない。証明済みの非送り候補は `status: skipped`、`image_status: not_performed`、`reason: same_page_rows_not_flow` とする。任意の `nonflow` に全行の同一ページ対応先をO座標で残し、HTMLにも内容比較を続ける旨を表示する。本文や画像の一致と混同しないよう、`pixel_equality_proven: false` を記録する。構造グループは検証済み送りだけを元のリンクIDで参照する。

`PageFlowComponents` は別々のページ群の単一原因を、従来の集約条件で一つずつ検証する。本文の全体一意性・共通順序を先に確認し、未接続の境界を跨ぐ行や、送りのないページの構造変更も拒否する。全実構造IDが一度ずつ所属し、全成分が成立した場合だけ集約する。一成分でも不成立なら全グループを取り消す。従来の単一原因・片側ページは維持し、複数原因と片側ページの組合せは追加しない。

ページ別内訳Uは採用されたC/Dの内容クラスタと実構造の合計。集約後は `U - Σ(nᵢ - 1)` であり、内容クラスタ・網羅性・相違の終了コード1は維持する。比較面・構造帯の生成とraw overlayのコードは今回変更していない。

## 複数原因と縦補正・設定・保護

追加12ベクターPDFによる12条件・旧新48プロセスでは、複数原因と縦補正の組合せを確認した。正負の一定補正量の両方向と、B側のページ別補正量・挿入削除の併存・末尾色変更の7条件で成立した。C/D28ページ、実構造70件、元帯PNG42枚、非送り候補の対応行14組をO/Gの座標から独立に照合し、raw144組も一致した。

ページ別補正量を持つPDFをA側に置く3条件は、Bの補正後もA側の固定部分がページ間で異なる位置となり、`fixed_parts_support` で見送った。横補正の両方向2条件も従来どおり見送った。これら5条件は無効時のページ結果全体と一致する。固定部の条件を緩めて複数原因の成立例にはしていない。

非送り境界末尾の除外は、必要な支持帯を失わせると `insufficient_support` により文書全体の送りを見送る。帯の一部だけを除外した対照でも支持帯不足となった。この組合せは採用未成立として残す。通常比較への復帰、`--no-regions` による除外無効化、同じ帯の厳密比較領域、文字収集上限、構造除外、明示的なページ選択を検証する。原因の集約を部分的に残さない。

compare-dirの設定継承・一覧の10→2、入力PDFが検証中に変わった場合、元帯PNG保存が失敗した場合も確認する。終了コード2、`--force` の旧出力保護、ステージングの削除を維持する。ブラウザー・画面サイズ・JavaScriptの保留はこの自動検証で合格にしない。
