# T3-1c：元ページの周辺を保持する帯の検証結果

2026-09-22。[前回の検証](t3-1c-page-flow-probe.md)後の続行指示を受け、[境界の補足案](../planning/t3-1c-context-verification.md)を設計し、製品と独立したツールで検証した。**帯の全画素一致に限定すれば、指定した正解帯の画像検証は成立する。許容付き比較の差分0だけを使う案は不採用**。自動候補・構造認定・集約・製品接続は未実施で、T3-1cは未完了。

## 方法と結論

送り元Aの候補帯だけを送り先Bの画素で置換したA'、逆にBの候補帯だけをAの画素で置換したB'を作る。A対A'・A'対A・B対B'・B'対Bをそれぞれ元ページ全体で比較する。帯外の周辺を白くしたり、有限の余白でgroupを切ったりせず、実際の各ページの周辺を保持する。

R10／R11／3ページ連鎖の既知の帯5組では、前回の正常帯に出た4〜8pxの偽差分がなくなり、normal／strict／looseの四比較がすべて0になった。帯の全画素が一致するため、置換後のページも元ページと完全一致することが理由である。差分をマスクして消した結果ではない。

ただし、帯が異なる場合に四比較0だけで一致と認めることはできなかった。境界をまたぐ薄い塗りを二つへ分けると、どちらも許容内になる反例がある。そのため、初期案では**帯のBGR全画素一致を追加の必要条件**とし、非一致の帯は四比較0でも送りを確定しない。

この限定は通常比較の式・しきい値・検出期待を変更しない。単独オブジェクトの2px移動は比較コアではnormal／looseで吸収され、strictでは検出されるまま。一方、送りの認定では全画素一致ではないので見送り、従来のページ比較を維持する。微小な描画差も送りとして確定できない制約を残す。

## 750比較の範囲

前回の20PDFから、正解として与えた送り帯13組を再読込した。PDFのSHA-256と帯座標は前回のままで、PDF生成コード・入力を変更していない。自動推定した候補ではない。

追加の24画像入力は、灰色罫線・薄い塗り・色変更を帯の外／境界交差／内側へ置いた21条件と、長い連続罫線・単独移動・1画素差の3条件。寸法・位置は実験用のpx格子で固定し、利用者向けの設定値は追加しない。

| 比較 | 条件数 |
|---|---:|
| 元ページの置換（37入力 × 3プロファイル × 両端 × 両順序） | 444 |
| 帯だけの対照（37入力 × 3プロファイル × 両順序） | 222 |
| 薄色の全変更／帯外だけの対照（7入力 × 3プロファイル × 2種類 × 両順序） | 84 |
| 合計 | 750 |

normalは`max_shift_mm=0.15 / edge_tolerance=0.3`、strictは`0 / 0`、looseは`0.30 / 0.3`。ほかは既定値。除外は使わない。C#と変更していないPython参照実装で、750比較すべての生差分マスク・生差分数・状態・クラスタ数・ノイズ数・吸収数・最大ずれが一致した。Python OpenCVは4.13.0。

元画像のハッシュ不変と、置換した帯の画素が相手の元画素に一致し、帯外が元のままであることをC#／Pythonの両方で確認した。置換画像は検証専用であり、raw evidenceの代わりに出力しない。

## 境界の反例を保持する

### 長い罫線

高さ480pxのページを貫く縦罫線と、上部・下部の横罫線を持つ入力を使った。帯はy=[120,320)で、対応する縦罫線のx位置を2px変える。帯だけを比較するとnormal／looseで1groupが吸収され、生差分0になる。

元ページに帯を置換すると、帯外の罫線につながる位置が変わるため、両端・両順序で生差分1,592pxが残る。40pxの余白より遠くまでつながるgroupを保持できており、切り出しによる吸収をそのまま採用しない。

### 境界をまたぐ薄い塗り

白から#F2F2F2へ変える24×4pxの塗りを、帯の上端または下端に2pxずつまたがるよう置いた。normal／looseで次の結果になった。A/Bの比較順を交換しても同じ。

| 比較範囲 | 生差分数 |
|---|---:|
| 分割前の4px高の変更全体 | 44 |
| Aに帯内の2px高だけを置換 | 0 |
| Bから帯内の2px高だけを戻す | 0 |
| 帯外の2px高だけを残す | 0 |

これは「二つの検証で差分0なら、全体でも差分0」という推論への反例である。後半の対照は分割の危険性を示す実験であり、既存の内容比較面Cがこの操作を自動採用したという意味ではない。

全画素一致を必要とする限定案では、この2入力はどのプロファイルでも送りの証拠にならない。44pxの検出期待を0へ変更していない。許容付きの置換検証だけで採用する案を不採用とした。

### ノイズと帯外の変更

strictの1画素差は、クラスタ数0でも生差分1として保持された。クラスタ数0を一致の根拠に使わない。

前回の帯外直近の変更は、帯が全画素一致なので帯の検証自体は通るが、既存の正解写像のCに52px・1クラスタが残る。今回その入力・既存記録の不変を照合した。新しい片側ページの余分な薄色や、反復行の一意性は別の検証が必要であり、帯の一致だけでは解決しない。
