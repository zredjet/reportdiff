# 元ページを保持する内容面の独立検証

2026-09-26。[構成案](../planning/t3-1c-anchored-content.md)を検証した。元の `same-page-two` の両方向で、片側の物理ページを全高にわたって保持し、送り先の実画素を対応付ける内容面を生成できた。両ページの内容差分は0で、内容色変更の2方向では3,807px・1クラスタを保持した。現行の `unanchored_join` 検査・比較式・支持条件は変更していない。

これは内容面の構成と比較の成立であり、製品の採用・表示・文書集約は未接続。元ケースの製品上の未成立を合格にせず、T3-1c全体は未完了・未コミットとする。

## 構成と連続性

順方向はA1・A2をそれぞれC1・C2の全高に保持する。B側だけ、実在する元帯を次のように対応付ける。幅999px、高さ1,250px、区間は半開区間。逆方向はA/Bを交換する。

| 内容面 | Cのy | Bの物理ページと元y |
|---|---|---|
| C1 | 0〜500 | B1: 0〜500 |
| C1 | 500〜700 | B1: 600〜800 |
| C1 | 700〜900 | B2: 300〜500（送り行） |
| C1 | 900〜1250 | B1: 900〜1250 |
| C2 | 0〜300 | B2: 0〜300 |
| C2 | 300〜700 | B2: 500〜900 |
| C2 | 700〜900 | 対応なし。A2の実在する純白を保持 |
| C2 | 900〜1250 | B2: 900〜1250 |

B1の500〜600と800〜900は、前工程で特定した二つの追加原因帯としてCから省略する。送り帯はCに残る。全Cと原因帯を合わせ、四つの元画像の各走査行が一度だけ現れることを検査する。純白区間は全チャンネル255の場合だけ認め、1画素の1チャンネルが254になった対照でも拒否する。

各CではAの元物理ページが画像端を含めて連続しているため、任意の比較近傍が同じ元ページに収まる。逆方向ではBがその役割を持つ。異なるページのB帯を、同じ元画像の連続区間と偽って扱うことはない。比較窓の縮小・境界でのグループ分割・白余白の切り詰めもない。

## 結果

元PDFは再生成せず、前工程の記録・PNG・固定30PDFをSHA256で確認した。記録44方向のうち、文字証拠・次ページ支持・送り帯検証が揃った4方向だけを固定入力の内容面実験へ進めた。残る40方向を新規採用せず、前工程の採否記録を保存する。この選別は記録の再利用であり、今回44方向の候補推定・採用を実行したという意味ではない。

計58条件。内容比較まで進んだ22条件・44ページについて、C#とPython参照コアの生差分マスク・生差分数・ノイズ数・吸収数・状態・クラスタ矩形／画素数が一致した。合計は検出成立12、周期吸収6、元ケースの差分0が2、検出期待未成立2であり、58条件すべての期待が成立したとはしない。

薄色の対照はBGR=(128,128,128)、幅36px・高さ1px、C1のy=499に追加した線。入力写像から作るCと、元ページの通常座標へ直接変更した正解画像が全画素一致し、参照コアでも差分0だった。新しい比較面で検出が消えた結果ではないが、薄い印の検出保持を一般に受け入れる証拠にもならない。検出期待を無視期待へ変更せず `unmet_detection: 2` として残す。SPECの既知の限界へ今回の別条件を自動追加せず、比較式も変更しない。

色変更3,807pxは元の6行ケースを変更した今回の値。以前の8行対照の1,614pxとは別入力であり、その期待は変更していない。

## 画素の保持と投影

入力写像の転写だけでなく、上表の物理座標から独立に組み立てた画像にも一致した。メモリ上の変更18条件は、通常座標の正解36画像と全画素一致した。比較面へは元PNGの画素をそのまま転写し、全チャンネル255を確認した片側純白区間だけ白を対応付ける。

22条件の元走査行計110,000行を一度ずつ被覆した。保持した純白は計4,395,600px（各条件199,800px）。生差分の元座標投影88画像をPythonで独立転写し、保持側の投影画素数とCの生差分数が一致した。両側への投影数を合計して件数にせず、物理ページへ写した後の再クラスタ化も行っていない。

ここで確認したのは元座標Oへの生差分投影であり、製品DへのクラスタID・構造ID・本文注釈・除外候補の投影ではない。クラスタが異なる物理ページへ分かれる表示契約は未実装。

## 次の境界

内容面の物理的な連続性という障害は、この限定構成で回避できた。ただし現行の2画像・1物理ページ用のC/D表現をそのまま使えるわけではない。次は以下の契約を、製品に接続する前に具体化する。

1. Cの各帯にA/Bそれぞれの物理ページ・元矩形・候補IDを保持し、実Dへの断片とクラスタIDを一対多で結ぶ。件数を複製せず、二原因・移動・送りの実構造IDを保持する。
2. 設定基準Aの領域・除外を各元ページからCへ写す。逆方向の保持側Bや、異なる実効設定のページを混同しない。まず未対応の設定は既存比較へ戻す範囲を明記する。
3. 前工程の外部支持を元の文書・配置・原因・候補・設定へ結び付ける。前方2行・原因間2行・次ページ4行の支持、インク、一意性、改善率を評価し、送り帯の一致を支持数へ転用しない。
4. 元画素の再読込・確保前の予算・全ページ失敗時の取り消しを含めて、既存負例と製品出力を検証する。今回の物理写像検査だけでは本文の誤対応や原因証拠の差し替えを防ぐ製品契約にならない。

この工程では上記の採用・集約・設定・出力の実装を先取りしない。元ケースの文書集約、薄色対照、A4未成立9条件、片側ページ・数値行自体の跨ぎ、Windows・実帳票・大規模性能・ブラウザー保留を残す。
