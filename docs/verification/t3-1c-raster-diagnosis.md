# T3-1c A4の描画差とC/Dの診断結果

2026-09-23、macOS arm64。**配置を除いたPDF命令と描画フォントが一致しても、元ラスタには位置による差がある。今回確認したCへの転写とDへの投影に誤りはなく、A4の送り採用を成立させる製品修正は行っていない。** [診断範囲](../planning/t3-1c-raster-diagnosis.md)、[機械可読記録](t3-1c-raster-diagnosis.json)を参照。

## 確認した範囲

前工程の固定12PDF・24ページを使い、通常のSkia 24行／48行、内側へ描画端を寄せたSkia、分数pt／整数ptのType3、疎なType3対照を診断した。本文288組の対応はpypdfで抽出した文字列から独立に求めた。配置だけを取り除いた描画命令は288組すべて一致し、描画用の埋込フォント・幅・文字コードも一致した。SkiaのToUnicodeは追加文字Wの有無で異なるが、対応する本文のコードと描画フォントは同じだった。

PDFtoImageの直接APIと製品経由の元画像は24枚すべて全画素一致し、前工程の元PNGともバイト一致した。12PDFのSHA256も固定記録と一致。PDFの書き換え、新しいPDFの生成、製品の描画条件変更は行っていない。

## 元画像で起きていること

以下は製品の判定マスクではなく、元BGR値が異なる画素の数。2ページ分の対応本文を整数の行移動量で照合した結果で、ページをまたぐ帯も含む。

| 入力 | 差のある対応行 | 元画素差の合計 | ページをまたぐ帯の差 |
|---|---:|---:|---:|
| Skia 24行 | 3 / 46 | 15,503 | 5,172 |
| Skia 48行 | 5 / 94 | 10,489 | 3,510 |
| Skia・描画端を内側へ | 3 / 46 | 15,503 | 5,172 |
| Type3・分数pt | 7 / 46 | 9,666 | 230 |
| Type3・整数pt | 4 / 46 | 8,976 | 0 |
| 疎なType3 | 0 / 10 | 0 | 0 |

Skia 24／48行の1ページ目は本文の非白範囲が `[400,2801)` となり、意図した高さ2,400pxより1px長い。全幅の本文境界を証明できず、`unproven_body_bounds` で見送る。内側へ寄せた対照は末尾超過を解消しても送り帯の文字画素が一致せず、`nonidentical_band_not_proven` で見送る。本文の文字が同じことだけでは、この元画素差を消す根拠にならない。

整数ptのType3では、0始まりのスロット9の横罫線だけが隣接スロットより1px太い。横位置X=150で、行内Y=80〜87のグレー値は次のとおり。同じ幅540pt・高さ0.48ptの矩形命令で、配置だけが24ptずつ異なる。

| スロット | 8画素の値（0が黒、255が白） |
|---|---|
| 8 | 255, 0, 0, 255, 255, 255, 255, 255 |
| 9 | 255, 0, 0, 0, 255, 255, 255, 255 |
| 10 | 255, 0, 0, 255, 255, 255, 255, 255 |

したがってスロット8→9、9→10の対応でそれぞれ2,244pxの差が生じる。これはCの切り貼り前に存在する。描画位置に依存する差であることは確認したが、PDFium内部の具体的な演算・丸め命令までは特定していない。

## 寸法と描画の対照

使用中のPDFtoImage 5.4.0は、DPI倍率をfloatで計算し、画像の確保には整数への切り捨て、PDF描画領域には切り上げを使う。[固定コミットの実装](https://github.com/sungaila/PDFtoImage/blob/5948628cb2cf7d070c7fd28b1b4496db39e3afcd/src/PDFtoImage/Internals/PdfDocument.cs#L247)を確認した。今回のページはタイル境界を超えない。

| PDFの寸法 pt | 既定の保存画像 px | 描画領域 px |
|---|---|---|
| 595 × 842 | 2479 × 3508 | 2480 × 3509 |
| 595.2 × 841.92 | 2480 × 3507 | 2480 × 3508 |
| 594 × 840 | 2475 × 3499 | 2475 × 3500 |

診断用に切り上げ寸法を明示すると、元サイズに切り出した24枚すべてが既定描画と全画素一致した。確保サイズの不足を直すだけでは、本文内の描画差は解消しない。

切り捨て寸法を描画領域にも明示した対照はSkia 24行の対応画素差を0にしたが、整数ptのType3では44行・97,026px、成立していた疎な対照でも8行・17,886pxの差を生じさせた。これは描画倍率の変更であり、採用できる修正ではない。パスのアンチエイリアスを無効にしても整数ptの罫線差8,976pxは残った。これらの対照を送りの証明や製品結果に使用していない。

## C/Dと判定マスク

範囲が成立する整数pt・疎な対照の計4ページで、製品が作ったCを独立に再構成した。元A/Bからの帯の転写、白帯、Cの判定マスクからDへの投影がすべて一致した。整数ptのCの元画素差は各ページ4,488pxで、元の横罫線2組の差がそのまま残っている。

整数ptの各Cで、判定マスクは13,452px・2クラスタ。X範囲 `[107,2349)`、Y範囲 `[1282,1285)` と `[1382,1385)` の2本になり、各クラスタ6,726pxだった。Cの値を既存Python参照実装へ渡しても、マスク全画素と件数が一致した。生のBGR不一致と判定マスクの画素数は異なる概念で、後者にはSPEC 5章の3×3平滑化・許容判定等が適用される。

判定画素から非連続の継ぎ目までの最短距離は1ページ目682px、2ページ目882pxで、必要近傍半径18pxを十分に超える。継ぎ目付近の偽差分やDへの重複投影ではない。疎な対照はCの元画素差・判定画素とも0だった。

採否は前工程を再現した。整数ptの1ページ目は基準5,791pxに対して候補13,452pxで改善率−1.3229、2ページ目は基準17,761pxに対して13,452pxで0.2426。前者の `low_improvement` により文書全体の送りを見送る。後者だけを採用しない。疎な対照2ページは採用条件を満たした。
