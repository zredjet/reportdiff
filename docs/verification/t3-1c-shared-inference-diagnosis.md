# T3-1c 共有原因の未成立6方向の前段診断

2026-09-23。[共有原因の製品接続](t3-1c-shared-cli.md)後に残った6方向を、[診断計画](../planning/t3-1c-shared-inference-diagnosis.md)に沿って調べた。三ページ連鎖と「共有原因→独立原因」の4方向は、候補を境界の共通行へ結び付ければ、既存の画像検証・支持・採用・集約まで診断上成立する。同一ページ二原因の2方向は別の支持不足があり、この候補再検証だけでは成立しない。

製品コード・設定・出力は変更していない。以下の診断件数を現在のCLIの件数や製品受け入れへ置き換えない。

## 六方向の不足と診断結果

| 入力（各A→B／B→A） | 現製品が止まる理由 | 独立診断 | 残る制限 |
|---|---|---|---|
| `shared-chain` | 第2ページに100pxと200pxの各2支持があり、`ambiguous_displacement` | 境界を跨ぐKK・LLの2行から高さ200pxを選ぶ。全ページ採用・10構造→2原因が成立 | 製品CLIは16→16のまま。候補再検証の接続は未実施 |
| `shared-and-independent` | 第2ページに100pxと200pxの各2支持があり、端点なしの曖昧候補が文書ゲートを止める | 第2→3ページを跨ぐ共通行はない。両変位の仮端点を既存の非送り条件で証明し、第1→2・第3→4ページの送りを確認。12構造→3原因が成立 | 製品CLIは20→20のまま。端点なしの候補と境界証明・既存IDの接続が必要 |
| `same-page-two` | 同一ページには100pxの2支持しかなく、その長さの帯は `text_mismatch` | 実際に跨ぐEE・FFは200pxの帯で、画像一致は成立する。しかし200pxの同一ページ支持は0、末尾の追加行には後ろの支持が0 | 第1ページは `unverified_edge_band`。製品・診断とも10→10。最低支持数や末尾構造条件を緩めない |

挿入方向の具体例で、三ページ連鎖の第2ページはGG・HHが100px、II・JJが200px移動し、KK・LLが第3ページへ送られる。推定器は現在、適格な正変位が一つの場合だけその高さを選ぶため、二つの変位を説明できる行順序を参照する前に止まる。診断では短い一致帯や最大変位を任意に選ばず、文書全体の一意な共通行のうち、その境界を跨ぐ全行が占める末尾／先頭帯と照合した。

共有原因→独立原因の第2ページも100px・200pxの移動を持つが、FIRSTの行は第2ページ内に残り、第3ページのSECONDは同じ第3ページに対応する。共通行の順序を保ったまま、境界を跨ぐ共通行が存在しない。100pxの仮端点では各側1行、200pxでは各側2行が同じ物理ページの相手へ対応し、既存 `PageFlowNonflow.Find` が両方の候補を証明できる。単に曖昧候補を無視した結果とは区別する。診断でも全適格変位の証明を要求した。

同一ページ二原因では、第1ページBの末尾800〜900pxに追加行 `ROW ADDED E A` があり、前に4共通行・後ろに0共通行となる。既存の局所構造帯は内側で前後それぞれ2行の支持を必要とするため、200pxの送り帯を正しく見つけても追加行の端が証明できない。元帯の画像一致を、その追加行や移動量の支持として使っていない。逆方向も同じ不足を確認した。

## 検証方法と対照

診断ツールは既存の固定26方向のPDFを読み直し、元本文・基線・左端・完全な行帯・物理ページを取得する。全ページ対応、両側の本文一意性、共通順序、隣接した跨ぎ、末尾／先頭の完全な行による被覆を要求する。元の `max_shift_mm: 20`（300dpiで236px）と `min_support_bands: 2` を使い、しきい値・PDF・文字層を変更していない。

元帯は製品のBGR全画素一致と両端置換比較を通し、そのまま既存のC/D作成・元本文による支持評価・改善率・因果集約へ渡した。支持不足の仮候補は後段の不足を観測するためだけに使用し、最終採用の入力ゲートはfalseにした。診断で使う反射は独立ツール内だけで、製品へ呼び出し経路を追加していない。

既存の共有二原因・色変更・独立原因との併存・隣接挿入対照8方向を維持し、新たに4方向が診断上成立した。元の正例期待14方向中12方向で成立、同一ページ二原因2方向は未成立。三原因・複数行原因・混在端点・異符号・反復本文・元帯画像変更の負例12方向は全て見送り、負例の新規採用は0。共有三原因は写像側で止まるため、原因数一般の対応を示す結果ではない。

既存のCLIを26方向で再実行し、前回の1,154ファイル（JSON・HTML・PNG）が日時以外一致した。診断結果の変更を製品出力へ混ぜていない。Pythonは各境界の変位支持と共通行の所属を再計算し、独立した原因モデルで集約件数・原因参照・移動寄与・収支を照合する。元画像からC/Dの転写を再構成し、内容生差分マスクをPython参照と画素単位で比較し、D投影と元A/B・raw overlayも検証する。
