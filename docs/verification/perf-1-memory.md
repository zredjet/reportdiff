# PERF-1 比較コアのメモリ削減

確認日：2026-09-21。変更前は `2e106435580f00a7f961ff19f935fea2dbf414b6`（v0.1.1）。今回の範囲はメモリ削減で、位置ずれ探索のアルゴリズムは変更していない。

## 実装

`ComparisonFeatures` が比較に使う平滑化・コントラストを float32 の連続 Mat として所有する。ページ全体の Lab と、同じ特徴量のマネージド配列を重ねて保持しない。画素ループは所有中の Mat から取得した読み取り専用 Span を使うため、画素ごとにネイティブ API を呼ばず、独自の unsafe メモリ管理も追加していない。

Lab・平滑化・コントラスト・インクは 128 行ずつ生成する。3×3 平滑化、5×5 最大／最小値、局所背景の半径に必要な余白を含め、帯の中央部分だけを最終 Mat にコピーする。画像端には従来と同じ OpenCV の境界処理を使う。非連続 Mat の親画像の画素を混ぜない。

`TolerantDifference.Calculate` の `using` が A/B の特徴量とインクを所有し、生差分を返す時点で解放する。その後の分類・移動注釈には大きな特徴量を持ち越さない。生成途中で例外が出た場合も、確保済みの出力 Mat と各帯の一時 Mat を破棄する。位置ずれの探索が無効ならグループ化用のインクは生成しない。厳密比較では平滑化・コントラストを生成しない。

検出の式・float32 の精度・解像度・既定値・しきい値・ずれの優先順・出力形式・参照実装・ゴールデン期待値は変更していない。強制 GC、ページ並列化、新規依存も追加していない。

## 最大メモリと時間

伊勢市の公開工程表／変更工程表を、通常設定と `--save-all-pages` で比較した。300dpi は A3 横・4960×3508px。400dpi は同じ PDF を高解像度で描画したもの。4 ページの条件は、同じ公開 PDF の 1 ページを PdfPig の `PdfDocumentBuilder.AddPage` で 4 回複製した PDF 同士を、300dpi で逐次比較したもの。

各条件・各版で 1 回ウォームアップ後、別プロセスで 3 回測定した。変更前→変更後を交互に実行し、他のビルド・テスト・ベンチマークとは重ねていない。プロセス起動、PDF 読み込み・描画、比較、文字注釈、全 PNG・JSON・HTML 保存、終了までを含む。最大 RSS は macOS `/usr/bin/time -l`。表はそれぞれの中央値で、GB は 10^9 bytes。

| 条件 | 変更前の最大 RSS | 変更後の最大 RSS | 削減率 | 変更前の時間 | 変更後の時間 |
|---|---:|---:|---:|---:|---:|
| A3・300dpi・1 ページ | 3.165GB | 2.082GB | 34.2% | 1.889 秒 | 1.882 秒 |
| A3・400dpi・1 ページ | 5.601GB | 3.694GB | 34.0% | 2.952 秒 | 3.043 秒 |
| A3・300dpi・4 ページ | 5.991GB | 2.170GB | 63.8% | 5.550 秒 | 5.604 秒 |

全測定値・入力ハッシュ・新旧 Core DLL のハッシュは [perf-1-memory.json](perf-1-memory.json) に記録した。各実行の JSON と PNG は全条件で一致し、PNG 枚数は 300dpi が 174、400dpi が 171、4 ページが 696。

メモリ削減は各回で安定している。4 ページでも変更後は約 2.17GB に収まり、比較中の大きな特徴量を後続ページまで保持しない効果を確認できた。ただし、この測定は長時間・大量ページでのメモリリーク不在を保証するものではない。

時間は 300dpi でほぼ同等、400dpi では約 3.1% 増加、4 ページでは約 1.0% 増加した。帯ごとの関数呼び出しや余白の重複計算があり、今回の変更を高速化の成果としては扱わない。位置ずれ探索と特徴量生成の速度改善は PERF-2 に分ける。
