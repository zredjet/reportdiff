#### [ ] T3-1d 画像の帯 DP（画像入力・文字層のない PDF）

- テキスト層が使えない側がある場合の仮説生成。インクマスクから長い横線・縦線をモルフォロジーの open で除き、内容インクの横方向投影から内容帯を取る。空白は帯にせず、帯の y 位置の差として扱う

- 検証・採用条件・出力は T3-1b と共通。`row_alignment.source` に `image` を記録する。送りの候補（T3-1c）は帯の一致度で出す

#### [ ] T3-4c 見出し語を基準にした領域（anchor）

可変レイアウトでは合計欄などの y 座標が明細の行数で変わり、ページ座標で書いた領域が文書ごとに外れるため。

- `regions` の要素に `anchor: {text, occurrence}` と、見出し語の左上からの相対位置 `dx`・`dy`（mm）、`w`・`h` を指定できるようにする。`x`・`y` との併用はエラー

```yaml
regions:
  - {name: 合計欄, page: all, anchor: {text: 合計, occurrence: last}, dx: -2, dy: -1, w: 80, h: 8, profile: strict}
```

- アンカーは A・B それぞれの PDF テキスト層で独立に探す。同じ行の隣接単語を連結し、空白を除いてから照合する（「合　計」のように字間を空けた見出しへの対策）。全角半角の正規化はしない
- 見つからない、または複数あって決まらない場合は、ページ・側・領域名とともに警告 `REGION_ANCHOR_NOT_FOUND` / `REGION_ANCHOR_AMBIGUOUS` を出す。画像入力と、テキスト注釈の省略条件に当たるページも同様。`mode: exclude` は両側のアンカーと対応を確認できた場合だけ適用し、片側でも失敗したら、そのページの当該領域全体を適用しない。共通の差分マスクに片側だけの除外矩形を適用して相手側の変更を隠すことを防ぐ。`compare` の片側失敗時の扱いは仕様案で確定する
- A と B で位置が違う場合：両側のアンカーが解決したうえで、行整列が採用されていればキャンバス上で一致することを確認する。一致しない場合の除外は適用しない。行整列が採用されていなければ、対応を確認した A 側・B 側それぞれの矩形の和集合に適用する（間の空間まで囲う外接矩形にはしない）

受け入れ条件：行数の違う 2 文書に同じ設定を使い、合計欄の領域が正しい位置に付く。行整列あり／なしの両方。見つからない・曖昧・画像入力の各警告と、適用しなかった事実の JSON / HTML 表示。字間を空けた見出し。除外として使った場合、片側の見出し語の変更・欠落・曖昧化で領域全体が非適用となり、その側の変更が検出に残ること。両側解決・整列後の対応不一致も非適用と理由を確認する。

#### [ ] T2-9 吸収されなかった group の診断値（what-if）

group の分割や許容の見直しを、実帳票の件数で判断するための計測。比較結果は一切変えない。

- CLI に `--diagnostics` を追加する（既定は無効。無効時は追加の診断処理を行わず、承認した新規項目を除いて既存出力が完全一致）。有効時、二段目で吸収されなかった group ごとに次を求め、その group の生差分を含むクラスタに付ける
  1. `component_absorbable`：A・B それぞれのインクの連結成分にラベルを付け、一対一に対応が取れ、対ごとに別の shift（±s 以内）を許せば、その group の候補がすべて残差 0 になるか。両側の全成分がちょうど 1 回ずつ使われ、インク以外の候補（塗りなど）が残らないことを条件にする
  2. `component_shift_spread_px`：そのときの成分ごとの shift の最大差
  3. `min_absorbing_shift_mm`：単一 shift のまま `max_shift_mm` を広げたとき、吸収に必要な最小値（上限 1.0mm まで探索。px 換算も併記。見つからなければ null）
- JSON はクラスタの `diagnostics`（無効時は null）。HTML はクラスタ行に折りたたみで表示する。`summary` に件数を出す
- これは診断であり、吸収の条件は変えない。group の分割を実装するかは T2-7 の結果で別途判断する。実装する場合の条件（現行の単一 shift を先に試す、A / B 別ラベルの一対一対応、group 単位で全か無か、既定は無効）を計画に記録しておく

受け入れ条件：`--diagnostics` の有無で、診断項目以外の JSON・PNG・終了コードが完全一致。合成ケース：同じ行で文字ごとにずれ量が違う → `component_absorbable: true`。D18（一重 → 狭い二重罫線）→ false（成分数が合わない）。未 → 末、ば → ぱ、数値変更 → false。1 か所だけ 3px ずれた図形 → 必要な許容量が 3px 相当と出る。有効時の追加時間を計測して報告する。T2-7 の記録用 YAML に診断値の欄を追加する。

#### [ ] T3-5 候補 YAML の出力（suggest）

- `reportdiff suggest <結果フォルダ> [--out candidates.yaml]`。単一比較の `result.json`、または compare-dir の `index.json` とそこから参照される配下の個別 `result.json` を読み、画像比較・元 PDF の再解析はしない。個別結果へのパスは結果フォルダ内の相対パスに限定する。必要な追加情報がない旧結果や欠損した結果は、その根拠による候補を作らず理由を報告する
- 根拠：同じ規則（帳票種別）に一致した対の中で、同じ位置、または同じ行の左隣の見出し語が同じ箇所に相違が出る頻度。`text_a` / `text_b` が日付・時刻・ページ番号の形で値だけ違う場合は、補強としてコメントに書く
- 矩形は差分の外接矩形から、T3-5a で保存した対象単語の矩形を覆う範囲へ広げる。可変位置の欄は保存した見出し語を根拠に T3-4c の `anchor` を候補にする。本文だけから位置や欄の範囲を推測しない
- T2-9 の診断値がある場合は、その根拠に合う許容設定を候補にする。`component_absorbable: true` は成分別 shift の仮定であり、単一 shift のままの `profile: loose` で消える根拠にはしない。`min_absorbing_shift_mm` 等で説明できる場合だけ該当する許容設定を提示し、根拠不足なら参考情報にとどめる
- 出力は自動適用しない。根拠をコメントに書き、候補の行はコメントアウトした YAML にする。入力の設定 YAML は書き換えない

受け入れ条件：合成の compare-dir 結果（全対で同じ位置に日時の相違、1 対だけの相違）から、前者だけが候補になる。候補の行の `#` を外して再実行すると、その相違が消える。可変位置の欄が見出し語でまとまる。コメントを外した出力が設定として読み込める。元 PDF がない状態でも index と個別結果だけで生成でき、旧結果の情報不足を明示する。成分別 shift の診断だけで loose を保証する候補を出さない。

#### [ ] T3-4d 領域内容の一体移動の許容（float_mm）
